## A. Summary Write Commands

1. **Set card summary.** Add `ledger-cli set-card-summary --ledger <ledger-json> --card-id <card-id> --summary <text>` to write `card.summary.text` and refresh `card.summary.updatedAt`.
2. **Set zone summary.** Add `ledger-cli set-zone-summary --ledger <ledger-json> --zone-id <zone-id> --summary <text>` to write `annotation.summary.text` and refresh `annotation.summary.updatedAt`.
3. **Validation.** Reject empty summaries, unknown ids, group annotations passed as zones, and summaries longer than the accepted one-to-three sentence limit.
4. **Output.** Return the updated id, entity type, and `summary.updatedAt`; any stale/fresh state in the response is computed by the CLI and is not written to the ledger.

---

## B. Missing Summary Command

1. **Command.** Add `ledger-cli missing-summaries --ledger <ledger-json> --json`.
2. **Card detection.** Report every card whose `summary.text` is missing or blank.
3. **Zone detection.** Report every regular zone annotation whose `summary.text` is missing or blank.
4. **Agent payload.** Include entity type, id, title or label, `body.file` for cards, containing zone context for cards, and child card ids for zones.
5. **Human output.** Without `--json`, print concise grouped text that is easy to paste into an agent instruction.

---

## C. Stale Summary Command

1. **Command.** Add `ledger-cli stale-summaries --ledger <ledger-json> --json`.
2. **Runtime reconstruction.** `stale-summaries` is a CLI view, not a persisted data-model field.
3. **Card staleness.** Report cards where `card.updatedAt` or `card.body.updatedAt` is later than `card.summary.updatedAt`.
4. **Zone staleness.** Report zones where `annotation.updatedAt` is later than `annotation.summary.updatedAt`.
5. **Missing timestamps.** Treat a present summary without `summary.updatedAt` as stale.
6. **Missing summaries.** Keep missing summaries in `missing-summaries`; add `--include-missing` only if operators need one combined maintenance queue.

---

## D. Sidecar Term Provenance

1. **Source.** `sidecar` is inherited from local engineering helper names such as `ledger-cli/src/business/ledger/helper/card-content-sidecar.ts` and `ledger-cli/src/business/ledger/helper/thread-sidecar.ts`.
2. **Meaning.** In this codebase it means a companion Markdown file stored outside the ledger JSON while the JSON keeps metadata and references the file path.
3. **Model boundary.** `sidecar` should remain implementation vocabulary only; the data model and operator-facing card language should use `body.file`, `threadFile`, or `Markdown body file`.

---

## E. Watcher Timestamp Command Path

1. **Body file update.** When the server watcher accepts a changed Markdown body file, it updates the matching `card.body.updatedAt` to the detected write time.
2. **Ledger save.** The watcher persists the timestamp through the same ledger write path used for other card mutations.
3. **Summary queue.** After the timestamp update, `stale-summaries` exposes cards whose summaries must be regenerated by an agent.
4. **No bypass.** Do not hide stale summaries in watcher context; stale state is the signal that a summary update is required.

---

## F. Tests

1. **Write commands.** Cover successful card summary writes, successful zone summary writes, unknown ids, group annotation rejection, and timestamp refresh.
2. **Missing command.** Cover missing card summaries, missing zone summaries, blank summary text, and JSON plus human output.
3. **Stale command.** Cover stale cards from `card.updatedAt`, stale cards from `card.body.updatedAt`, stale zones, fresh summaries, missing `summary.updatedAt`, and `--include-missing`.
4. **Watcher freshness.** Cover Markdown body file modification advancing `card.body.updatedAt` without changing `card.summary.updatedAt`.
5. **Context parity.** Cover geometry-based zone attribution so summary maintenance reports use the same card-zone ownership as the current frontend and export paths.
