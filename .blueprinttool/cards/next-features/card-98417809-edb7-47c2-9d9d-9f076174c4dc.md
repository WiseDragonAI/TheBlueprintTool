## A. Skill Purpose

1. **Name.** `corev2-refresh-summaries`.
2. **Trigger.** Use when the operator asks to get missing summaries, update stale summaries, create summaries, regenerate summaries, or refresh card and zone summaries.
3. **Goal.** Use `ledger-cli` to find missing or stale card and zone summaries, inspect the relevant ledger/card/zone context, write concise summaries, and verify that no requested missing or stale summaries remain.

---

## B. Exact Skill Prompt

1. **Prompt.** Use this exact skill body:

````markdown
# CoreV2 Refresh Summaries

## Purpose

Refresh Blueprinttool card and zone summaries for the active workspace. A missing summary is an entity with no `summary.text`. A stale summary is computed at runtime by `ledger-cli`: card summaries are stale when `card.body.updatedAt` is later than `card.summary.updatedAt`, and zone summaries are stale when `annotation.updatedAt` is later than `annotation.summary.updatedAt`.

## Default Target

Use the shell cwd as the target workspace by default. Look for `.blueprinttool/state.json` in that cwd. Resolve ledgers from `state.tabs[].ledgerFile`; if the operator names a ledger, use only the matching ledger. If no ledger is named, process the active/default ledger when known, otherwise process every non-state ledger under `.blueprinttool/`.

Resolve the CoreV2 ledger CLI from the workspace or repo:

```bash
LEDGER_CLI="${COREV2_REPO:-$(pwd)}/bin/ledger-cli.mjs"
```

## Commands

Use these commands from the target workspace:

```bash
node "$LEDGER_CLI" missing-summaries --ledger <ledger-json> --json
node "$LEDGER_CLI" stale-summaries --ledger <ledger-json> --json
node "$LEDGER_CLI" set-card-summary --ledger <ledger-json> --card-id <card-id> --summary "<one-to-three-sentence summary>"
node "$LEDGER_CLI" set-zone-summary --ledger <ledger-json> --zone-id <zone-id> --summary "<one-to-three-sentence summary>"
```

## Summary Rules

1. Card summaries are one to three sentences about the card's durable objective, decision, or implementation boundary.
2. Zone summaries are one to three sentences about the zone's topic, workflow, and the kind of cards inside it.
3. Do not restate only the title.
4. Do not include temporary progress states such as `working`, `blocked`, or `needs reply`.
5. Write in English only.

## Workflow

1. Query missing summaries first.
2. Query stale summaries second.
3. For each missing or stale card summary, read the card title, `card.body.file` when present, and nearby zone context.
4. For each missing or stale zone summary, read the zone label and the titles/summaries of cards geometrically inside the zone.
5. Write summaries with the appropriate `set-card-summary` or `set-zone-summary` command.
6. Re-run `missing-summaries` and `stale-summaries` for every processed ledger.
7. Stop only when the requested ledgers report no missing or stale summaries, or report the exact blocker and next command needed.

## Safety

Do not change card status, zone geometry, card body text, thread notes, or unrelated ledger fields while refreshing summaries. Only update `summary.text` and `summary.updatedAt` through the summary commands.
````
