## A. Current Ledger Model

1. **Cards.** Cards are stored in `ledger.cards[]`. A card owns identity, title, type, status, geometry, labels, and a `comment` object.
2. **Card body.** Long card markdown is usually stored outside JSON through `card.comment.contentFile`, for example `.blueprinttool/cards/<ledger>/<card-id>.md`.
3. **Inline fallback.** Card content can also appear as `comment.what`, `comment.body`, or `comment.description` in older or hydrated paths.
4. **Zones.** Zones are stored in `ledger.annotations[]`. Regular zones are annotations where `variant !== "group"` and `color` is a string.
5. **Zone title.** The visible zone name is `annotation.label`, with fallbacks in some export code to `title`, `name`, then `id`.
6. **Zone membership.** A card is attributed to a zone by geometry overlap, not by a durable `zoneId` field on the card.

---

## B. Current Zone Attribution

1. **Frontend helper.** `resolveLedgerCardZone(card, annotations)` computes card-zone membership from rectangle overlap.
2. **Best overlap wins.** If a card overlaps several regular zones, the zone with the largest overlap area owns the card for attribution.
3. **Groups are excluded.** `variant: "group"` annotations are not treated as zones for card context.
4. **CLI export parity.** The markdown export path also groups cards under zones by geometric overlap.
5. **Implication.** A watcher context command can reproduce current behavior without adding a new card-zone relationship field.

---

## C. Split Cards

1. **Summary data model.** `Summary Data Model` owns the proposed `summary`, `createdAt`, and `updatedAt` fields for cards, zones, and summaries.
2. **Summary CLI maintenance.** `Summary CLI Maintenance` owns the `ledger-cli` write, missing-summary, stale-summary, and watcher timestamp update commands.
