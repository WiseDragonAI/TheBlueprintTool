## A. Processing Queue UX

1. **Problem.** Today, sending a note in a thread can push the card directly into `processing`, which is too eager for a watcher-driven workflow.
2. **New status.** Add a `to_process` state for cards that have work waiting but should not immediately trigger an agent run.
3. **Processing transition.** A queued card moves from `to_process` to `processing` only when the operator explicitly triggers processing.

---

## B. Canvas Controls

1. **Keyboard shortcut.** Add `Ctrl+S` as the operator shortcut to process the queued cards.
2. **Queue notification.** When the thread conversation overlay is not open, show a floating notification on the right side of the canvas with the number of cards waiting in `to_process`.
3. **Expandable list.** Clicking the notification expands or collapses a right-side layer that lists the cards that will be processed.
4. **Low ceremony UI.** The list is primarily a visibility and confidence tool. It does not need to become a heavy planning interface.

---

## C. Watcher Trigger

1. **Trigger moment.** The watcher should stop idling and start inference when cards move into `processing`.
2. **Context extraction.** The trigger should collect each processing card, its thread context, and the zone context around that card.
3. **Agent handoff.** The extracted context becomes the prompt payload for the active Codex inference run.
4. **Status ownership.** The implementation must define which component owns transitions among `to_process`, `processing`, completed, and blocked states.

---

## D. Deferred Context Format

1. **Separate card.** The exact `ledger-cli unanswered` context format belongs in the companion card `Unanswered Context Payload`.
2. **Reason.** This card defines the queue and trigger behavior; the companion card defines what the agent receives when the trigger fires.
