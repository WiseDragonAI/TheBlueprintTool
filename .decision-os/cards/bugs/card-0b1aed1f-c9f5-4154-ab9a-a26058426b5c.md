## A. Scope

1. **Operator request.** Analyze the refresh and interaction issue tied to this card, reformat the durable card markdown, and add the commit history for the fixes that were expected to repair the problem.
2. **Target behavior.** During card drag, group drag, zone drag, resize, pan, wheel zoom, thread edits, and Codex content refresh, Decision OS must keep the current canvas interaction attached to the same ledger, same pointer session, same selected objects, same viewport, and same locally moved geometry.
3. **Primary failure class.** The existing fixes protect server refresh merge results for geometry and viewport values, but they do not protect the active interaction session that connects `state.pointer.targetId`, `state.selection`, `state.viewport`, rendered DOM nodes, and `patch-geometry` payloads.
4. **In-scope runtime paths.** The affected files are `frontend/src/runtime/ledger/effect/load-active-ledger-state.ts`, `frontend/src/runtime/refresh/controller/refresh-runtime-state.ts`, `frontend/src/runtime/refresh/effect/subscribe-ledger-content-events.ts`, `frontend/src/runtime/gesture/controller/handle-pointer-down.ts`, `frontend/src/runtime/gesture/controller/handle-pointer-move.ts`, `frontend/src/runtime/gesture/controller/handle-pointer-up.ts`, `frontend/src/runtime/selection/effect/move-selected.ts`, `frontend/src/runtime/ledger/effect/commit-selected-ledger-geometry.ts`, `frontend/src/runtime/ledger/helper/active-ledger-geometry.ts`, `frontend/src/runtime/card/effect/resize-selected-card.ts`, and `frontend/src/runtime/zone/effect/resize-selected-zone.ts`.

## B. Verified Current Behavior

1. **Ledger load clears selection.** `loadActiveLedgerState()` fetches the active ledger, merges local canvas geometry through `mergeLocalCanvasStateIntoLedger()`, restores the current viewport for the same `activeLedgerId`, and then resets `state.selection` to empty.
2. **Manual refresh clears selection twice.** `refreshRuntimeState()` preserves the local viewport for the next ledger id, reads persisted state, clears `state.selection`, hydrates persisted geometry, then calls `loadActiveLedgerState()`, which clears `state.selection` again.
3. **Ledger content refresh remounts canvas state.** `reloadLedgerContent()` calls `loadActiveLedgerState()`, calls `renderCanvasSurface()`, and optionally resizes the changed card with `resizeChangedCardToContent()`. It does not capture the active pointer session and does not preserve current selection explicitly.
4. **Thread content refresh can restore stale selection.** `reloadThreadContent()` captures `const selection = state.selection`, awaits `loadActiveLedgerState()`, then assigns `state.selection = selection`. If the operator changes selection while the fetch is in flight, the old snapshot can overwrite the newer selection.
5. **Pointer down stores target identity.** `handlePointerDown()` records `targetKind` and `targetId` in `state.pointer`, then calls `selectTarget()` for drag and resize paths when selection needs to change.
6. **Pointer move uses live selection.** `handlePointerMove()` calls `moveSelected(canvasDx, canvasDy)` for drag and group gestures. `moveSelected()` reads `state.selection.cardIds`, `state.selection.zoneIds`, and `state.selection.groupIds` at movement time.
7. **Pointer up commits live selection.** `handlePointerUp()` calls `commitSelectedLedgerGeometry()` for drag, group, and resize releases. `commitSelectedLedgerGeometry()` calls `selectedLedgerGeometryPayload()` with its default `state.selection`.
8. **Wheel zoom mutates viewport directly.** `handleWheel()` updates `state.viewport`, calls `scheduleViewportPersistence()`, and calls `scheduleViewportTransform()`. Commit `e1a55b5` protects in-flight `loadActiveLedgerState()` from overwriting current viewport values, but current tests do not exercise a real wheel event racing with ledger content refresh and delayed viewport persistence.

## D. Remaining Defect

1. **Selection rollback.** `loadActiveLedgerState()` and `refreshRuntimeState()` still clear `state.selection`. `reloadThreadContent()` still restores a pre-refresh selection snapshot after an async ledger load. The result can be empty selection, older selection, and newer operator selection being overwritten.
2. **Wrong drag target.** `handlePointerDown()` records the intended target in `state.pointer.targetId`, but drag movement and geometry commit use live `state.selection`. A refresh between pointer down and pointer move can make `moveSelected()` move the wrong card, zone, group, and attached selection set.
3. **Wrong geometry payload.** A refresh between pointer move and pointer up can make `commitSelectedLedgerGeometry()` commit geometry for the current `state.selection`, not the selected ids that belonged to the pointer session.
4. **Detached resize target.** `resizeSelectedCard()` and `resizeSelectedZone()` rely on `state.pointer.target` as a DOM element. A content refresh can remount the canvas while a pointer session is active, leaving the saved element stale even though `state.pointer.targetId` still identifies the intended ledger record.
5. **Pan session gap.** Viewport values are preserved, but no test proves that an active pan session keeps `state.pointer`, continues applying deltas, and finishes cleanly after `loadActiveLedgerState()`, `requestLedgerContentRefresh()`, and `refreshRuntimeState()`.
6. **Wheel refresh gap.** Scale preservation is tested as a direct state mutation, but a real wheel event with `scheduleViewportPersistence()` and `scheduleViewportTransform()` is not tested against a simultaneous ledger refresh.
7. **Coverage gap.** The browser refresh spec `tests/browser/refresh/the-refresh-system-preserves-canvas-continuity-during-operator-work.spec.ts` delegates to `assertFrontendSpec()` and checks source tokens. It is not an interaction race reproduction.

## E. Root Cause

1. **Shared mutable selection.** `state.selection` is both the durable visible selection and the live operand for active drag, group drag, and resize. Refresh code also mutates the same object, so refresh owns a value that pointer code assumes is stable.
2. **Async refresh writes global state after awaits.** `loadActiveLedgerState()`, `reloadLedgerContent()`, `reloadThreadContent()`, and `refreshRuntimeState()` write selection and active ledger state after network and file-refresh awaits without checking whether a pointer session started, moved, changed selection, and reached release during the wait.
3. **Pointer session lacks a geometry selection snapshot.** `state.pointer` stores `targetKind` and `targetId`, but not the full selected card, zone, and group id set that should receive movement deltas and release commits.
4. **DOM target is treated as stable.** Resize helpers use the saved DOM element instead of resolving the target by `targetId` against the current render and active ledger record.

## F. Selected Fix Contract

1. **Capture a pointer selection snapshot.** After `handlePointerDown()` finishes `selectTarget()` for `drag`, `group`, and `resize`, store `state.pointer.selectionSnapshot` with `cardIds`, `zoneIds`, `groupIds`, `targetKind`, `targetId`, and the current `ledgerStateId`.
2. **Move explicit gesture selection.** Update `moveSelected()` to accept an explicit selection argument and use that selection for ledger geometry mutation, DOM position patches, telemetry, zone labels, relationship overlays, and canvas controls. `handlePointerMove()` must pass `state.pointer.selectionSnapshot` for active drag and group gestures.
3. **Commit explicit gesture selection.** Update `commitSelectedLedgerGeometry()` to accept an explicit selection argument and pass that selection to `selectedLedgerGeometryPayload(selection)`. `handlePointerUp()` must commit `pointerSession.selectionSnapshot` for drag, group, and resize releases.
4. **Resolve resize targets by id.** Update `resizeSelectedCard()` and `resizeSelectedZone()` so they resolve the active DOM node from `state.pointer.targetId` when the saved `state.pointer.target` is missing, detached, and stale. Ledger geometry must be patched through `activeLedgerCardMap()` and `activeLedgerAnnotationMap()` by id.
5. **Preserve same-ledger selection through refresh.** Update `loadActiveLedgerState()` so same-ledger refresh keeps the current selection after pruning selected ids that no longer exist in the refreshed ledger. Route changes and ledger changes remain the only paths that clear selection.
6. **Protect active pointer selection during refresh.** When `state.pointer` is active, refresh code must keep `state.pointer.selectionSnapshot` unchanged and must restore visible `state.selection` from that snapshot after the active ledger merge finishes.
7. **Prevent stale thread refresh selection restore.** Update `reloadThreadContent()` so it restores the captured selection only when no pointer session is active and the visible selection has not changed since the snapshot was captured. If selection changed during the await, the newer selection remains authoritative.
8. **Keep viewport preservation unchanged.** Keep the `e1a55b5` behavior that samples `state.viewport` after the fetch and JSON parse in `loadActiveLedgerState()`. Add race tests for wheel and pan paths instead of replacing this behavior.

## G. Acceptance Criteria

1. **Active drag plus ledger load.** With `pointerdown` on `card-a`, a same-ledger `loadActiveLedgerState()` completing before `pointermove` must not move `card-b`, must not commit `card-b`, and must commit only `card-a`.
2. **Multi-selection drag plus content refresh.** With `card-a`, `zone-a`, and `group-a` selected at pointer down, `requestLedgerContentRefresh()` completing before pointer up must preserve the same movement target set and must commit geometry for that exact set.
3. **Resize plus remount.** With a resize session active, a render from `reloadLedgerContent()` must not detach the resize operation from the intended card, zone, and group id. The final geometry payload must use `state.pointer.targetId`.
4. **Thread refresh selection freshness.** If `reloadThreadContent()` starts with `card-a` selected and the operator selects `card-b` before the load resolves, the final visible selection must stay on `card-b`.
5. **Same-ledger selection preservation.** A same-ledger load must preserve existing selected ids that still exist in the refreshed ledger and must remove selected ids missing from the refreshed ledger.
6. **Manual refresh during pan.** During a pointer pan session, `refreshRuntimeState()` must keep `state.pointer.intent` as `pan`, preserve the latest `state.viewport`, allow the next pointer move to continue from the current pointer coordinates, and allow pointer up to call `finishPointer()`.
7. **Wheel zoom race.** A wheel zoom followed by same-ledger refresh must leave the latest `state.viewport.x`, `state.viewport.y`, and `state.viewport.scale` in memory and in the next `scheduleViewportPersistence()` write.
8. **Browser spec strength.** The refresh browser test must include an interaction-race assertion instead of relying only on source-token evidence from `assertFrontendSpec()`.
