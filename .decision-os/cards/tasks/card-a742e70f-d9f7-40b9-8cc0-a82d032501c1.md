## A. Symlink project lifecycle

1. Project creation resolves the selected link target for Git and Decision OS initialization while persisting the catalog-relative link path as project identity.
2. Registry reloads resolve the persisted alias again, so externally targeted projects remain available after creation and restart.
3. Existing Git, Decision OS state, project identity, and source files on the resolved target remain preserved.
4. Missing Git and Decision OS state are initialized on the resolved target only.
