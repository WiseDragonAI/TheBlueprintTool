Ledger: Specs
Queue rank: 3

## A. Required behavior

1. Keep the `Queue`, `Exec`, and `Backlog` column scroll positions independent and stable while the application remains loaded.
2. Preserve each column's position across Control Room data refreshes, project and ledger filter rerenders, tab changes, task-detail navigation, and browser back navigation.
3. Restore each position after the replacement column list is connected and its content is rendered.
4. Keep this state in frontend runtime memory only. A full page reload may reset all three positions.

---

## B. Verified reset boundary

1. `frontend/src/app/responsive/application.js` renders the three columns in `renderControlRoom()`.
2. Each render calls `destroyQueueSortables()` and then `elements['control-task-list'].replaceChildren(...columns)`, replacing every scroll container and resetting its `scrollTop`.
3. Event-driven task refreshes call `loadControlRoom()` and then `renderControlRoom()` through `refreshControlRoomFromEvent()`.
4. The current `persistControlRoomScrollAnchor()` listens to `window` scrolling and writes a task anchor into the route. The active scroll owners are `.control-task-column-list`, so this mechanism does not retain per-column positions.

---

## C. Acceptance

1. Scrolling one column does not change the remembered position of either other column.
2. A task refresh that rerenders the Control Room leaves all three columns at their previous positions, clamped to the new scroll range.
3. Opening a task from the Control Room and returning with the task back control and browser history restores all three positions.
4. Project filters, ledger filters, and Control Room tab selection retain the three remembered positions during the same page lifetime.
5. Focused frontend tests cover independent capture, rerender restoration, refresh restoration, and task-detail back navigation.
