## A. Scope

1. Extend the project-sync lifecycle with terminal `cancelled` state and durable cancellation evidence.
2. Return the current lock-owner `syncId` on admission and participant lock conflicts.
3. Add authenticated, idempotent compare-and-release cancellation for a specific `originFingerprint` and expected owner `syncId`.
4. Preserve a newer owner's lock when the expected owner no longer matches.

---

## B. Acceptance criteria

1. Cancelling an active run persists `cancelled`, releases its local lock, and requests conditional release from the remote participant.
2. Repeating cancellation returns the same terminal state without extra mutation.
3. A stale cancellation request cannot release another run's lock.
4. Store restoration preserves cancelled runs and valid locks while removing no lock without an explicit ownership proof.
