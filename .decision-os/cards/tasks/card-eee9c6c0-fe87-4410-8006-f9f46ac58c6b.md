## A. Corrected Execution Model

1. **History unit:** one operator launch or continuation is one selectable Codex Log entry, identified by durable `executionId`.
2. **Session ownership:** `runId` remains the append-only artifact and API authorization key; it no longer defines the navigator count.
3. **Metrics and hydration:** each selected execution filters its own JSONL line interval and displays its own elapsed time, tool calls, messages, file changes, diagnostics counters, status, and latest event.
4. **Timing boundary:** execution settlement writes a durable finish marker, excluding operator idle time before a later continuation. Automatic transport retries retain the same execution ID.
