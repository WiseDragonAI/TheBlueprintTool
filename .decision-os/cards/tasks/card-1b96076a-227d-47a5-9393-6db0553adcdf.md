## A. Objective

1. AgentSocial will let an agent **turn owned source media into reviewed platform variants, schedule them across connected social channels, observe publication, and learn from outcomes** through one deterministic CLI.
2. The first complete journey is `Twitch VOD -> candidate moments -> reviewed vertical short -> platform variants -> Postiz draft -> approval -> scheduled publication -> receipt -> analytics`.

---

## B. Verified landscape

1. AutoSocial is **a local browser-automation dashboard, not a durable agent backend**: it relies on global account state, filesystem queues, in-process schedules, unauthenticated mutations, and publish heuristics without provider receipts.
2. Postiz is **the credible primary publishing backend**: its public REST API exposes connected channels, live provider settings, uploads, drafts, scheduling, publication state, release reconciliation, and analytics across a broad provider registry.
3. Postiz still requires AgentSocial-owned safeguards because `POST /public/v1/posts` has no idempotency key, multi-channel creation is non-transactional, and a successful response does not prove Temporal workflow admission.
4. The DroidFleet live-to-shorts work contains valuable deterministic media stages, but a fresh run cannot complete because its editorial artifact handoff is missing, final recut defaults to the low-resolution proxy, agent subprocesses have excessive authority, and dependency provenance is incomplete.
5. The official `yt-dlp` executable provides the required Twitch and YouTube acquisition surface when pinned, checksum-verified, and invoked with `--ignore-config`, `--no-plugin-dirs`, `--no-remote-components`, and machine output.

---

## C. Strategic design

1. Build **one AgentSocial application service** behind `agentsocial`, Codex skills, pipeline recipes, and AgentSocial-owned `MCP` tools so every interface shares policy and state transitions.
2. Use SQLite for durable AgentSocial authority over sources, immutable assets, content revisions, platform variants, campaigns, approvals, pipeline runs, publication jobs, attempts, normalized receipts, incidents, and events.
3. Use a clean-room `PostizPublisherAdapter` over public REST and treat Postiz as authoritative for each connected channel, scheduled post, publication result, release identity, and provider analytics.
4. Build a self-contained Go media worker from the verified DroidFleet stage contracts; replace unrestricted `codex exec` file mutation with a schema-bound `DecisionProvider`, use the HD master for production recuts, and persist checksummed manifests.
5. Manage `yt-dlp`, `ffmpeg`, and `ffprobe` as pinned external dependencies with direct argv execution, finite deadlines, cancellation, contained outputs, explicit cookie secrets, and complete acquisition receipts.
6. Defer the MIT-derived `BrowserPublisherAdapter` until the primary backend is qualified; bind it explicitly to one channel and send uncertain publication to `reconciliation_required`.

---

## D. Product guardrails

1. **Unattended preparation is allowed; external publication is approval-gated.** An approval binds exact content revisions, media checksums, channels, provider settings, mutation type, and publication window.
2. Every mutation includes explicit `profile`, `channel`, `content_revision`, `asset_revision`, and `idempotency_key`; no agent command depends on a global active account.
3. Provider variants compile from live settings schemas and never silently truncate content, remove media, infer audience declarations, change visibility, or discard settings.
4. Successful download does not establish reuse rights. Rights basis, ownership, permitted use, consent, territory, expiry, attribution, and disclosures are blocking source metadata.
5. AutoSocial’s MIT logic may be ported behind the fallback adapter; Postiz AGPL source, SDK, CLI, skills, and provider code remain outside the AgentSocial codebase.

---

## E. Current decision

1. **Proceed with the AgentSocial CLI kernel, domain state, and clean-room Postiz adapter as the first implementation boundary**, while the media worker closes the verified DAG and provenance gaps.
2. The complete source analysis, delivery sequence, qualification gates, and actionable implementation graph are now owned by the AgentSocial project with accent `#ff1744`.
3. No planning blocker remains. The operator must select the AgentSocial repository license before distribution, and controlled provider-policy qualification remains mandatory before recurring production schedules.
