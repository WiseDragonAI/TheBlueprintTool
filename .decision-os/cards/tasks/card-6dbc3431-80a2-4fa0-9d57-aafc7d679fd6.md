## A. Scope

1. **Objective:** Make the active project an explicit, shareable segment of every project-scoped mobile page and request URL.
2. **Canonical prefix:** Use `/p/:projectId` as the single project context boundary; derive backend workspace selection exclusively from that path segment.
3. **Stack boundary:** Align mobile navigation, direct entry, ledger CRUD, Codex, pipelines, uploads, voice transcription, and ledger-content events with the same URL-derived project identity.
4. **Removed state:** Delete the `decision-os-project` cookie contract and the `x-decision-os-project` request-header contract.

---

## B. Verified Findings

1. **Frontend routes:** Control Room uses `/`, overview uses `/ledgers`, and ledger, zone, and card routes start at `/:ledgerId`; none identifies the project.
2. **Frontend selection:** `frontend-mobile/src/mobile.js` writes `decision-os-project`, stores `activeProjectId` in memory, and adds `x-decision-os-project` through `projectFetch`.
3. **Backend selection:** `backend/src/business/server/helper/create-http-server.ts` resolves the project from the header, then the cookie, then the server workspace fallback.
4. **Shared requests:** Mobile thread and Codex flows reuse canvas modules whose ledger, Codex, pipeline, upload, voice, and event-stream requests are absolute `/api/*` and `/decision-os/*` URLs.
5. **Failure mode:** A copied ledger, zone, card, Control Room, Codex, upload, or event URL cannot reproduce its project context; missing state silently falls back to another workspace.

---

## C. Canonical URL Contract

1. **Control Room:** `/p/:projectId/control-room?tab=:tab#task-:id`.
2. **Project management:** `/p/:projectId/projects` lists projects and `/p/:projectId/projects/:viewedProjectId` shows project detail and settings.
3. **Ledgers:** `/p/:projectId/ledgers` lists ledgers and `/p/:projectId/ledgers/:ledgerId` opens one ledger.
4. **Zones and cards:** `/p/:projectId/ledgers/:ledgerId/zones/:zoneId` and `/p/:projectId/ledgers/:ledgerId/zones/:zoneId/cards/:cardId` are the canonical deep links.
5. **Project APIs:** Prefix project-sensitive endpoints with the same project base, including `/p/:projectId/decision-os/*` and `/p/:projectId/api/*`.
6. **Global endpoints:** Keep `GET /decision-os/projects`, `PATCH /decision-os/projects/:projectId`, static modules, static assets, and `POST /api/server/restart` outside project scope.
7. **Legacy pages:** Redirect projectless mobile page routes to the canonical route for the server workspace project.
8. **Legacy APIs:** Reject projectless project-sensitive `/decision-os/*` and `/api/*` requests with an explicit project-context error instead of selecting a fallback workspace.

---

## D. Implementation Contract

1. **Route parser:** Add one tested frontend route helper that parses and generates every canonical page and request path.
2. **URL-derived state:** Resolve `activeProjectId` from the page route before loading project state; an unknown project id produces `404` and never falls back.
3. **Navigation:** Preserve the project prefix through drawer navigation, Control Room tabs and anchors, ledger links, zone and card traversal, creation flows, back actions, browser history, and cross-project task opening.
4. **Request scoping:** Route every project-sensitive fetch and `EventSource` through the canonical project base, including calls originating in shared canvas modules.
5. **Cross-project behavior:** Opening a task, subtask, or project switches both the visible URL prefix and backend request scope to the selected project.
6. **Backend parsing:** Resolve and validate the project path segment before asset lookup, API dispatch, ledger loading, mutation, upload handling, and event subscription.
7. **No hidden selection:** Remove all cookie writes, cookie reads, selection-cookie repair, and project-header injection.

---

## E. Acceptance Criteria

1. **Direct access:** Fresh direct entry and reload work for Control Room, Projects, ledger, zone, and card URLs without pre-existing cookies or in-memory state.
2. **Shareability:** Opening the same canonical URL in a clean browser resolves the same project and resource.
3. **Isolation:** Two project URLs can request the same ledger id without reading or mutating each other's files.
4. **Unknown project:** Unknown project ids return `404` for pages and project-scoped APIs without fallback.
5. **Ambiguous API removal:** Projectless ledger, Codex, upload, voice, and event endpoints fail explicitly; no request selects a project from cookies or `x-decision-os-project`.
6. **Navigation coverage:** All generated application links retain `/p/:projectId`, and cross-project task navigation changes it to the task's project id.
7. **Regression coverage:** Backend integration tests cover URL parsing, redirects, rejection, isolation, and removal of cookie/header selection; mobile tests cover every route generator, direct entry, history, requests, and event scoping.
8. **Behavioral verification:** At `390x844`, verify direct card entry, refresh, back, forward, project switching, a successful persisted mutation, and absence of `decision-os-project` after reload on a served two-project fixture.
