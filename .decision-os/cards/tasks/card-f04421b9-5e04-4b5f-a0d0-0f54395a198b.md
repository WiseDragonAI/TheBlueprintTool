## A. Refresh contract

1. The run widget polls `/api/codex/skills/runs/:runId` and renders its returned backend status.
2. The canvas reloads authoritative ledger state from project-scoped server-sent ledger events.
3. The child process `close` callback updates terminal runtime state, removes the queue item, and invokes `onCodexRunSettled`.

---

## B. Classification

1. **Intentional client rule:** backend run status remains authoritative over a terminal log event.
2. **Lifecycle defect:** the backend lacks bounded reconciliation when JSONL is terminal but the Codex wrapper stays alive.
3. **Refresh defect:** `onCodexRunSettled` publishes a terminal ledger event for pipelines but not for ordinary thread runs.
4. **Correction contract:** settle terminal JSONL after a bounded grace period, terminate the hung wrapper, remove the queue item, clear active ownership, and publish a terminal ledger event for every thread run.
