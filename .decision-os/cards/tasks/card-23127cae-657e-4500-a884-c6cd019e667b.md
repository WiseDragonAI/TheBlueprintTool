## A. Scope

1. **Objective:** Add durable browser-local voice upload recovery before server acceptance.
2. **Result:** Implemented in merge commit `0d950e0`.

---

## B. Implementation

1. **Durable store:** `frontend/src/runtime/voice/effect/persist-pending-voice-upload.ts` stores the audio `Blob` and upload identity in native `IndexedDB` under database `decision-os-voice`.
2. **Ordering:** `requestTranscription` awaits the committed `IndexedDB` transaction before calling `POST /api/voice-upload`.
3. **Shared submission:** `submit-pending-voice-upload.ts` owns initial upload and retry for the same `noteId`.
4. **Retention:** Network failure, rejected HTTP response, malformed acceptance, and absent `voiceFileRef` retain the local audio.
5. **Cleanup:** Server acceptance with a non-empty `voiceFileRef` deletes the local entry; accepted server notes also clean a retained crash-window entry during restore.
6. **Reload recovery:** `restore-pending-voice-uploads.ts` recreates the failed optimistic note and its `Retry` action after page reload.
7. **Deletion:** Deleting a retained note deletes its associated local audio after the ledger mutation succeeds.

---

## C. Acceptance Criteria

1. **Failure retention:** Passed by `request-transcription keeps preserved upload retryable when metadata commit fails`.
2. **Stable note:** Retry reuses the original `noteId` and updates the same note.
3. **Accepted cleanup:** The regression confirms `readPendingVoiceUpload(noteId)` returns `null` after accepted retry.
