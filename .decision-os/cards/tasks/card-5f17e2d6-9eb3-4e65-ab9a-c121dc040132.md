## A. Objective

1. **Outcome:** Every new Decision OS Codex session receives an explicit `platform: linux` or `platform: termux` developer instruction, and browser instructions dispatch to the matching verified workflow.
2. **Session boundary:** Existing sessions resumed with `codex exec resume` retain the platform context established by their original fresh launch and receive no duplicate injection.

---

## B. Implemented Result

1. **New-session contract:** `resolveCodexCommand` injects the normalized runtime platform while preserving caller developer instructions. This covers fresh thread runs, skill and pipeline runs, project-sync skill runs, and continuation fallback paths that create a new session.
2. **Resume contract:** `resolveCodexResumeCommand` preserves model and effort arguments without adding `developer_instructions`.
3. **Browser workflows:** `BROWSER_RUNBOOK.md` contains separate Linux Playwright and Termux Puppeteer procedures; `AGENTS.md` dispatches from the platform already present in the session context.
4. **Corrective delivery:** Commit `18e269d1` was merged by `1568e108` after removing the redundant resume injection. The correction worktree and branch were removed.

---

## D. Reasoning Lesson

1. **Mistake:** The first implementation classified every process invocation as a startup and ignored session continuity.
2. **Correct model:** Prompt injection belongs to session creation. A resume continues the established system and developer context, so repeating immutable startup context is redundant.
3. **Future check:** Before modifying a shared command builder, classify each caller by semantic lifecycle transition: new session, resumed session, and new fallback session. Bind prompt initialization only to new-session transitions.
