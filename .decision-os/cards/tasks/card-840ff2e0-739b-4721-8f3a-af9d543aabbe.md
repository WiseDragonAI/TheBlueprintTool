#master-task

Ledger: Specs

## A. Scope

1. **Objective:** automatically recover a headless card-thread Codex run when the active model reports `Selected model is at capacity. Please try a different model.`
2. **Session contract:** wait `5,000ms`, then run `codex exec resume` against the captured session id.
3. **Selection contract:** retain the exact model and `model_reasoning_effort` snapshot from the interrupted run; do not select a different model.

---

## B. Findings

1. **Failure transition:** `start-thread-codex-process-controller.ts` treated every non-zero child exit as terminal and appended a failed run status.
2. **Durable context:** the Codex JSONL artifact already records `thread_id`, and `resolveCodexResumeCommand` already accepts explicit model and effort values.
3. **Recovery boundary:** only the exact capacity message is retryable; unrelated non-zero exits retain the existing failed status.

---

## C. Implementation

1. **Classification:** inspect only the current process segment in stdout and stderr for the capacity message.
2. **Resume:** keep the run active, record the retry timestamp, and resume the same session after `5,000ms`.
3. **Repeated interruption:** apply the same classification to each resumed segment so repeated capacity failures remain recoverable.
4. **Commit:** implementation is merged in `151086e` through focused commit `22a338a`.

---

## D. Acceptance Criteria

1. **Delay:** the resumed process starts no earlier than `4,900ms` after the interrupted process launch in automated coverage.
2. **Session:** the resume command includes the captured session id.
3. **Model:** the initial and resumed commands use the same `--model` value.
4. **Effort:** the initial and resumed commands use the same `model_reasoning_effort` value.
5. **Completion:** a successful resumed process settles the original run as `complete`.
