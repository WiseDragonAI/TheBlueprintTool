## A. Objective

1. Replace three drifting process engines with one lifecycle kernel while keeping prompt and pipeline planning at application boundaries.

---

## B. Verified Evidence

1. Start, continuation, and pipeline duplicate spawn, streams, runtime, markers, retry, and settlement.
2. Pipeline runtime and markers lack admitted execution identity.
3. Capacity retry allocates a second execution ID.

---

## C. Implementation Contract

1. Implement typed `admit`, `launch`, `retry`, `cancel`, `settle`, `recover`, and `delete` transitions with one event vocabulary.
2. Keep prompts, pipeline sequencing, and log rendering outside the kernel.
3. Register one process handle and write one start marker plus one terminal marker.
4. Preserve execution identity through capacity retry and expose one history entry.

---

## D. Acceptance Tests

1. All launch kinds assert identical transition traces and identity propagation.
2. Capacity retry retains one execution, queue lease, and navigator entry.
3. Repeated terminal callbacks settle once and cannot clear newer execution.
