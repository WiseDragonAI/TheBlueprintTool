## A. Scope

1. **Backend controller:** Add a controller under `backend/src/business/codex/controller/` that deletes one card-thread Codex session identified by `ledgerId`, `cardId`, and `runId`.
2. **HTTP contract:** Add `DELETE /api/codex/skills/runs/:runId` in `backend/src/business/server/helper/create-http-server.ts` with `ledgerId` and `cardId` in the JSON body.
3. **Owned state:** Limit deletion to the run referenced by the target card's `codexThreadRunId`.

---

## B. Implementation Contract

1. **Validation:** Resolve the selected ledger through canonical Decision OS state, verify the ledger path remains inside `.decision-os`, load the card, and reject any ownership mismatch before process or filesystem mutation.
2. **Active run:** Reuse the existing cancellation semantics to send `SIGTERM`, then await child settlement and stream closure before clearing persistence and removing files.
3. **Persistence:** Remove `codexThreadRunId` and `codexThreadRunOutputFile` while preserving card content, thread content, `codexRunModel`, and `codexRunEffort`; write the ledger without hydrated thread notes.
4. **Artifacts:** Delete only files whose safe run basename matches the owned run in `.decision-os/runs/codex-skills/<ledger>/`, including `.jsonl`, `.log`, `.md`, and ingestion telemetry.
5. **Runtime:** Remove the settled run from `runtime.codexSkillRuns` and publish one ledger-change notification after cleanup succeeds.
6. **Failure integrity:** Return a concrete non-success response without clearing ownership when cancellation, persistence, or cleanup cannot finish.

---

## C. Acceptance Criteria

1. **Automated tests:** Cover terminal deletion, active child settlement before unlink, mismatched ownership, path containment, cleanup failure, and removal of the runtime entry.
2. **Fresh launch regression:** After deletion, `startThreadCodexProcessController` accepts the same card, creates a different run id, and resolves a fresh Codex command without a resume session id.
3. **No late writes:** A cancelled run's close handler cannot recreate the deleted `.md`, `.jsonl`, `.log`, or telemetry files.
