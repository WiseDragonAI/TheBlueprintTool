## A. Problem and incorrect flow

1. **The former projection exposed remote replica `N` of project `P` as public identity `N:P`.** Routing therefore created a second project.
2. **The catalog published replicas as peer projects.** Filters, URLs, mutations, and tasks propagated the split.
3. **Late reconciliation was observer-relative.** It omitted `ledgerId` from the card key and retained only one execution observation.

---

## B. Engineered solution

1. **Keep public project identity `P`.**
2. **Represent locations as `{ projectId, nodeId }` replica descriptors.**
3. **Route the selected node independently** while canonical URLs retain `P`.
4. **Reconcile by `P + ledgerId + cardId`** with deterministic authority.
5. **Retain all verified executions** and expose concurrent observations as one conflict.

---

## C. Implemented control flow

1. `/decision-os/projects` groups rows by `P` and attaches ordered replicas.
2. `?replica=N` becomes request header `x-decision-os-replica-node: N` without rewriting `P`.
3. The backend proxies selected replica mutations and retains cached offline replica reads.
4. Control Room uses the complete logical card key and retains all execution observations.
