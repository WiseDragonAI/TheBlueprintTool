## A. Objective

1. Keep historical log navigation independent from canonical active indicator and action.

---

## B. Verified Evidence

1. `render-thread-panel.ts` binds selected history.
2. `render-thread-codex-log.ts` derives global controls from that selection.
3. Screenshots show Run 2 presenting `RESUME` while Run 3 is active.

---

## C. Implementation Contract

1. Store `historySelection` separately from `activeExecution`.
2. Admission selects the newest active entry; later history selection cannot mutate active ownership.
3. Render log content and metrics from history selection.
4. Render activity and `STOP` or `CANCEL` from active execution.
5. Render typed retained-session, direct-run, and pipeline entries.

---

## D. Acceptance Tests

1. Run 2 stays visible while Run 3 controls activity and action.
2. Admission selects Run 3.
3. Returning to Run 2 does not change action target.
4. Completion updates activity without replacing history selection.
