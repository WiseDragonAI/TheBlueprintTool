## A. Verified Server Boundary

1. **Single dispatch point:** `backend/src/business/server/helper/create-http-server.ts` resolves `/p/:projectId`, selects that project's `.decision-os` root and runtime, then invokes the existing ledger, asset, upload, event, and Codex controllers.
2. **Single browser boundary:** `frontend/src/runtime/project/helper/project-request-scope.ts` rewrites project-sensitive `fetch` calls, while `subscribe-ledger-content-events.ts` applies the same scope to the ledger `EventSource`.
3. **Finding:** Federation can be inserted at project resolution. Local projects keep the current dispatch path; an owner-qualified remote project is forwarded before a local project context is created.

---

## B. Owner-Dispatch Allowlist

1. **Ledger reads:** Allow the existing project-scoped state, ledger, canvas, navigation, search, card, and thread reads.
2. **Ledger mutations:** Allow project-scoped ledger and content mutations; the owner continues to enforce revision, mutation, and master-completion contracts.
3. **Content and events:** Allow project-scoped asset reads, ledger events, uploads, voice orchestration, and transcription status.
4. **Codex:** Allow the existing project-scoped `/api/codex/pipelines**`, `/api/codex/skills**`, `/api/codex/skill-library/**`, and `/api/codex/threads/process` route families.
5. **Git read:** Add only `GET /api/git/status`; carry it through the existing finite request and response stream.

---

## C. Forbidden Federation Surface

1. **Node administration:** Reject server restart, settings, and debug routes.
2. **Project administration:** Do not proxy project creation, project metadata mutation, or raw local discovery.
3. **Git execution:** Do not expose `git`, shell text, executable paths, arguments, environment variables, repository credentials, packfiles, refs mutation, commit, push, pull, reset, checkout, rebase, merge, or conflict-resolution endpoints.
4. **Verified gap:** `readRequestBuffer.ts` currently buffers without a byte limit. Federation must enforce limits before reading a relayed body.

---

## D. Structured Git Status

1. **Owner computation:** Run `git status --porcelain=v2 --branch -z` with the owner project root as the fixed working directory and a bounded timeout. Do not accept command text or a filesystem path from the requester.
2. **Response:** Return `isRepository`, `branch`, `detached`, `headOid`, `upstream`, `ahead`, `behind`, staged, unstaged, untracked, conflicted counts, operation state, `checkedAt`, and `networkFresh: false`.
3. **Privacy:** Return counts and repository state by default, not file contents, diffs, remote URLs, credential configuration, hooks, environment variables, or ignored files.
4. **Cost:** Compute status on demand for the selected project and coalesce concurrent requests; do not scan every federated project during catalog refresh.

---

## E. Owner-Side Reconciliation

1. **Task path:** The requester creates a normal card or thread note in the remote project and launches the existing Codex process route. The owner node performs the run inside its local project workspace.
2. **Mutations:** Commit, push, fetch, fast-forward pull, and semantic conflict resolution are Codex task actions, not relay protocol commands.
3. **Result:** The relay gains no arbitrary-command surface, every Git mutation inherits the existing Codex transcript and run settlement, and project credentials never leave the owner.
