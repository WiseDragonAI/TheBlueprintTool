## A. Scope

1. Add the durable `armed`, `firing`, and `failed` request model under the master server `.decision-os` root.
2. Record request ID, request time, current Linux boot ID, transition times, and failure diagnostic.
3. Persist each transition through a same-directory temporary file and atomic rename.
4. Transition to `firing` before invoking `/usr/bin/systemctl poweroff --no-block --no-ask-password`.
5. Require a new explicit request before every later invocation; never auto-retry fired, failed, stale-boot, or malformed state.

---

## B. Targets

1. **Files:** `backend/src/business/server/helper/deferred-poweroff-store.ts`; `backend/src/business/server/helper/deferred-poweroff-executor.ts`.
2. **Symbols:** `DeferredPoweroffRequest`; atomic read and write helpers; `/proc/sys/kernel/random/boot_id` reader; injected executor interface.

---

## C. Done When

1. Atomic persistence survives a server restart.
2. The executor receives exactly `poweroff --no-block --no-ask-password`.
3. A fired, failed, stale-boot, or malformed request produces zero automatic executor calls.
