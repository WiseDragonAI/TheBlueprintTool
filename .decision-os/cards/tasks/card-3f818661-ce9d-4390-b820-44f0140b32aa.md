#master-task

Ledger: Specs

## A. Scope

1. **Surface:** Correct the waiting-duration label and FIFO timestamp in the mobile Control Room task list.
2. **Source of truth:** Use the newest valid timestamp in the task thread, including the latest `# AGENT` reply and any newer `# OPERATOR` message.
3. **Fallback:** Retain the Markdown `Waiting since` timestamp when the thread has no valid timestamped note.

---

## B. Implementation

1. **Thread parsing:** Pass the hydrated `document.notes[thread-${card.id}]` collection into `parseMasterTaskMarkdown`.
2. **Waiting transition:** Derive `waitingSince` and `waitingTime` from the maximum valid thread-note timestamp.
3. **Queue ordering:** Continue sorting on `waitingTime` so visible waiting age and FIFO order share one timestamp.

---

## C. Acceptance Criteria

1. **Agent reply:** A later agent reply resets the displayed waiting duration to the reply timestamp.
2. **Operator reply:** A later operator reply resets the displayed waiting duration to the operator timestamp.
3. **Legacy data:** Missing and malformed thread timestamps fall back to the card Markdown timestamp.
4. **Regression:** The mobile automated test suite passes.
