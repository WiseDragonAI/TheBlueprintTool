## A. Essential lessons with examples

1. **One concept must have one authority.** **Example:** a directly opened card appeared cyan even though its persisted zone was violet. **Fix:** hydrate the owning zone ID and persisted color before rendering the card.
2. **A shared-state fix must cover every consumer.** **Example:** projecting a pipeline run onto the source card fixed Codex Log, but Control Room still classified it from the legacy field. **Fix:** update the shared ownership helper, Control Room classification, and regression fixture together.
3. **A change includes its full contract.** **Example:** copying a skill preserved file bytes but lost executable modes through the process umask. **Fix:** snapshot and restore modes, explicitly apply each source mode after writing, and test create, update, and rollback.
4. **Only operator-visible evidence proves UI behavior.** **Example:** the form contained `#5d5bcf`, but Brave displayed zeroed color-picker handles. **Fix:** implement the authorized JavaScript picker, then verify real Android touch-drag, draft updates, Cancel, and Set on the served page.
5. **Behavior fixes must preserve validated product boundaries.** **Example:** an initial color-picker fix silently replaced the validated component with Coloris. **Fix:** revert the substitution and replace the component only after the operator explicitly authorized the Brave-style JavaScript picker.
6. **Governance is part of correctness.** **Example:** a finished linked task projected as `Status: completed`, then `Status: done`, kept the master gate stale. **Fix:** write the exact literal `Status: complete`; the gate became ready with no discrepancies.
