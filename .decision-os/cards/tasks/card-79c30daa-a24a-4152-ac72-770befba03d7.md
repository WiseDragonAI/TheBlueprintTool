## A. Finding

1. **Root cause:** the Active Cards link is correctly project-scoped. The stale Codex Log is caused by a surviving thread-run poller that derives request scope from the browser's current route after navigation returns to the global Control Room at `/`.
2. **First incorrect transition:** after the card thread is closed and navigation returns to `/`, the existing poller remains subscribed and sends its next status request to unscoped `/api/codex/skills/runs/<runId>`.
3. **Sticky state:** HTTP `400` is normalized as an unavailable run, stored in `terminalSummaries`, and replayed on every later bind for the same `ledgerId:cardId:runId`. The poller does not retry after the card URL becomes project-scoped again.
4. **Refresh behavior:** a full reload clears `pollers`, `consumers`, and `terminalSummaries`. The card route still contains `/p/ZGVjaXNpb24tb3M`, so the new request is scoped and returns the live run.

1. **Correct Active Cards URL:** `pathForTask` calls `cardPathForProject(task.projectId, task.ledgerId, ...)` in `frontend-mobile/src/mobile.js:100-106`; the Active row calls `navigate(pathForTask(task))` at `frontend-mobile/src/mobile.js:556-559`.

3. **Persistent consumer:** `bindCardSkillRunLogConsumer` registers a consumer without a matching unbind operation in `frontend/src/runtime/codex/effect/poll-card-skill-run.ts:559-600`. `closeMobileThread` only hides the panel in `frontend-mobile/src/mobile-thread.js:113-119`.

5. **Terminalized transport failure:** `poll` stores every `!summary.ok` result in `terminalSummaries`, stops the poller, and returns in `frontend/src/runtime/codex/effect/poll-card-skill-run.ts:507-521`. 6. **Server contract:** an unscoped project-sensitive endpoint returns `400` with `Project id is required in the URL.` when the catalog has multiple projects in `backend/src/business/server/helper/create-http-server.ts:363-368`.

## C. Runtime Reproduction

1. **Served route:** `http://127.0.0.1:50150/?tab=active` returned HTTP `200`; Chromium used the mandated Termux flags and the already-running server.
2. **Initial card poll:** navigation produced `/p/ZGVjaXNpb24tb3M/ledgers/specs/zones/zone-7207205d-af0f-4d41-a7c4-dfd9a77cc570/cards/card-ad6652a3-f7b4-4727-9e98-89fa0ffe2c6c`; the run request used `/p/ZGVjaXNpb24tb3M/api/...` and returned HTTP `200` with status `running`.
3. **Control Room transition:** after closing the thread and returning to `/`, the same poller requested unscoped `/api/...&since=129` and received HTTP `400`.
4. **Second card visit:** the browser again showed the correct `/p/ZGVjaXNpb24tb3M/...` card URL, but the Codex Log status was `unavailable` because the HTTP `400` summary was replayed from `terminalSummaries`.
5. **Direct endpoint check:** unscoped status returned `{"ok":false,"error":"Project id is required in the URL."}`; the equivalent `/p/ZGVjaXNpb24tb3M/api/...` request returned HTTP `200` with `status: running`.

## D. Coverage Gap

1. **Existing coverage:** `frontend-mobile/test/mobile-control-room.test.mjs` asserts that Active rows call `navigate(pathForTask(task))` and that task paths use `cardPathForProject`.
2. **Existing server coverage:** `backend/test/server/decision-os-project-catalog.integration.test.ts:88-90` asserts the HTTP `400` response for an ambiguous unscoped endpoint.
3. **Missing regression:** no test exercises `scoped card -> open running thread -> close thread -> global Control Room -> poll tick -> same scoped card` and asserts that the run remains live.

---

## E. Recommendation

1. **Make project scope immutable poller context:** add `projectId` to the thread-run binding and poller identity, build every run-status request with `projectScopedRequestPath(path, projectId)`, and remove the consumer when the mobile thread closes. This prevents a live card poll from changing workspace ownership when the visible route changes.
2. **Regression contract:** automate the reproduced route sequence and assert that every request for the active run retains `/p/<projectId>`, no HTTP `400` summary enters `terminalSummaries`, and reopening the card shows `running` without a browser refresh.
