## A. Scope

1. **Goal/spec link:** Verify the product behavior of a dynamic pipeline that queues one skill and re-enters the calling `GateTest` skill in a fresh execution context.
2. **Affected product area:** Decision OS Codex pipeline execution and dynamic skill queueing.
3. **Affected workflow:** A running gate queues a worker; the worker completes; a returning gate is launched with the worker result and current task conversation.
4. **Affected actor/role:** The operator using a gate skill to request additional work and receive the returning gate analysis.
5. **Relevant context fact:** `queue-codex-skill-after-execution-controller.ts` creates a temporary two-step run, records `queuedAfterExecutionId`, sets `initialInputCardId` to the current output card, and preserves the caller prompt snapshot for the returning skill.
6. **Current behavior:** `codex-pipeline-runner.ts` resolves the immediately prior output card at spawn time. For a `pipeline-prompt` skill, `build-pipeline-skill-prompt.ts` renders the admitted snapshot with current master-card and thread context, plus the prior output as `PREVIOUS_SKILL_RESULT`.
7. **Expected behavior:** The returning gate receives the worker result, the complete current task conversation, the canonical master objective, and a distinct execution identity while retaining the admitted prompt revision, commit, and snapshot.
8. **Acceptance signal:** `backend/test/codex/start-codex-pipeline-run-controller.test.ts` asserts the returning input contains the master objective, latest operator message, `PREVIOUS_SKILL_RESULT` with `WORKER_RESULT`, the task thread ID, and a different returning execution ID.
