## A. Identity Result

1. **Existing local authority:** Each project already persists a stable URL-safe ID in `.decision-os/project.json`; discovery reuses it across path changes and server restarts.
2. **Node authority:** Each Decision OS environment receives one relay-issued stable `nodeId` stored with its credential in ignored local settings.
3. **Global key:** A project is globally identified by `{ownerNodeId, localProjectId}`. The route-facing opaque reference is `${ownerNodeId}:${localProjectId}` for remote projects; local projects keep their existing IDs.
4. **Git identity:** Two clones of one Git repository remain two owner-qualified Decision OS projects. Matching remotes or commit SHAs do not collapse ownership.

---

## B. Catalog Contract

1. **Node manifest:** `{protocolVersion, federationId, nodeId, bootId, revision, projects[]}`; each project record contains local identity, display metadata, and ledger summaries.
2. **Relay persistence:** Persist node membership, revocation state, and the latest accepted manifest. Do not persist ledgers, cards, threads, assets, Git state, repository URLs, credentials, or Codex output.
3. **Requester view:** Merge the local catalog with authorized remote manifests and add owner, local, route, and presence identity fields.
4. **Presence:** Send a heartbeat every `15 s`; mark a node offline after `45 s` without a heartbeat.

---

## C. Git State Contract

1. **On-demand snapshot:** Git status belongs to the live owner response, not the persisted federation manifest. This prevents stale catalog data from being presented as current repository state.
2. **Local-reference meaning:** `ahead` and `behind` compare the current branch to the locally stored upstream ref. The response sets `networkFresh: false` until an owner-side task completes a fetch and a later status is requested.
3. **Clone correlation:** Show a repository fingerprint only after a separate privacy decision. Remote URLs can contain usernames and tokens, so the proof does not transmit them.
4. **No ownership transfer:** A push updates a Git remote; it does not move Decision OS ownership, transfer local run state, or merge two project identities.

---

## D. Convergence Rules

1. **Manifest replacement:** A node publishes a complete manifest after connect and whenever local discovery changes. The relay accepts only a higher revision within the same boot.
2. **Project removal:** Absence from a newer full manifest removes the online route; a disconnected manifest remains display-only.
3. **Git refresh:** The UI invalidates the selected project's Git snapshot after an owner Codex run settles, then requests a new owner-computed snapshot.
4. **Source handoff:** A pushed commit becomes available to another clone only after that clone fetches. Fast-forward succeeds only when its local worktree and history permit it.
