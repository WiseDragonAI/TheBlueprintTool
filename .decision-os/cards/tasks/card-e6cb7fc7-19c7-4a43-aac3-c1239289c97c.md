## A. Identity Result

1. **Existing local authority:** Each project already persists a stable URL-safe ID in `.decision-os/project.json`; discovery reuses it across path changes and server restarts.
2. **Node authority:** Each Decision OS environment receives one relay-issued stable `nodeId` stored with its credential in ignored local settings.
3. **Global key:** A project is globally identified by `{ownerNodeId, localProjectId}`. The route-facing opaque reference is `${ownerNodeId}:${localProjectId}` for remote projects; local projects keep their existing `localProjectId` URLs.
4. **Collision result:** Equal phone and workstation project IDs remain distinct because the owner is part of the global key.

---

## B. Catalog Contract

1. **Node manifest:** `{protocolVersion, federationId, nodeId, bootId, revision, projects[]}`; each project record contains `localProjectId`, name, description, color, and ledger summaries.
2. **Relay persistence:** Persist node membership, revocation state, and the latest accepted manifest. Do not persist ledgers, cards, threads, assets, uploads, or Codex output.
3. **Requester view:** Merge the local catalog with the latest authorized remote manifests and add `ownerNodeId`, `localProjectId`, `routeProjectId`, and `presence` to each runtime record.
4. **Presence:** Send a heartbeat every `15 s`; mark a node offline after `45 s` without a heartbeat. Cached manifest entries remain visible with `presence: offline`.

---

## C. Convergence Rules

1. **Full replacement:** A node publishes a complete manifest after connect and whenever local discovery changes. The relay accepts only a higher `revision` within the same `bootId`; a new `bootId` starts a new revision sequence.
2. **Rename:** Update display metadata under the same global key.
3. **Removal:** Absence from a newer full manifest removes the project from the online union; the relay retains no content copy.
4. **Stale manifest:** A disconnected node's manifest is display-only and cannot route reads, mutations, uploads, events, or Codex operations.
5. **Ownership transfer:** Treat import on another node as a new global project identity. Automated ownership transfer and content copying are outside this proof.
