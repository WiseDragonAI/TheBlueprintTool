## A. Implemented result

1. **Manual completion:** `Complete manually` retains the existing `complete-master-task` mutation and returns to the Control Room queue.
2. **Pipeline completion:** `Complete with pipeline` admits the configured server pipeline with the current `ledgerId`, master-card `sourceCardId`, and saved `pipelineId`, then opens Exec.
3. **Settings:** `masterTaskCompletionPipelineId` is exposed and validated through `/api/settings/codex-processes`, persisted in `.decision-os/.settings.json`, and selectable as `Master-task completion pipeline`.
4. **Responsive behavior:** desktop renders the two actions side by side; mobile stacks the same controls vertically. An unconfigured pipeline disables its action, and admission rejection leaves the task open while showing the server error.
