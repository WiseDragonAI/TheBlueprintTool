## A. Verified storage map

1. **Subtask truth already exists in JSON:** every card has `status`; `ledger-cli done` changes only `cards[].status` and writes the ledger once.
2. **Subtask status is duplicated in Markdown:** `master-task-apply` generates each canonical link with `— Status: pending`; `master-task-gate` parses that suffix and reports `stale_subtask_projection:<card-id>` when it disagrees with JSON.
3. **Master visible status is already derived without the Markdown status token:** the Control Room maps `card.status === done` to complete, live queued or processing runtime state to active, and the remaining `todo` state to waiting.
4. **Markdown still controls classification and validation:** `#master-task`, exactly one `#task-*` token, `Ledger`, and lifecycle timestamps are parsed by `validate-master-tasks`; canonical subtask membership is also recovered from Markdown links during completion.
5. **Relationships duplicate membership:** `master-task-apply` creates `label: subtask` relationships at the same time as Markdown links, but completion and the gate do not use those relationships as the authoritative subtask set.

---

## B. Mutation chain

1. **Plan:** `master-task-apply` snapshots the ledger and card files, generates IDs, writes master and subtask Markdown, writes relationships, and then writes JSON.
2. **Progress:** each `done` invocation validates one card, changes one JSON status, and rewrites the ledger. It does not update the master Markdown.
3. **Projection repair:** the agent must use generic `mutate --card-comment-file` to rewrite the master Markdown status suffixes because no `master-task-sync` command exists.
4. **Gate:** `master-task-gate` rereads JSON and documents, validates the lifecycle header, checks every linked JSON status, compares every Markdown status suffix, and validates thread roles.
5. **Completion:** `master-task-complete` calls the server; the server sets every linked subtask and master JSON status to `done`, rewrites the master lifecycle token and status suffixes, writes the ledger, then creates a scoped Git commit.

---

## C. Verified defect

1. **The instruction has no executable counterpart:** the launch prompt says `ledger-cli done` and “sync projections,” while `ledger-cli --help` exposes no projection synchronization command.
2. **The gate makes the unsupported step mandatory:** a correct JSON status update can still fail closeout solely because an agent-authored Markdown suffix is stale.
3. **The generic mutation path cannot enforce master-task invariants:** it accepts a whole replacement body and cannot atomically bind the content edit to the corresponding JSON status changes.
