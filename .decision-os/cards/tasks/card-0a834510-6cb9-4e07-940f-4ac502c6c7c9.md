## A. Objective

1. **Keep** every long-lived Codex run-status poll bound to its originating project across mobile route changes.

---

## B. Result

1. **Implemented:** the run poller captures `projectId` once, includes it in the poller key, and sends every status request through the captured `/p/:projectId` scope.
2. **Cleanup:** closing the mobile thread unregisters its thread-log consumer and cancels the background poll timer when no widget remains.
3. **Regression:** focused coverage proves teardown removes the scheduled poll and reopening the same run starts a fresh scoped request.
4. **Served verification:** on mobile Chromium, `scoped card -> running thread -> Control Room -> wait past poll interval -> same active card` produced only project-scoped HTTP `200` run-status responses, zero unscoped run-status requests, and no `Project id is required in the URL` Codex Log state.
5. **Delivery:** implementation commit `164a160` was merged by `0fc9cbe`.
