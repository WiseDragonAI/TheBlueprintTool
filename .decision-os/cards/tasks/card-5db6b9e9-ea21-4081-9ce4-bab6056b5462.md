## B. Measurements

1. **Aggregate:** `94` completed shell calls, `65` textual `ledger-cli` invocations, and `5` failed shell calls.
2. **Complex study:** the federated-environments run issued `28` `ledger-cli` invocations: `9` generic content mutations, `7` real subtask completion writes, `2` validations, `3` gates, `1` answer, plus help and context reads.
3. **Summary runs:** the two lesson-summary runs used `8` and `6` invocations. Their write path was master content mutation, gate or validation, and thread answer as separate commands.
4. **Authorized closeouts:** the three retrospective runs used `5`, `6`, and `12` invocations. Each ultimately needed one `master-task-complete`; the remaining calls were help, repeated context reads, and gates before and after completion.
5. **Observed duplication:** the complex study created eight temporary Markdown files, called generic mutation once per card, called `done` once per verified subtask, and embedded `Status: complete` manually in the master update.

## C. Instruction effect

1. **Current launch guidance is compact but incomplete:** it names `master-task-apply`, `done`, `master-task-gate`, `master-task-complete`, and `answer`.
2. **Missing contract:** “sync projections” names an outcome, not a command or payload, so agents discover the generic mutation path through help and repeated context inspection.
3. **Resulting behavior:** agents correctly treat JSON as truth, then spend additional commands recreating and checking the Markdown duplicate demanded by the gate.
