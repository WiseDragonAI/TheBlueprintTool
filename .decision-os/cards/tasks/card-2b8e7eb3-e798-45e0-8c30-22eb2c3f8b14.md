#master-task

Ledger: Specs

## A. Outcome

Make an operator click on `Run` launch Codex regardless of stale card, queue, recovery, or terminal run metadata. Reject launch only when the target thread already has a live Codex process.

---

## B. Acceptance

1. **Authoritative launch:** A stale or non-live prior run cannot suppress a new operator-triggered run.
2. **Single live process:** A second launch is rejected only while the target thread has a verified live process.
3. **Regression coverage:** Automated tests exercise stale metadata, non-live queue state, and live-process rejection.
4. **Target verification:** The operator-facing route serves the changed files and the Run action is exercised in Chromium after the running backend loads the merged code.
