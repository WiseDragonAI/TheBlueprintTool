#master-task

Ledger: Specs

## A. Scope

1. **Surface:** Change the mobile master-task detail completion flow in `frontend-mobile/src/mobile.js`.
2. **Return behavior:** After `complete-master-task` succeeds, return to the route from which the operator opened the master task.
3. **Fallback:** When no prior internal route is recorded, return to the Control Room at `/`.

---

## C. Acceptance Criteria

1. **Successful completion:** The completed master-task detail is not rendered in place after the server mutation succeeds.
2. **Navigation continuity:** A master task opened from a mobile application route returns to that exact route, including query and hash state.
3. **Control Room fallback:** A completion without recorded route history returns to `/`.
4. **Regression coverage:** `frontend-mobile/test/mobile-control-room.test.mjs` verifies the completion navigation contract and passes.
