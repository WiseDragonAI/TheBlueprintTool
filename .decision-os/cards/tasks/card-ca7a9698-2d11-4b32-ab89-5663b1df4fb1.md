## A. Executive Decision

1. **Goal:** let an operator request workstation poweroff from Decision OS, then wait until every local Codex job has finished.
2. **Selected architecture:** Decision OS owns the drain decision; `systemd-logind` performs the final poweroff.
3. **Workstation fit:** systemd `255` reports `CanPowerOff = yes`; the runtime needs no `sudo`, root helper, or custom polkit rule.
4. **Scope:** the shutdown gate covers every registered project executing on this workstation. Work owned by another federation node does not block local poweroff.

---

## B. Operator Experience

1. Select **Power off after queue** in the Control Room and confirm once.
2. Decision OS stops accepting new local Codex launches and completes the existing queue.
3. The Control Room shows pending and running counts throughout the drain.
4. The operator can cancel before poweroff begins; cancellation immediately reopens Codex admission.
5. When the workstation is idle, Decision OS asks systemd to power off.

---

## C. Safety Guarantees

1. **No early shutdown:** pending queue items, running processes, project-sync work, and an active scheduler block poweroff.
2. **No shutdown loop:** the request records the Linux boot ID and transitions to `firing` before systemd is invoked.
3. **No automatic retry:** a fired, failed, stale-boot, or malformed request requires a new explicit operator action.
4. **Visible failure:** authorization and command failures remain visible in Decision OS with the exact diagnostic.
5. **Safe verification:** automated tests use an injected fake executor and can never invoke the workstation poweroff command.
