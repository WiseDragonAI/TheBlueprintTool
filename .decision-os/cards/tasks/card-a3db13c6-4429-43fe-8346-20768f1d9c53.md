## A. Objective

1. Make `STOP`, pending `CANCEL`, continuation, pipeline lifecycle actions, and thread-session deletion target the correct run kind and execution.

---

## B. Verified Evidence

1. Pipeline source-card `STOP` fails because runtime owns the output card.
2. Frontend cancellation omits execution identity.
3. Pipeline entries receive generic thread actions; pending entries expose no cancellation.

---

## C. Implementation Contract

1. Resolve actions from typed run kind, projection owner, source card, output card, run, and execution.
2. Send and validate `{cardId, runId, executionId}` for every active command.
3. Expose `CANCEL` for pending and `STOP` for running.
4. Fence stale commands before process mutation.
5. Route projected pipeline cancellation through pipeline ownership.
6. Restrict thread-session deletion to retained thread sessions.

---

## D. Acceptance Tests

1. Source-card pipeline `STOP` cancels the exact process.
2. Stale `STOP` cannot cancel newer same-run execution.
3. Pending cancellation removes one lease.
4. Temporary and pipeline runs never receive thread-session deletion.
5. Adopted and moved-card commands resolve persisted owner.
