## A. Scope

1. Remove the combined task/content snapshot path: `federation-task-replica.ts`, `/api/federation/task-replica`, `federation-task-replicas-v1.json`, the 15-second replica poller, and task-state dependence on snapshot invalidation frames.
2. Define an owner-produced content manifest for card Markdown, thread Markdown, and referenced managed assets with stable resource key, content hash, byte size, and changed date.
3. Implement a persistent asynchronous content queue that diffs manifests and transfers only missing hashes after priority state work.
4. Give content an independent low-priority credit window, concurrency cap, retry schedule, and cancellation boundary.
5. Verify hashes and install content atomically; retain the last verified local version on interruption or corruption.
6. Expose `missing`, `synchronizing`, `available`, and `stale` states without blocking task metadata reads.
7. Keep content bytes outside task events and state snapshots; preserve owner-scoped mutation and intentional Git commits.

---

## B. Acceptance

1. A task appears with complete metadata before its content manifest or content bytes arrive.
2. Saturated, stalled, failed, and corrupt content transfers do not delay task events, acknowledgements, state snapshot bootstrap, or convergence.
3. Unchanged hashes transfer zero bytes; changed resources install atomically and survive restart.
4. Offline reads use the last verified local content and expose `stale`; missing content exposes `missing` without hiding the task.
5. The old hydrated replica builder, endpoint, store, timer, and task-state invalidation workflow are absent.
6. Event and state-snapshot payload tests contain no content bytes.
