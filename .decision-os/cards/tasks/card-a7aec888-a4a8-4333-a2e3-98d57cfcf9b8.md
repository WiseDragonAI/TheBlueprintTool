## A. Objective

1. **Reduce cross-node image transfer and canvas rendering cost without weakening local-first durability.**
2. Persist image intent and the locally captured original before acknowledgement; synchronize structural state immediately and fetch image bytes only when a consuming surface demands them.
3. Preserve the original immutable image as the fidelity source while adding one deterministic `canvas-preview-v1` derivative capped at `768px` on its longest edge.

---

## B. Existing Foundation

1. Epoch 4 already synchronizes resource heads eagerly and transfers immutable content objects on demand.
2. The canvas already mounts detailed card content only for visible cards, uses lazy image decoding, and persists image dimensions through `imageSizes`.
3. Card and thread image URLs already resolve through project-scoped routes.

---

## C. Required Delivery Boundary

1. Generate and retain the preview beside the original after the local backend accepts an image.
2. Replicate original and preview identities, hashes, dimensions, media types, and derivation version without eagerly transferring either body.
3. Demand `canvas-preview-v1` for visible canvas cards; demand the original for detail and fullscreen surfaces.
4. Keep raw voice audio outside this image synchronization contract.
5. Preserve exact-hash verification, conflict visibility, bounded demand, retry backoff, cache reachability, and garbage-collection safety.

---

## D. Acceptance Criteria

1. An accepted image survives local restart before relay availability.
2. A remote canvas fetches only the preview for a visible card and does not fetch the original.
3. Opening detail and fullscreen views fetches the original on demand and preserves current resize behavior.
4. Two nodes converge on the same derivative identity for the same original and derivation version.
5. Performance evidence records transferred bytes, decode work, demand count, cache hits, and visible-card render timing against the current implementation.
