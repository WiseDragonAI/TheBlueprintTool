## A. Scope

1. Render the latest authoritative run identity, phase, and failure detail in the existing Project Settings synchronization panel.
2. Change the failed-state action to `Retry synchronization`; route it through the backend recovery operation.
3. Keep the control pending until the response settles, reject duplicate activation, and replace local state with the returned run.
4. Render `cancelled` distinctly and keep recovery errors attached to the failed run.

---

## B. Acceptance criteria

1. A failed run presents one retry action and never sends a plain new-start request.
2. Successful recovery updates through the initial response and subsequent SSE events, then survives reload.
3. Failed conditional cancellation leaves the original failed run visible with the server error.
4. The served Project Settings surface demonstrates the screenshot scenario recovering to a new active run, then reaching a terminal result.

---
