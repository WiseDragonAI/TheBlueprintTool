## A. Scope

1. **Objective:** Make the backend the sole durable owner of voice transcription phases, deadlines, timing evidence, and note-scoped status reads.
2. **Primary files:** `backend/src/business/transcription/controller/start-voice-upload-orchestration-controller.ts`, `backend/src/business/transcription/effect/call-openai-transcription.ts`, `backend/src/business/server/helper/create-http-server.ts`, and the ledger note metadata helpers.

---

## B. Implementation Contract

1. **Phases:** Persist `uploading`, `queued`, `transcribing`, `finalizing`, `transcribed`, and `transcription failed` as server-owned states for the existing `noteId`.
2. **Timing:** Persist and emit `uploadReceivedAt`, `audioPersistedAt`, `acceptedAt`, `providerStartedAt`, `providerSettledAt`, `completedAt`, and a monotonically increasing note `revision`.
3. **Status read:** Add `GET /api/voice-transcription-status?ledgerId=<id>&threadId=<id>&noteId=<id>` and return only the requested note lifecycle fields, body, error, and `voiceFileRef`.
4. **Deadline:** Enforce `120_000ms` around the provider request with `AbortController`, persist `transcription failed` on expiry, and preserve the audio file for retry.
5. **Publication:** Publish the scoped thread-content event after each persisted phase transition. Include `ledgerId`, `threadId`, `contentFile`, `noteId`, `status`, and `revision`.
6. **Ordering:** Reject a phase write whose revision is older than the currently persisted note revision.
7. **Telemetry:** Record each timing boundary and the duration between adjacent boundaries without recording audio, transcript text, or API credentials.

---

## C. Acceptance Criteria

1. **Authoritative terminal state:** Success, provider failure, configuration failure, and deadline expiry each persist exactly one terminal note state.
2. **Targeted response:** The status route rejects incomplete scope, unknown ledgers, unknown threads, and unknown notes; a valid request returns only the requested note.
3. **Retry preservation:** Every terminal failure retains the original `voiceFileRef` and remains compatible with the existing retry path.
4. **Latency diagnosis:** Focused tests prove every phase timestamp and duration is emitted in lifecycle order.
5. **Regression coverage:** Backend orchestration tests cover success, provider rejection, deadline abort, stale revision rejection, and note-scoped status reads.
