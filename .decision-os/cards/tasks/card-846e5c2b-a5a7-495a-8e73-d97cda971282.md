#master-task

Ledger: Specs
Queue rank: 3

## A. Scope

1. **Surface:** Add destructive task deletion to the mobile master-task detail in `frontend-mobile/src/mobile.js`.
2. **Placement:** Render `Delete master task` below `Complete master task` at the bottom of the master-task detail.
3. **Persistence:** Delete only the selected master-task card through the existing `delete-card` ledger mutation; preserve linked subtask cards.

---

## B. Interaction Contract

1. **Confirmation:** Opening deletion must show a modal that names the destructive action and states that linked subtasks are preserved.
2. **Cancellation:** `Cancel` must close the modal without changing ledger state.
3. **Success:** Confirming deletion must remove the master-task card and return to the mobile Control Room.
4. **Failure:** A rejected deletion request must show the existing error view and must not report success.

---

## C. Acceptance Criteria

1. **Button:** A full-width destructive `Delete master task` button appears below the completion button for master tasks only.
2. **Modal:** The delete mutation cannot run before explicit confirmation.
3. **Mutation:** Confirmation sends `{ action: 'delete-card', cardId }` for the displayed master task.
4. **Regression:** The mobile Control Room test asserts placement, modal copy, mutation payload, navigation, and destructive styling.
