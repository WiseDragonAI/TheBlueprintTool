Ledger: Specs

## A. Operator outcome

1. Terminal Codex turns must settle even when the wrapper process remains alive.
2. Every ordinary thread-run settlement must publish the ledger event that refreshes the canvas.

---

## B. Implemented lifecycle correction

1. Terminal `complete`, `failed`, and `cancelled` JSONL events now start a five-second wrapper close grace period.
2. A wrapper still alive after the grace period receives `SIGTERM` as a process group, followed by `SIGKILL` after two additional seconds when required.
3. Settlement preserves the terminal event status, removes the queue entry, and clears `codexActiveRunId` only when it still belongs to the settling run.
4. Every non-pipeline thread settlement publishes one scoped `codex-thread-settled` ledger event containing ledger, card, thread, run, and status identity.
