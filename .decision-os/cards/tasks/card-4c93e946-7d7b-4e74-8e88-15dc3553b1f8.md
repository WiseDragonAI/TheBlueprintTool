## A. Scope

1. **Type:** `code`.
2. **Targets:** `frontend/src/app/responsive/application.js` and `frontend/assets/application.css`.
3. **Symbols:** `initializeQueueSortable()`, `syncQueueFromDom()`, `persistQueueOrder()`, and `ledgerMutation()`.
4. **Library:** Reuse vendored SortableJS `1.15.7`, MIT license, loaded at runtime by `frontend/src/app/controller/boot-application.ts`.

---

## B. Implementation

1. Create grouped Sortable instances for the desktop Backlog and Queue lane lists.
2. Keep Exec outside the writable Sortable group.
3. On drop completion, update the in-memory collections before awaiting persistence.
4. Persist Queue to Backlog as `status: backlog`.
5. Persist Backlog to Queue as `status: todo` with the resulting queue ranks.
6. Preserve same-lane queue ordering and the existing drag visual classes.
7. After the latest rejected mutation, reload the Control Room projection and render server-confirmed state.

---

## C. Completion

1. Queue to Backlog and Backlog to Queue both persist.
2. Same-lane queue reordering still persists queue ranks.
3. The destination lane updates before the persistence request resolves.
4. A fresh reload preserves successful movement.
5. A rejected request restores server-confirmed placement.
6. Exec accepts no drop.
