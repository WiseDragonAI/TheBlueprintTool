## A. Cloudflare Failure Contract

1. **Requester disconnect:** Cancel its open remote streams at the owner. A completed owner mutation remains authoritative and is discovered by refresh.
2. **Owner disconnect:** Fail new work with `503 owner_offline`, terminate finite streams, and close bridged SSE so the browser reconnect path retries.
3. **Durable Object restart:** Reconstruct connected node identity from socket attachments and membership plus manifests from SQLite; discard unpersisted in-flight routes and return an ambiguous outcome for mutations.
4. **Cloudflare runtime replacement:** Both connectors treat a closed socket as relay loss and reconnect. Local projects remain fully usable.
5. **Codex continuation:** Requester loss does not kill an owner process; explicit cancellation does. The owner persists run settlement through its existing path.

---

## B. Platform Bounds

1. **Worker limits:** Current Free-plan limits include `128 MB` memory, `10 ms` CPU per invocation, `100,000` Worker requests per day, and `100 MB` request bodies. WebSocket messages received by Workers are limited to `32 MiB`.
2. **Durable Object limits:** SQLite-backed objects are available on the Free plan. One object supports up to `32,768` WebSockets, while this proof admits exactly two node sockets and `32` streams per node.
3. **Hibernation:** `acceptWebSocket()` allows idle sockets to remain connected without duration charges. Protocol ping/pong is handled by Cloudflare without waking the object. Outbound sockets from the Durable Object are prohibited because they prevent hibernation.
4. **Data path:** Relay `64 KiB` binary chunks directly between accepted client sockets; do not buffer full uploads or persist streamed bodies. Explicit credit bounds unacknowledged data to `1 MiB` per request direction.
5. **Placement:** Create the federation object with the `apac-se` location hint from the first proof connection. Durable Object placement does not move after creation, and the hint is best effort.

---

## C. Cost Boundary

1. **Free allowance:** Workers Free currently includes `100,000` requests per day. Durable Objects Free includes `100,000` requests and `13,000 GB-s` per day with SQLite storage.
2. **Message billing:** Incoming Durable Object WebSocket messages use a `20:1` ratio for compute-request billing. Outgoing WebSocket messages and protocol pings are not billed as requests. Cloudflare lists no data-transfer charge for Workers.
3. **Idle cost:** Hibernatable accepted sockets do not accrue idle duration. This makes a low-traffic two-node proof likely to remain inside the free allowances, subject to measurement.
4. **Paid floor:** The Workers Paid plan currently has a `$5/month` minimum and higher included limits. No paid plan is selected for the proof.

---

## D. Measurements Required

1. **Correctness:** Exercise discovery, mutation, upload, voice, SSE, Codex launch, status, cancellation, duplicate requests, ambiguous disconnects, revocation, and reconnection in both directions.
2. **Cloudflare:** Record Worker and Durable Object request counts, CPU time percentiles, duration, memory percentiles, errors, reconnects during a deployed version change, and SQLite size.
3. **Network:** Record Thailand-to-object round-trip latency, event latency, finite-request latency, `25 MiB` upload throughput, and cancellation propagation.
4. **Flow control:** Prove outstanding credit never exceeds `1 MiB` per request direction and a non-reading receiver cannot cause unbounded relay memory.
5. **Pass thresholds:** No buffer exceeds the hard bound, local project latency remains unchanged within measurement noise, a `25 MiB` upload completes, and event plus cancellation propagation remain below `2 s` on the test network.
