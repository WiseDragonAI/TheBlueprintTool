Ledger: Specs

## A. Implemented lifecycle

1. **Classification:** `cards[].labels` now carries `master-task` and `subtask`; the `tags` field remains a read-only compatibility alias.
2. **Status:** `cards[].status` is the sole persisted completion source.
3. **Membership:** direct `relationships[label=subtask]` entries are authoritative and endpoint-label mismatches are diagnosed.
4. **Markdown:** task hashtags and status suffixes are no longer generated or validated; Markdown contains operator content, lifecycle timestamps, and canonical navigation links.

---

## B. Atomic CLI workflow

1. **Apply:** `master-task-apply` creates automatic card and relationship IDs, writes canonical JSON labels, and generates relationship-backed links without status projections.
2. **Progress:** `master-task-progress --plan-stdin --json` preflights the complete plan, updates content and labels, marks verified subtasks, regenerates links, appends one agent reply, rolls back every affected file on failure, and returns the post-write gate.
3. **Completion:** `master-task-complete` validates JSON labels and relationships, touch-migrates legacy Markdown, and returns its post-transaction gate result. Only this explicitly authorized command can complete the master.

---

## C. Runtime migration

1. **Control Room:** backend projection and mobile detailed-card parsing now use JSON labels, JSON statuses, canonical relationships, and live run state.
2. **Compatibility:** legacy Markdown classification is accepted only when a card has no JSON task label.
3. **Touch migration:** apply, progress, and completion add canonical labels and remove legacy task tokens without bulk-rewriting untouched cards.

---

## D. Agent contract

1. **Injected prompt:** agents are instructed to plan with `master-task-apply`, record verified progress with one `master-task-progress` transaction, treat the ledger gate as truth, and reserve master completion for explicit authorization.
2. **Data model:** no structured task type, duplicate status field, queue rank, or subtask ID array was added.
