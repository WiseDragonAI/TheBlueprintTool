## A. Frontend Result

1. **Preserve the validated route model:** Keep `/p/:projectId/...`; a remote catalog record uses one owner-qualified opaque route segment.
2. **Preserve request scoping:** The existing global `fetch` wrapper and ledger `EventSource` prepend the active project route. They do not need separate remote endpoint logic.
3. **Server decision:** Extend project resolution so local IDs dispatch locally and owner-qualified IDs use the federation connector.

---

## B. Required Runtime Changes

1. **Catalog:** Return the merged local and authorized remote catalog with owner and presence fields.
2. **Navigation:** Use the route project identity in project, ledger, zone, and card URLs; keep the local ID only for owner dispatch.
3. **Control Room:** Fetch each online owner's read model through the relay, qualify project IDs, merge it with the local projection, and bridge each owner's event stream.
4. **Project surface:** Reuse the current ledger, card, thread, asset, upload, voice, and Codex components.
5. **Live changes:** Convert the remote owner's relayed SSE bytes back into the browser-facing SSE response.

---

## C. Git Operator Surface

1. **Selected-project status:** Add a compact repository panel that requests `GET /api/git/status` only when opened. Show repository presence, branch, abbreviated head, upstream, ahead, behind, staged, unstaged, untracked, conflicted, operation state, check time, and `Local refs`.
2. **Freshness:** Label the snapshot `Local refs` until an owner task fetches. Do not imply that zero ahead or behind means the network remote is current.
3. **Action:** Provide one `Create reconciliation task` action that drafts a normal task on the selected owner project. Launch remains the existing explicit Codex control.
4. **No shell UI:** Do not add command text fields, Git action buttons, credential inputs, remote URL display, automatic pull, automatic push, or unattended conflict controls.

---

## D. Presence and Refresh

1. **Online:** Show the owner label and allow the same project actions as local projects.
2. **Offline:** Keep cached project summaries visible as `Owner offline`; disable Git refresh, mutations, uploads, voice, and Codex launch.
3. **Run settlement:** After an owner Codex run settles, invalidate the displayed Git snapshot and request it again when the repository panel is visible.
4. **Local continuity:** Relay loss never changes local project routing, local event subscriptions, local mutations, or local Codex execution.
