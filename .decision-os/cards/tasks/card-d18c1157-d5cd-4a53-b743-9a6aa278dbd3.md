## A. Objective

1. **Keep every Control Room Active timer anchored to the latest logical Codex launch.**
2. **Prevent queue dispatch and server recovery from resetting unrelated task clocks to the same time.**

---

## B. Contradicted-Claim RCA

1. The previous fix replaced every direct task’s persisted `Active since` timestamp with the status API’s process-segment `startedAt` timestamp.
2. The server-wide concurrency limit was `5`. On recovery, five queued continuations were dispatched within `679 ms` and each received a new process-segment marker.
3. The screenshot at `2026-07-14T19:18:01.609Z` therefore showed five `00:29` timers even though their logical launch requests had occurred at different times.
4. The first incorrect transition was `process recovery → new segment startedAt → Control Room clock anchor`.

---

## C. Corrected State Contract

1. Direct Codex tasks use the persisted card `Active since` value written when the operator launches the logical run.
2. Pipeline tasks use the durable pipeline attempt `resumedAt`, falling back to pipeline `createdAt`.
3. Codex Log process-segment timing remains independent and can reset when a process is recovered.

---
