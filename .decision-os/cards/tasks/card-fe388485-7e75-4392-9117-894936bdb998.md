## B. Corrected Root Cause

1. **The visible reset was real backend churn, not a Settings-render reset.** The root and the still-running source process shared one node credential and replaced each other every one to two seconds with close code `4001`.
2. **The previous relay crash fix exposed this second failure instead of resolving it.** Once socket replacement stopped throwing HTTP `500`, both connectors could successfully replace each other, so every replacement reset the backend `connectedAt`.
3. **Credential rotation removed the active collision immediately.** The stale source credential is no longer authorized and cannot replace the root socket. The settings file remains mode `600`.

## C. Permanent Connector Contract

1. **Duplicate identity is terminal.** A connector closed with `4001 replaced` enters `disconnected` and does not retry until an explicit Save/Connect reconfiguration.
2. **Authentication rejection is terminal.** HTTP `401` or `403` records a precise backend error and waits for explicit credential correction instead of generating an infinite retry loop.
3. **Navigation is regression-tested.** Two consecutive Settings GETs preserve `connectedAt` and keep the relay socket count unchanged. Focused federation tests pass `3/3`; backend typecheck passes.
