## A. Repository Intent

1. **Decision OS** serves every discovered project from one node process, connects each node to one federated relay, preserves task-state convergence, and keeps runtime diagnostics available when one project or subsystem fails.
2. **MultiTerm** owns workstation background-process registration, launch, bounded restart, log rotation, and restart-circuit incidents.
3. **Cloudflare Wrangler** owns the production relay version upload and traffic deployment for `decision-os-federation-relay`.
4. **Git** owns reviewed source identity. A delivery must preserve unrelated working-tree bytes and protected staged hunks while promoting one admitted `dev` commit through a reviewable `main` merge commit.

## D. Findings

1. **Gap — no delivery authority:** no source component owns admission, `main` promotion, relay versioning, node activation, restart receipts, convergence, compensation, and the final outcome.
2. **Gap — no admitted-dev record:** the canary runbook is precise, but no durable record ties its checks to one clean `origin/dev` SHA.
3. **Gap — no safe merge owner:** no command creates the required `main` merge commit from an exact admitted SHA in an isolated integration worktree and pushes it with the Wise SSH identity.
4. **Gap — no application version identity:** `/api/health` cannot prove which Git SHA the restarted node serves.
5. **Gap — no relay release identity:** relay `/health` cannot correlate the active Worker code with the promoted Git SHA.
6. **Gap — no remote install contract:** federation can proxy bounded HTTP requests, but no authenticated node endpoint stages immutable application code and dependencies.
7. **Gap — no supervisor-adoption contract:** the workstation has MultiTerm supervision, while the source has no cross-platform declaration proving that every target node restarts the stable release launcher after a clean exit.
8. **Gap — unsafe restart authorization:** `/api/server/restart` is a global unscoped route. It accepts no authenticated peer, target SHA, delivery ID, expected current SHA, or replay guard.
9. **Gap — pre-exit acknowledgement is not restart proof:** a successful restart response does not establish process replacement, installed SHA, HTTP readiness, federation reconnection, catalog restoration, or root convergence.
10. **Gap — no durable rollout journal:** runtime incidents and MultiTerm incidents capture component failures, but neither records the complete cross-system release state needed for resume and compensation.
11. **Gap — no safe application rollback:** rewinding a dirty checked-out branch would risk operator work. The existing Git topology provides no immutable runtime release pointer.
12. **Gap — relay rollback is outside the product:** Wrangler can redeploy a previous version, but Decision OS does not capture that version before mutation or bind it to node rollback.
13. **Gap — offline ownership policy was absent:** the durable manifest catalog provides a concrete answer. Every nonempty-manifest node is an active release target, and any offline active target blocks before `main` changes.
14. **Drift — canary documentation claims an isolated Wrangler `env.dev`, while the inspected `federation-relay/wrangler.toml` contains only the top-level production Worker and bindings.** The local `--env dev` proof does not establish a source-defined distinct Worker configuration.
15. **Omission — project convergence is only locally observable:** complete admission requires the same status response from every active target node, not only the coordinator.
16. **Omission — delivery and authored Git writes share one repository:** promotion needs an exclusive repository delivery lock and must reject concurrent authored commits before the merge candidate is created.

## E. Selected Ownership Boundary

1. Add one executable owner: **`bin/decision-os-delivery.mjs`**, published as **`decision-os-delivery`** from root `package.json`.
2. The one-command release contract is:

   ```text
   decision-os-delivery promote --release-sha <admitted-origin-dev-sha> --server http://127.0.0.1:50150 --json
   ```

3. `promote` is non-interactive. The explicit invocation is the operator promotion decision. Missing credentials, missing node adoption, offline active nodes, dirty admission, non-convergence, a changed remote ref, and failed verification return before irreversible mutation.
4. The CLI process owns orchestration so restarting the coordinator server cannot destroy the delivery controller.
5. The local server owns only authenticated topology and node-operation transport. Add coordinator routes that proxy bounded delivery requests through `FederationNodeConnector.request()`.
6. Each node owns only its local immutable release preparation, active-release pointer, health receipt, and supervised exit.
7. Store coordinator runs under `<catalog-root>/.decision-os/delivery/runs/<deliveryId>.json`. Store node receipts under the node settings root at `.decision-os/delivery/nodes/<deliveryId>.json`. Use atomic replace and preserve invalid bytes under a timestamped corrupt name.
8. Add one filesystem lock at `<catalog-root>/.decision-os/delivery/lock`. The lock records delivery ID, PID, start time, admitted SHA, and a finite expiry. A live lock rejects a second delivery.
9. Install runtime code into immutable detached Git worktrees under the configured absolute `deliveryReleaseRoot`, keyed by the resulting `main` SHA. Never activate code from the dirty primary checkout.
10. Point each node supervisor at one stable `current` symlink below `deliveryReleaseRoot`. Activation atomically replaces that symlink, replies with the staged SHA, and schedules a clean process exit. The supervisor restarts the same stable path.
11. MultiTerm remains the workstation supervisor. Mobile must declare the same supervised-exit contract through ignored node settings before it enters the target set.
12. A one-time `decision-os-delivery bootstrap-node` adoption is required on every active node before the first distributed promotion. Routine delivery then uses the single `promote` command.

## F. Command And Data Contract

1. **Promote input:** exact 40-character `releaseSha`, local coordinator URL, JSON-output flag, and an optional existing `deliveryId` used only by `resume`.
2. **Derived immutable identities:** `previousMainSha`, `admittedDevSha`, generated `mainSha`, previous relay deployment ID, uploaded relay version ID, active target node IDs, and each node's previous active release SHA.
3. **Required phases:** `admitting`, `verifying`, `merging-main`, `uploading-relay`, `deploying-relay`, `activating-nodes`, `verifying-nodes`, `verifying-convergence`, `complete`.
4. **Failure phases:** `admission-rejected`, `paused`, `compensating`, `rolled-back-runtime`, `compensation-failed`.
5. **Node receipt fields:** node ID, delivery ID, previous SHA, staged SHA, dependency-install result, active SHA, prior process start identity, new process start identity, supervisor declaration, health result, federation phase, incident summary, and phase timestamps.
6. **Coordinator evidence fields:** exact commands as argument arrays with secrets redacted, stdout and stderr artifact paths, exit codes, Git object IDs, Cloudflare deployment IDs, relay health bodies, node responses, convergence snapshots, retry count, failure code, and final status.
7. **Exit codes:** `0` only for `complete`; `2` for admission rejection before mutation; `3` for durable paused or partial state; `4` for failed compensation.
8. **Companion commands in the same CLI:** `status --delivery-id`, `resume --delivery-id`, `rollback --delivery-id`, and `bootstrap-node`. They do not create a second release owner.

## G. Promotion Protocol

1. Acquire the delivery lock and create the durable run before network or Git work.
2. Fetch `origin/main` and `origin/dev` using the Wise SSH identity in `BatchMode`.
3. Require `origin/dev` to equal `--release-sha`, require every tracked source worktree involved in the release to have no staged hunks, require no active Git operation, and require `origin/main` to be an ancestor of the admitted SHA.
4. Require the canary process registrations to identify `50151` and `50152`, require both health routes, and run the canary verification commands through `bin/decision-os-verify.mjs`.
5. Resolve the active target set from `/api/federation/nodes` by selecting the local node plus every remote node with at least one persisted project manifest. Record zero-project identities separately.
6. Require every active target online and require its delivery preflight to report delivery protocol `1`, supervised-exit adoption, enough free space, no staged application-repository paths, no active Git operation, and a repository origin fingerprint matching the coordinator.
7. Request convergence reconciliation on every target, then require zero runtime-dirty entities, zero pending delivery IDs, zero content queue depth, zero unavailable content resources, and converged relay entries for every locally owned project.
8. Create an isolated integration worktree from exact `origin/main`. Merge the admitted `dev` SHA with `--no-ff` and a commit message containing `WHAT:` and `WHY:`. Do not use the dirty primary checkout.
9. Run the complete admitted verification against the merge candidate. Re-fetch `origin/main` immediately before push and reject when it differs from `previousMainSha`.
10. Push the generated merge commit to `refs/heads/main` without force and record the resulting `mainSha`.
11. Ask every target node to prepare the exact `mainSha` as an immutable detached release worktree, install locked dependencies, validate the launcher, and return its previous active release SHA. No node pointer changes in this phase.
12. Read the current production relay deployment as JSON. Upload the release worktree's relay with Wrangler `4.111.0`, `--strict`, a release-SHA tag, and a redacted message. Resolve the uploaded Cloudflare version ID through JSON `versions list`.
13. Deploy the uploaded relay version at `100%` with `versions deploy <version-id>@100% --yes`.
14. Require public relay `/health` to return HTTP `200`, the expected task-state protocol, schema, baseline epoch, and the promoted `mainSha`.
15. Activate remote nodes one at a time. After each supervised exit, poll through the coordinator until the node returns online with a new process start identity, `releaseSha === mainSha`, HTTP-ready health, restored catalog, and connected federation phase.
16. Activate the coordinator node last. The external CLI polls the original server URL until it reports a new process start identity and the promoted SHA.
17. Re-run complete convergence checks from every active target. Record unrelated active incidents but fail only when a delivery dependency is paused, a server-fatal scope is active, release identity differs, or required convergence is absent.
18. Mark `complete` only after main, relay, every target node, restart identity, health, and convergence evidence agree.

## H. Rollback And Partial-Failure Containment

1. A failure before relay traffic deployment leaves all runtimes unchanged. Preserve the uploaded relay version and mark the run `paused`.
2. A failure after relay deployment and before node activation redeploys the captured previous relay version at `100%`.
3. A failure during rolling node activation stops further activation, switches every already-activated node back to its recorded immutable previous release pointer in reverse activation order, restarts and verifies each restored node, then redeploys the previous relay version.
4. **Do not rewind published `main`.** Runtime rollback changes only the relay deployment and immutable node release pointers. The next corrective delivery advances `main` with a new reviewed commit.
5. An unreachable node during compensation leaves the run `compensation-failed`, records the exact node and last confirmed release, and keeps every other node's outcome intact.
6. Retry uses the existing delivery ID. Every phase first reads current Git, Cloudflare, node, process, and convergence state; it never trusts the last request acknowledgement as final state.
7. A lost response during restart is resolved by polling node release SHA and process start identity before issuing another activation.
8. Every remote request has a finite timeout and cancellation signal through the existing bounded federation request transport.
9. Every node failure records a delivery-scoped runtime incident through `createRuntimeIncidentLedger()`. The coordinator run remains readable even when a node server falls back to launcher-emergency mode.
10. MultiTerm continues to own workstation exponential restart backoff, bounded logs, restart-circuit incidents, and explicit incident resolution after a stable restart.
