## A. Corrected Requirement

1. **Connection-time synchronization:** A federation catalog change triggers automatic exchange. Every node materializes complete skill packages first, then saved pipeline definitions.
2. **Canonical local cache:** Peer skills are stored under the receiving server's `.skills` directory. Peer pipelines are merged into the receiving server's `.decision-os/codex-pipelines.json`.
3. **Consumer impact:** Skills, Pipelines, and Process Card read these local stores. Opening a library never initiates remote project fan-out.
4. **Offline retention:** Materialized files remain available after the source node disconnects.
5. **Manual recovery:** The Skills and Pipelines modals expose `Resynchronize`, which explicitly runs the same skills-first reconciliation and refreshes the local catalog after completion.
