## A. Finding

1. **The linked Codex execution was running, not queued.** Execution `codex-execution-1784539328795-2f5ced83` started at `2026-07-20T09:22:08.996Z`, emitted its first turn at `2026-07-20T09:22:24.663Z`, and finished at `2026-07-20T09:23:21.423Z`.
2. **The bug is in Control Room classification.** A master task enters `Exec` only when `runtimeStatus()` produces an execution observation. An active card lease alone does not produce that observation.
3. **The first unsafe transition is `pending` to `running`.** `buildProjectSlice()` includes only `pending` records from `codex-process-queue.json`. After `markCodexProcessQueueItemRunning()` changes the record to `running`, `runtimeStatus()` requires a matching live process from the server runtime. Without that volatile match it returns `unknown`.
4. **`unknown` demotes the task to Queue.** `taskFrom()` maps a `todo` card with no execution observation to `task-waiting`, even when `codexActiveRunId` and `codexActiveExecutionId` still identify an active execution.
5. **This creates two competing lifecycle truths.** The card/run surface can report an admitted execution while the Control Room independently reports waiting because it reconstructs column state from a narrower observation set.

## C. Product Contract Gap

1. **Current behavior:** the task column is derived from a projection-time observation that can become `unknown` between durable queue admission and live runtime recognition.
2. **Expected behavior:** every admitted non-terminal execution keeps its master task in `Exec` for the complete execution lease, including the scheduler transition from `pending` to `running`.
3. **Acceptance signal:** the linked master task never appears in Queue while its exact `runId` and `executionId` remain non-terminal, and pending, process-started, turn-started, terminal, and reload transitions produce one continuous column history.
4. **Missing technical specification:** one authoritative non-terminal execution state must govern the card control, run status, and Control Room column projection.
5. **Missing regression coverage:** no end-to-end lifecycle test observes the same master task through admission, scheduler claim, child attachment, first turn, settlement, and fresh Control Room reads.
