## A. Scope

1. **Objective:** Persist the final queue order without blocking the optimistic visual result on server synchronization.
2. **Files:** Update `frontend-mobile/src/mobile.js`, supporting control-room helpers, and focused tests under `frontend-mobile/test/`.

---

## B. Requirements

1. **Immediate commit:** On drop, normalize ranks in the in-memory queue and render the final state before awaiting network requests.
2. **Success path:** Persist every changed task Markdown body through `patch-card` and retain the optimistic state without a full control-room reload.
3. **Failure path:** If any mutation fails, reload server-confirmed documents, rebuild the Control Room, render the confirmed order, and surface the request error.
4. **Concurrency:** Prevent an older persistence completion from replacing a newer optimistic reorder.
5. **Rank contract:** Keep `Queue rank` values contiguous from `1` within the reordered visible queue and preserve unrelated Markdown content.

---

## C. Acceptance Criteria

1. **Latency:** The final queue order is visible before the first rank request resolves.
2. **Durability:** Successful requests persist the exact optimistic ordering.
3. **Reconciliation:** A rejected request restores the server-confirmed ordering without stale in-memory ranks.
4. **Coverage:** Automated tests verify optimistic timing, success, rejection, stale completion protection, and rank normalization.
