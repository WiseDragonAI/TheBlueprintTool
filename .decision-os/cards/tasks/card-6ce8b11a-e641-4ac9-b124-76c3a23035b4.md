Ledger: Specs

## A. Product Contract

1. **Goal:** every application button executes the transition owned by its current route, layer, component, and asynchronous request context.
2. **Affected workflow:** opening a master task, entering a relationship-backed subtask, using `Back`, traversing project, ledger, zone, card, thread, processing, pipeline, picker, and modal surfaces.
3. **Affected actor:** the operator navigating and mutating Decision OS state.
4. **Verified current behavior:** a subtask card assigns `.back-to-zone-button` the literal destination `zone`; clicking it builds `zonePath(state.activeLedgerId, state.activeZoneId)`, which returns to the zone canvas instead of the parent master task.
5. **Expected behavior:** a relationship-backed subtask returns to its parent master-task card; every other button resolves its command from one explicit owner and preserves route, layer, pending-request, and persistence boundaries.
6. **Acceptance signal:** the served application passes exhaustive command-ownership checks and browser transitions for every Back, Close, navigation, mutation, selection, media, thread, voice, Codex, and form control.

---

## B. Codebase Evidence

1. **Task ancestry is available but one-directional in presentation:** `parseMasterTaskMarkdown` in `frontend/src/app/responsive/control-room.js` reads canonical `subtask` relationships only when the rendered card is the relationship source; child cards receive no parent identity.
2. **The faulty transition is literal UI state:** `renderCard` in `frontend/src/app/responsive/application.js` writes `backButton.dataset.destination = parsedTask.masterTask ? 'control-room' : 'zone'`; the click listener supports only those two values.
3. **Route ownership already has an immutable base:** `frontend/src/app/responsive/navigation-ownership.js` captures route snapshots for deferred work, but Back controls do not consume a comparable resolved transition.
4. **Button ownership is fragmented:** canvas commands use `handleActionClick`, responsive shell controls use direct listeners in `application.js`, responsive Codex controls use direct listeners in `codex.js`, and responsive thread controls use a separate delegated dispatcher in `thread.js`.
5. **Inventory size:** `frontend/index.html` contains `90` static buttons; production source contains `62` `createElement('button')` construction sites across `25` files.
6. **Existing coverage gap:** `tests/browser/control-room/the-column-scroll-position-survives-refresh-and-navigation.spec.ts` verifies master-task Back to Control Room; no browser test exercises subtask Back to its relationship-backed parent.

---

## C. Ownership Gaps

1. **Navigation ownership gap:** the card route and relationship graph own the parent destination, while a mutable DOM `dataset` currently owns it.
2. **Layer ownership gap:** page Back, modal Back, modal Close, thread Close, and browser-history dismissal use separate state transitions without one executable transition contract.
3. **Command ownership gap:** the same command families, including voice and thread actions, are dispatched through multiple registries and local listeners.
4. **Acceptance gap:** source inspection can identify bindings but cannot prove click, keyboard, browser-history, pending-request, success, rejection, and reload behavior.
5. **Linked specifications:** no existing code-linked specification ID defines app-wide button ownership; the operator request supplies the missing product contract for this task.
