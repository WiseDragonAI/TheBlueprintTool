## A. Required Result

1. **Pipeline 1 — Context Analysis:** `Spec clarification` → `Linked specs analysis` → `Memory review` → `Codebase analysis`, then operator `Questions`.
2. **Pipeline 2 — Solution Design:** `Tasks` → `Maximum architecture` → `Hackish baseline` → `Over-engineering review` → `Problem and solution explanation`, then operator decision.
3. **Pipeline 3 — Implementation Delivery:** `Execution` → `Check and commit` → `Report`, then operator `QA`.
4. **Pipeline 4 — Lessons:** `Lessons` after QA acceptance.
5. **Removed stages:** no `Specification review` and no `Plan review`.

---

## B. Completion Signals

1. **Question boundary:** Pipeline 1 completes all analysis before emitting questions and stops while awaiting answers.
2. **Input boundary:** Pipeline 2 receives the analyzed context plus persisted answers; Pipeline 3 receives the accepted problem-and-solution revision.
3. **Reject paths:** solution-revision feedback restarts Pipeline 2; failed QA restarts Pipeline 1.
4. **No automatic closure:** no pipeline or gate marks the master task done.
