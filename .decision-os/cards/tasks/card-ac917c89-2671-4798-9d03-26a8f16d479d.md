## C. Verified Security Controls

1. **Transport and access:** The public Worker endpoint uses HTTPS. Production returned `401` for missing credentials and `401` for an invalid credential; authenticated health and reads returned `200`.
2. **Secret storage:** The client credential is a `64`-character bearer value stored in `$HOME/.decision-os/.settings.json` with mode `0600`. The repository settings file contains no memory credential.
3. **Leak check:** The exact credential appears in no current tracked file and was not found in Git patch history. `wrangler.toml`, cards, and documentation contain no credential value.
4. **Worker boundary:** Every route is authenticated before D1 access. The D1 database is accessed through the Worker binding, SQL values are parameter-bound, reads are capped at `100`, and responses carry `cache-control: no-store`.
5. **Write surface:** The service exposes authenticated upsert only. It has no delete endpoint. Type, tag, and subtag values must be lowercase slugs.
6. **Regression evidence:** The focused Worker tests pass for unauthenticated rejection, authenticated health, parameter binding, read bounds, type normalization, and upsert behavior.

## D. Security Verdict and Gaps

1. **Verdict:** The current deployment has a sound baseline for a small trusted operator group, but it is not fully hardened for broader multi-user access.
2. **Authorization gap:** One shared bearer credential grants complete read and write access to every project record. The service has no per-client identity, read/write separation, revocation scope, or write attribution.
3. **Abuse controls:** The Worker has no application-level request rate limit and no explicit maximum sizes for title, body, source, or the POST body.
4. **Error exposure:** Caught runtime and D1 error messages are returned to authenticated clients as HTTP `400`, which can disclose implementation details.
5. **Control-plane blocker:** Cloudflare account policy, secret inventory, access roles, audit retention, and recovery configuration could not be inspected because non-interactive Wrangler has no `CLOUDFLARE_API_TOKEN` in this environment.
6. **Recommended hardening:** Replace the shared credential with individually attributable client credentials, enforce separate read and write permissions, add request and field limits, add rate limiting, return generic server errors, record write actor metadata, and rotate the existing shared credential after migration.
