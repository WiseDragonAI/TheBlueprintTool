#master-task

Ledger: Specs

## A. Scope

1. **Objective:** Extend `complete-master-task` so a successful completion creates one Git commit containing the ledger projection, master-task card, canonical subtask cards, and master-task thread.
2. **Asset boundary:** Keep image assets excluded through the repository `.gitignore` rules for `.decision-os/**/*.png`, `.jpg`, `.jpeg`, `.gif`, and `.webp`.
3. **Run-log boundary:** Do not add Codex run logs; `.decision-os/runs/` is already ignored.

---

## B. Contract

1. **Atomic result:** Return success only after the completion state is persisted and the scoped Git commit succeeds.
2. **Scoped commit:** Stage and commit only the active ledger JSON, master-task card, canonical subtask card files, and master-task thread file.
3. **Dirty-worktree safety:** Preserve unrelated tracked and untracked files and exclude images from the commit.
4. **Failure behavior:** Restore the touched Decision OS files and in-memory ledger state when Git staging or commit creation fails.

---

## C. Acceptance Criteria

1. **Commit coverage:** A completion integration test proves the new commit contains the ledger, master card, subtask cards, and thread.
2. **Exclusions:** The same test proves image files and unrelated dirty files are absent from the commit.
3. **Lifecycle:** Existing master completion status and Markdown tests continue to pass.
4. **Repository:** The focused implementation is committed in an isolated worktree, merged into the primary checkout with a merge commit, and the temporary worktree and feature branch are removed.
