## A. Corrected Objective

1. **List row:** Render the skill name as a larger colored title, the description beneath it, and skill tags in a bottom-left label row.
2. **Metadata removal:** Do not render project ownership, `server`, `plugin`, `workspace`, or a favorite badge inside a skill row.
3. **Detail view:** Treat skill detail as an exclusive modal view that hides tabs, search, project filters, tag filters, clear action, result count, and the library list.
4. **Tag editing:** Let the operator edit persistent skill tags from detail and use those tags for row labels and filters.

---

## B. Root Cause

1. **Rendered row:** The former shared renderer placed `Uncategorized` inside `.skill-result-header` beside the skill name, then appended project labels, source `server`, and `Favorite` inside `.codex-list-labels`.
2. **Computed presentation:** The selected skill name rendered at `13px` in the muted text color; the category shared the title row instead of the lower-left label position.
3. **Detail transition:** The former click handler hid only `.process-library`; `.codex-library-controls` and `.codex-tabs` remained visible.
4. **First incorrect transition:** The shared row contract mixed category, ownership, source, and favorite metadata; mobile detail code had no library/detail view state.
5. **Persistence gap:** The former category helper derived one label from a hard-coded name map, so no API or stored skill record accepted operator-edited tags.

---

## C. Implemented Correction

1. **Shared row:** Desktop and mobile now consume one renderer containing only the colored skill title, description, and bottom tag row.
2. **Shared tags:** Stored tags override the inferred fallback; a common color helper supplies known and deterministic custom-tag colors to filters and row labels.
3. **Exclusive detail state:** `setMobileCodexView` owns the responsive library/detail transition and restores the complete library state on Back.
4. **Tag editor:** Global skill detail accepts comma-separated tags, saves them optimistically across the owning project records, and reloads server state after a rejected request.
5. **Persistence:** Skill-library records normalize and return `tags`; metadata-only PUT accepts `favorite` and `tags` without rewriting protected skill Markdown.
6. **Delivery:** Feature commit `023e6ff` is integrated into `main` by merge commit `c6edddf`.
