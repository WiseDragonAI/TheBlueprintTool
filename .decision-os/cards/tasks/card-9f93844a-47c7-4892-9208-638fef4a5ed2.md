## A. Scope

1. **Objective:** Trace Pink from the Termux service supervisor through backend root resolution, project discovery, and client rendering.
2. **Reopened:** The first finding described the immediate environment value but did not identify the invalid server and CLI coupling.

---

## B. Runtime Evidence

1. **Service contract:** `/data/data/com.termux/files/usr/var/service/decision-os/run` changes directory to `/data/data/com.termux/files/home`, sets `PORT=50150`, sets the `frontend-mobile` root, and does not set `DECISION_OS_ROOT`.
2. **Supervisor contamination:** The live `runsvdir`, `runsv decision-os`, launcher, and backend processes inherit `DECISION_OS_ROOT=/data/data/com.termux/files/home/decision-os/.decision-os`.
3. **Backend consumption:** `resolve-decision-os-root.ts` gives `process.env.DECISION_OS_ROOT` precedence over the launch cwd. `create-http-server.ts` derives both `masterDecisionOsRoot` and `masterRoot` from that result.
4. **Observed result:** The live backend cwd is `/data/data/com.termux/files/home`, yet `GET /decision-os/projects` catalogs only descendants of `/data/data/com.termux/files/home/decision-os`.
5. **Pink validity:** `/data/data/com.termux/files/home/health/pink/.decision-os/state.json` exists and declares ledger `tasks`.

---

## C. Legacy Selector Audit

1. **Runtime code:** No `decision-os-project` cookie read, `x-decision-os-project` header read, cookie write, or project-selection storage path exists in backend, frontend, or `frontend-mobile` runtime source.
2. **Residual test references:** `backend/test/server/decision-os-project-catalog.integration.test.ts` still sends the legacy cookie and header. `frontend-mobile/test/mobile-control-room.test.mjs` still names the legacy header in a negative source assertion.
3. **Finding:** The legacy mechanism is absent at runtime but is not completely absent from the codebase.
4. **Canonical scope:** Project-owned routes use `/p/:projectId/...`; the project catalog endpoint is global.

---

## D. Root Contract Audit

1. **Correct CLI use:** `decision-os-codex-runtime.ts` injects a project-specific `DECISION_OS_ROOT` into each Codex child, and `ledger-cli` uses it to enforce ledger scope.
2. **Incorrect server use:** `resolve-decision-os-root.ts` also consumes the same environment variable during backend startup, allowing a project-scoped agent environment to redefine the server catalog.
3. **Documentation residue:** `MIGRATE_RUNBOOK.md` and `documentation/specs.json` still describe `DECISION_OS_ROOT` as a server startup override.
4. **Test gap:** No launcher or server-root regression proves that inherited project-scoping variables are discarded and that the launch cwd owns the catalog.

---

## E. Root Cause

1. **First incorrect transition:** A project-scoped Codex environment reached the Termux service supervisor.
2. **Structural defect:** The backend interpreted the inherited CLI scope as its server storage and catalog scope.
3. **Impact:** The valid home launch cwd was ignored, so Pink fell outside traversal even though the Termux service script was correct.

---

## F. Acceptance Criteria

1. **Cause identified:** The server and CLI share one environment variable with incompatible scope.
2. **Legacy audit complete:** Runtime references are absent and two test-only references are identified.
3. **Correction selected:** Server startup must derive its master scope from the launch cwd; `DECISION_OS_ROOT` must remain confined to Codex child and `ledger-cli` scope.
