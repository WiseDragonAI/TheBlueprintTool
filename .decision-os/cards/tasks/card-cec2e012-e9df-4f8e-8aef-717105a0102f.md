## A. Gate Objective

1. Implement the approved groups within their declared file, symbol, behavior, and state boundaries.
2. Preserve unrelated dirty work and protected staged hunks.

---

## B. Execution Rules

1. Use the repository's established architecture, helpers, fixtures, migration machinery, and verification lease.
2. Add change-specific regressions at the first affected boundary.
3. Build a repeatable repository tool only when the migration exposes a proven recurring operation.
4. Record deviations in the owning task before expanding scope.

---

## C. Exit Condition

1. Each implementation group has a reviewable diff, mapped acceptance checks, and no unresolved contract deviation.
2. End with `READY_FOR_FULL_TEST_ATTRIBUTION` after all groups are integrated into one candidate change set.
