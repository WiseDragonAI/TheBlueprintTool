The canonical boundary is documented in `documentation/documentation/architecture/codex-content-authoring.md:1-11`, `:88-120`, and `:141-151`.

## C. Findings

1. **Implemented foundation — CodeMirror is the document authority.** `mountCodeMirrorFileEditor()` creates `EditorState` from the Markdown bytes, installs `basicSetup`, `markdown()`, keymaps, read-only and wrapping compartments, listens only to `docChanged`, and reads the save value from `view.state.doc` at `frontend/src/runtime/codex/component/codemirror-file-editor.ts:213-247` and `:270-305`. No Git state currently enters the editor.
2. **Implemented foundation — session persistence is structurally correct.** Saving reconfigures the existing view instead of remounting it; authoritative reload replaces the document with `Transaction.addToHistory.of(false)`; preview has an independent lifetime; final disposal destroys both views and removes global listeners at `frontend/src/runtime/codex/component/codemirror-file-editor.ts:273-313` and `frontend/src/runtime/content-authoring/controller/text-file-editor-session.ts:125-197`.
3. **Available extension contract — CodeMirror can carry mapped metadata without changing Markdown bytes.** The published `@codemirror/state@6.7.1/dist/index.d.ts` contract exposes `ChangeDesc.mapPos()` and `touchesRange()` at `:170-244`, `StateField` at `:653-675`, mapped `StateEffect` values at `:783-840`, and immutable `RangeSet.map()` at `:1564-1649`. The published `@codemirror/view@6.43.6/dist/index.d.ts` contract exposes metadata-bearing `Decoration` marks, widgets, replacements, and line decorations at `:263-356`, plugin update and destruction at `:430-521`, viewport-bounded rendering at `:733-765`, and the `decorations` plus `atomicRanges` facets at `:1307-1352`.
4. **Gap — Decision OS does not export the required extension symbols.** `frontend/scripts/codemirror-vendor-entry.ts:5-11` exports `Compartment`, `EditorState`, `Transaction`, `EditorView`, highlighting, Markdown, commands, and search. Repository search found no use of `StateField`, `StateEffect`, `Decoration`, `ViewPlugin`, `WidgetType`, `RangeSet`, `MapMode`, and `syntaxTree`. The checked-in browser bundle therefore cannot yet host a Git metadata field and decoration layer through the supported application boundary.
5. **Available extension contract — Markdown syntax remains incremental.** `@codemirror/lang-markdown@6.5.1` returns `LanguageSupport`, defaults to CommonMark, supports parser extensions, and installs Markdown editing key bindings in its published `dist/index.d.ts:55-116`. `@codemirror/language@6.12.4/dist/index.d.ts:175-204` exposes the current incremental syntax tree plus bounded parse completion. This is a suitable syntax source for an editable semantic layer; it does not itself implement Decision OS directives.
6. **Reusable Pierre data — the patch model is usable independently of Pierre DOM.** `parsePatchFiles()` returns `ParsedPatch[]` through `frontend/node_modules/@pierre/diffs/dist/utils/parsePatchFiles.d.ts:4-23`. `FileDiffMetadata` is a JSON-compatible file model with `hunks`, old and new line arrays, object identities, change type, and partial/full status at `frontend/node_modules/@pierre/diffs/dist/types.d.ts:194-264`. Each `Hunk` records old and new starts, counts, line indexes, grouped context/change content, render counts, and end-of-file state at `:104-188`. These records can feed an application-owned range adapter.
7. **Pierre constraint — patch parsing produces partial file arrays for the current API input.** `processFile()` sets `isPartial` when full old and new files are absent, and then fills `deletionLines` plus `additionLines` only from patch content at `frontend/node_modules/@pierre/diffs/dist/utils/parsePatchFiles.js:48-84` and `:136-235`. The type contract explicitly states that hunk expansion is unavailable in this state at `frontend/node_modules/@pierre/diffs/dist/types.d.ts:233-257`. Hunk coordinates remain available, but the adapter must validate them against the exact committed Markdown before creating editor ranges.
8. **Reusable Pierre derivation — full old/new bytes produce complete metadata.** The published `parseDiffFromFile()` calls `diff@9.0.0` `createTwoFilesPatch()` and then `processFile()` with both complete files at `frontend/node_modules/@pierre/diffs/dist/utils/parseDiffFromFile.js:1-24`. This produces full `FileDiffMetadata`, but `frontend/scripts/pierre-vendor-entry.ts:5-9` does not export that function.
9. **Drift — current rendering requests expansion from partial data.** `renderSkillRevisionDiff()` parses a bounded-context patch and sets `expandUnchanged: true` at `frontend/src/runtime/codex/component/render-skill-revision-diff.ts:27-47`, while the Pierre type contract states that hunk expansion is unavailable when `isPartial` is true at `frontend/node_modules/@pierre/diffs/dist/types.d.ts:233-257`.
10. **Renderer-owned Pierre behavior is not reusable inside the editable surface.** `FileDiff` owns `InteractionManager`, `ResizeManager`, `ScrollSyncManager`, selection, annotations, Shiki-rendered code nodes, render ranges, virtual buffers, and cleanup in `frontend/node_modules/@pierre/diffs/dist/components/FileDiff.d.ts:57-146`. Mounting that renderer inside CodeMirror would create a second selection, syntax, scrolling, virtualization, event, and lifecycle owner.
11. **Current integration confirms the renderer separation.** `renderSkillRevisionDiff()` creates a dedicated Pierre custom element, constructs `FileDiff`, renders the parsed patch, and returns `renderer.cleanUp()` at `frontend/src/runtime/codex/component/render-skill-revision-diff.ts:25-58`. 14. **Omission — Decision OS directives are outside the CodeMirror Markdown grammar.** The canonical parser recognizes `::html`, `::git-diff`, and `::questions` as application blocks at `frontend/src/runtime/ledger/helper/parse-ledger-card-markdown.ts:50-81` and `:164-189`. `mountCodeMirrorFileEditor()` calls plain `cm.markdown()` with no parser extension at `frontend/src/runtime/codex/component/codemirror-file-editor.ts:235-245`. ## D. Remediation Paths

1. **Keep one document owner.** `EditorState.doc` must remain the exact current Markdown submitted to the existing optimistic save contract. Deleted Git text must never be inserted into document bytes. Git identity, hunks, ranges, stale state, and presentation must live in an editor extension.
2. **Expand the deterministic browser bundles narrowly.** Export `StateField`, `StateEffect`, `RangeSet`, `MapMode`, `Decoration`, `ViewPlugin`, `WidgetType`, and `syntaxTree` from the CodeMirror vendor entry. Export `parseDiffFromFile` through a dedicated pinned Worker entry. Keep `FileDiff` in the existing standalone Pierre bundle.
3. **Define one identity-bound diff snapshot.** Extend backend revision detail with the complete immediately older `baseMarkdown`, then carry `commit`, `olderCommit`, `contentRevision`, `baseMarkdown`, and current `markdown` into the active editor. Admit the snapshot only when current bytes and revision identity match the loaded authoritative editor state.
4. **Compute complete diff metadata away from input handling.** Run `parseDiffFromFile(baseMarkdown, draftMarkdown)` in a deadline-bound Worker after a bounded debounce. Terminate stale work when the session generation changes, and reject results whose generation and base identity no longer match.
5. **Normalize Pierre data into application state.** Convert validated `FileDiffMetadata` into records containing hunk identity, change kind, old text, new-document line coordinates, and current-document offsets. Pierre records are transient inputs; application-owned mapped ranges are the editor state.
6. **Store mapped metadata in CodeMirror state.** Add a `StateField` updated by identity-bound `StateEffect` values. Map unaffected ranges through `transaction.changes`; use `touchesRange()` to mark a hunk stale while a newer Worker result is pending. Install snapshot refresh effects with `Transaction.addToHistory.of(false)` so Git refresh does not become an authored undo event.
7. **Render additions and removals through CodeMirror decorations.** Use line and mark decorations for added bytes already present in `EditorState.doc`. Use non-editable `WidgetType` block decorations for removed bytes anchored at the corresponding new-document position. Give every change a sign, text label, line identity, and accessible group name. Keep the CodeMirror selection and scroller authoritative.
8. **Make canonical Markdown source-positioned before claiming rendered parity.** Extend `parseLedgerCardMarkdown()` and `parseLedgerMarkdownInline()` to return exact source spans, then compare those spans with the CodeMirror syntax tree. Reuse canonical rendering rules as presentation inputs; do not mount the complete detached `renderLedgerCardMarkdown()` tree inside the contenteditable surface.
9. **Own refresh and disposal in the existing session.** Load the validated baseline when the authoritative editor opens and after a successful save. Cancel the debounce, terminate the Worker, invalidate its generation, and let `EditorView.destroy()` dispose plugins and widgets. Retain Pierre `FileDiff` only for existing standalone history and Git-review surfaces.
10. **Prove the hardest boundary before production planning.** The proof must render one multi-hunk Markdown revision in one editable CodeMirror view, edit before a hunk, edit inside a hunk, undo, redo, search, select across an added region, navigate across a deletion widget, reject a stale Worker result, refresh to a new commit, and dispose the session. It must measure mapping correctness, DOM order, focus, scroll continuity, accessible names, stale-hunk behavior, and bounded rendering at the maximum admitted document size.
11. **Add change-specific evidence.** Unit tests must cover full-content diff normalization, line-to-offset conversion, range mapping, overlap invalidation, effect identity, stale-generation rejection, deadline cleanup, and final disposal. Browser evidence must cover the complete served interaction and persistence moments required by the Decision OS interaction contract. Static checks alone cannot establish feasibility acceptance.

## E. Operator Decision Summary

1. **Feasibility verdict for this stage:** the unified model is technically feasible through CodeMirror’s supported state, range, decoration, widget, and plugin contracts. No package-license blocker exists.
2. **Selected ownership boundary:** CodeMirror must own the editable document and every browser interaction. Pierre’s `ParsedPatch`, `FileDiffMetadata`, and `Hunk` records are reusable inputs; Pierre’s `FileDiff` renderer is rejected for the unified surface because it owns a separate shadow DOM and interaction lifecycle.
3. **Primary prerequisite:** add a complete immutable baseline, deadline-bound diff derivation, identity-bound diff state, and exact source spans for canonical Decision OS Markdown. Without these contracts, additions and removals cannot remain correct across edits and rendered semantics cannot track cursor positions.
4. **Uncertainty boundary:** the evidence supports editable source Markdown with semantic Git decorations. It does not establish that the complete canonical rendered-Markdown DOM can inhabit CodeMirror while retaining editability; that claim requires the source-positioned proof.
5. **Proof boundary:** validate mapped additions, anchored removals, overlap invalidation, undo and redo, accessibility, performance, refresh, stale-generation rejection, and disposal inside one CodeMirror view before producing the final implementation-ready change list.
6. **Current completion boundary:** this result establishes the source-level architecture trace and one remediation path. The unified interaction model, conflict policy, proof verdict, and symbol-level production change list remain for the later research subtasks. No production feature code was changed.
