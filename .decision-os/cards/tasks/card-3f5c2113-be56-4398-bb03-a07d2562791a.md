#master-task

Ledger: Specs

## A. Scope

1. **Objective:** In the mobile `New task` project picker, show only each project's `name`.
2. **Affected surface:** The project-selection modal shown before a new task intake is created.

---

## B. Contract

1. **Visible label:** Render `project.name` as the sole text inside each `.new-task-project-option`.
2. **Hidden path:** Do not render `project.relativePath`, including `.` and nested paths such as `health/pink`.
3. **Grid layout:** Render `.new-task-project-list` as two equal-width columns.
4. **Compact buttons:** Use a `52px` minimum button height with reduced padding.
5. **Centered labels:** Center each project name horizontally and vertically.
6. **Preserved behavior:** Keep project color, focus, selection, intake creation, loading state, cancellation, and error handling unchanged.

---

## C. Acceptance Criteria

1. **Examples:** The supplied catalog renders `home`, `decision-os`, and `pink` without secondary path lines.
2. **Columns:** The project options occupy two equal-width columns with the third option on the next row.
3. **Alignment:** Every project name is centered on both axes inside its button.
4. **Regression:** The mobile control-room test rejects `project.relativePath` and requires the compact two-column CSS contract.
5. **Verification:** All `frontend-mobile` tests pass and the operator-facing route serves the changed mobile asset.
