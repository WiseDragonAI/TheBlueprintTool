## A. Cloudflare Security Boundary

1. **Public surface:** Expose only the WebSocket upgrade, pairing administration, health, and revocation routes. Browsers continue to access their loopback Decision OS server.
2. **Pairing:** Protect administration with a Worker secret; redeeming a single-use pairing token creates a node identity and random credential whose hash is persisted.
3. **Socket binding:** Authenticate before accepting the socket, bind it to federation and node identity, and ignore requester identity carried in later payloads.
4. **Owner authority:** The owner independently validates membership, owner identity, local project existence, route allowlist, method, and body size before loopback dispatch.

---

## B. Authorization Matrix

1. **Catalog read:** Any active node in the paired single-operator federation may read the authorized union of manifests.
2. **Project operations:** Each active paired node may access every published peer project through the owner route allowlist.
3. **Git status:** An active paired node may request the structured status of a published online project. The owner fixes the working directory and command shape.
4. **Administration:** A node cannot remotely restart a server, change settings, create a project, alter project metadata, invoke debug routes, or address a project owned by another socket.
5. **Rejections:** Use stable authentication, authorization, unknown-owner, duplicate-request, body-limit, capacity, timeout, and owner-offline results.

---

## C. Git Execution Boundary

1. **No command RPC:** Reject caller-provided binaries, arguments, shell strings, filesystem paths, environment variables, Git configuration, credentials, hooks, aliases, and URL rewrites.
2. **Read helper:** The fixed status helper executes only the pinned status command in the resolved owner project root, disables optional locks, uses a bounded timeout, and returns a parsed schema.
3. **Write workflow:** Git writes occur only inside an explicitly launched owner-side Codex task. The requester sends task intent through existing card and thread content, not an executable command frame.
4. **Credential authority:** SSH keys, tokens, credential helpers, signing keys, and remote configuration remain on the owner node. Cloudflare and the peer never receive them.
5. **Audit:** Record the status request and Codex run identity. The existing Codex transcript provides command-level evidence for owner-side reconciliation.

---

## D. Storage and Product Boundary

1. **Durable Object storage:** Persist membership, credential hashes, revocation, manifests, and bounded terminal request metadata. Do not persist Git snapshots, paths, repository URLs, diffs, file names, credentials, prompts, or streamed bodies.
2. **Deployment secret:** Inject the administrator credential with Wrangler secret management and never place it in source, ledger state, URLs, logs, or committed development variables.
3. **Product boundary:** Multi-user identity, per-user project ACLs, unattended synchronization policy, and automated conflict resolution require separate authorization before the federation expands beyond one paired operator.
