## A. Canonical Backlog State

1. **Goal:** Replace the newly added `delayed` vocabulary with canonical `backlog` across storage, server, desktop, mobile, projections, routes, styles, and tests.
2. **Persisted status:** Change ledger card status `delayed` to `backlog` while retaining `todo` and `done`.
3. **Derived status:** Change `task-delayed` to `task-backlog` and expose the Control Room collection as `backlog`.
4. **Markdown boundary:** Keep master-task lifecycle labels limited to `#task-waiting`, `#task-active`, and `#task-complete`; backlog membership comes only from ledger status.
5. **Meaning:** A backlog task is parked outside execution capacity until an operator restores it to `todo`.

---

## B. Surface Rename

1. **Backend:** Update mutation validation, types, errors, projection schemas, workflow helpers, active-run guards, and integration fixtures.
2. **Desktop:** Update persisted and visible work-status types, card datasets, controls, labels, CSS selectors, low-detail indicators, and tests.
3. **Mobile:** Update Control Room tabs, query routing, empty state, age label, task detail actions, navigation, filters, counts, and tests.
4. **Projection:** Emit `status: "task-backlog"`, group the task only in `backlog`, and exclude it from queue and active capacity.
5. **Compatibility route:** Canonicalize an incoming `?tab=delayed` link to `?tab=backlog` once, then render and persist only the new vocabulary.

---

## C. Data Migration

1. **Catalog scope:** Visit every ledger declared by every discovered project's `.decision-os/state.json`.
2. **Atomic rewrite:** Change each persisted card status from `delayed` to `backlog` through temporary-file rename while preserving every unrelated field and file.
3. **Version marker:** Record migration completion per project so restart does not rewrite unchanged ledgers.
4. **Failure:** Stop publication for the affected project, retain original files, report the exact ledger, and retry only after the migration error is resolved.
5. **Current baseline:** The two projects verified below the launch root contain no persisted `status: "delayed"`; regression fixtures still cover existing installations.
6. **Cache boundary:** Increment projection schema and projector versions so snapshots containing `delayed` vocabulary cannot warm-start.

---

## D. Workflow Contract

1. **Park:** `todo -> backlog` preserves queue rank, waiting timestamp, active timestamp, Markdown, geometry, thread history, and subtask state.
2. **Restore:** `backlog -> todo` returns the task to queue ordering from its preserved rank and waiting timestamp.
3. **Active guard:** Reject parking when the owning skill and pipeline lifecycle is pending with a queue position, processing, running, and in progress.
4. **Complete:** Master-task completion writes `done` and `#task-complete` from both queue and backlog after existing completion gates pass.
5. **Delete:** Task deletion removes the backlog projection through the same ledger revision and invalidation path.
6. **Invalidation:** Park, restore, complete, and delete rebuild the owning project slice and then advance the global aggregate revision.

---

## E. Verification Gates

1. **Vocabulary:** Production code, routes, copy, styles, payloads, and tests use `backlog`; `delayed` remains only in the migration matcher, migration fixture, and legacy route canonicalizer.
2. **Migration:** A fixture with `status: "delayed"` becomes `status: "backlog"` while every unrelated value remains unchanged.
3. **Projection:** Backlog tasks appear only in `backlog`, do not consume queue and active counts, and remain isolated by project.
4. **Round trip:** Parked tasks survive fresh reload, projection rebuild, server restart, project rediscovery, restore, completion, and deletion.
5. **Guard:** Queued and running skill and pipeline cases reject parking without changing persisted state and UI state.
6. **Routes:** Direct `?tab=backlog` works and legacy `?tab=delayed` canonicalizes to it.
7. **Payload:** Backlog support does not violate the Control Room `250 KB` limit.
8. **Target behavior:** Verify park, rejection, restore, complete, delete, counts, empty state, and direct route on the served mobile surface.
