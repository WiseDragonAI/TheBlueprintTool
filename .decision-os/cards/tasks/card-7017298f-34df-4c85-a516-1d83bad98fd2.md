## A. Objective

1. Guarantee one pending or running execution lease per card across every launch kind.

---

## B. Verified Evidence

1. Thread start can supersede a recoverable session.
2. Two pending continuations can enqueue twice.
3. Admission paths persist partial state before queue and manifest success.

---

## C. Implementation Contract

1. Serialize admission by project, ledger, and card.
2. Allocate execution identity before the first mutation and persist it in card, queue, runtime seed, response, markers, and events.
3. Return the existing pending or running lease and queue position for repeated admission.
4. Route start on a retained thread session through continuation; deletion makes the next start allocate a new thread run.
5. Roll back created cards, relationships, manifest, queue item, and ownership pointers when admission fails.

---

## D. Acceptance Tests

1. Two concurrent continuations return one execution and one queue item.
2. Competing thread and pipeline launches return one lease.
3. Failure after each write leaves no orphan.
4. Repeated start retains the session and creates one continuation.
