## A. Architecture Decision

1. **Selected model:** one long-lived CodeMirror `EditorView` owns the editable Markdown document, every transaction, history, selection, search, scrolling, focus, rendering lifecycle, and final disposal. Git additions and removals enter that view only as CodeMirror state plus decorations.
2. **Pierre boundary:** reuse `parseDiffFromFile()`, `FileDiffMetadata`, and `Hunk` as transient derivation inputs. Keep Pierre `FileDiff` outside the unified surface because its shadow DOM, selection, scrolling, syntax rendering, event managers, and cleanup would create a second interaction owner.
3. **Document invariant:** `EditorState.doc` contains the exact current Markdown submitted through the existing optimistic save contract. Deleted Git text never enters document bytes.
4. **Rendered-parity boundary:** the model supports editable source Markdown, source-positioned canonical semantics, added-text decorations, and deletion widgets. It does not establish complete parity with the detached `renderLedgerCardMarkdown()` DOM.
5. **Production boundary:** this result defines architecture and proof facts only. No production implementation is authorized.

## B. Stack and Root Blocks

1. **Frontend Root Block:** frameworkless TypeScript browser modules using the pinned CodeMirror `6` packages, browser DOM APIs, one dedicated Web Worker for complete Pierre diff derivation, and Playwright for served interaction proof. It owns the unified editor, CodeMirror extensions, semantic presentation, diff presentation, session Runtime State, accessibility, cancellation, and browser cleanup.
2. **Backend Root Block:** TypeScript server runtime owning authoritative authored Markdown, revision identity, complete baseline bytes, optimistic save validation, Git commit refresh, and conflict responses. The authored revision detail boundary must return the complete immediately older Markdown with the current revision identity.
3. **Worker ownership:** the diff Worker is part of the Frontend Root Block. It has a separate execution lifetime but no independent project, package, durable data, deployment target, or Root Block directory.
4. **QA ownership:** unit coverage remains inside each Root Block. The complete browser interaction proof belongs to the cross-root integration boundary.
5. **Repository shape:** preserve the current monorepo with `frontend/` and `backend/` as separate Root Block directories. This analysis does not authorize a framework change, repository relocation, or Git submodule conversion.

## C. Authority and Runtime State

1. **Document bytes:** `EditorState.doc` is the sole editable-byte authority.
2. **Authoritative revision snapshot:** the backend supplies `contentRevision`, `commit`, `olderCommit`, `baseMarkdown`, and accepted current Markdown as one immutable identity-bound snapshot.
3. **Diff identity:** a diff result is identified by session generation, `contentRevision`, `commit`, `olderCommit`, exact `baseMarkdown`, and the exact requested `EditorState.doc` bytes. Equality of every member is required for admission.
4. **Hunk identity:** each normalized hunk is identified by its admitted diff identity and Pierre `Hunk` order. It carries change kind, old text, new-document line coordinates, current-document offsets, deletion anchor, and stale status.
5. **Diff Runtime State:** one CodeMirror `StateField` owns the admitted snapshot, application-normalized hunks, mapped ranges, stale flags, and the `RangeSet` from which decorations are derived.
6. **Syntax Runtime State:** CodeMirror's incremental Markdown `syntaxTree()` owns base Markdown syntax. Source-positioned canonical parser records own Decision OS block plus inline semantics for the exact same document bytes.
7. **Session Runtime State:** the existing text editor session owns `PersistenceState`, `RefreshState`, active request cancellation, debounce, Worker identity, finite deadline, conflict status, and disposal.
8. **Presentation Runtime State:** `Decoration.mark()` plus line decorations present additions already in the document. `WidgetType` block decorations present removed text at deletion anchors. Pierre DOM never enters the editor.

## D. Transaction and Range Mapping Policy

1. **Snapshot installation:** an admitted Worker result replaces the complete diff `StateField` atomically through an identity-bound `StateEffect`. Snapshot installation uses `Transaction.addToHistory.of(false)`.
2. **Edit before a hunk:** map each addition range and deletion anchor through `transaction.changes`. Preserve the hunk presentation when `touchesRange()` proves the transaction did not touch its range or anchor. Start a replacement derivation for the new document generation.
3. **Edit inside an addition:** immediately remove every decoration belonging to the touched hunk, mark that hunk stale, preserve unaffected hunks, and start a replacement derivation.
4. **Edit at a deletion anchor:** treat insertion exactly at the zero-length anchor plus deletion across the anchor as touching the hunk. Immediately withdraw that hunk's deletion widget and start replacement derivation.
5. **Deletion-anchor placement:** place removed text immediately before the first surviving new-document byte represented by the hunk. Place an end-of-file deletion at `EditorState.doc.length`. Map only untouched anchors.
6. **Worker replacement:** replace all mapped interim hunks with the newly normalized complete diff only when the returned identity matches the active identity tuple.
7. **Undo and redo:** CodeMirror history owns authored undo and redo. Every undo plus redo transaction follows the same mapping and touched-hunk policy as direct input. Diff snapshot effects never become authored history events.
8. **Selection and clipboard:** CodeMirror selection ranges remain document offsets. Added text selects and copies as current Markdown. Deleted widget text remains review information and never becomes authored clipboard content.
9. **Search:** CodeMirror search reads current document bytes only. Deleted widget text is not a search match because it is absent from the authored document.
10. **Scrolling and focus:** the existing CodeMirror scroller and focus target remain exclusive. Diff effects do not remount the view, replace its scroller, move focus, or create an independent selection.

## E. Persistence, Reload, and Conflict Policy

1. **Initial load:** admit a baseline only after current Markdown bytes, `contentRevision`, `commit`, and `olderCommit` match the authoritative editor load. Start one complete diff derivation from `baseMarkdown` to `EditorState.doc`.
2. **Successful save:** require the save response to return the accepted bytes and new immutable revision snapshot. If accepted bytes differ from submitted bytes, classify settlement as a conflict instead of silently rewriting the editor. Preserve CodeMirror document history, install the returned baseline through a non-history effect, and derive the new diff.
3. **Rejected save:** preserve the local draft, selection, scroll, focus, and authored history. Set `PersistenceState` to the returned failure and keep the existing accepted snapshot available for retry.
4. **Rejected save with newer authority:** record the server-confirmed identity plus bytes in conflict state, cancel active derivation, withdraw Git presentation whose baseline is no longer authoritative, and retain the local draft for explicit recovery. Do not overwrite either byte sequence.
5. **Authoritative reload:** invalidate the session generation, cancel pending work, replace the complete CodeMirror state without remounting the `EditorView`, clear pre-reload undo plus redo history, clamp selection into the new document, and restore valid scroll plus focus.
6. **Commit refresh while clean:** when `EditorState.doc` equals the accepted current Markdown, install the refreshed authoritative snapshot through the authoritative reload boundary and derive its diff.
7. **Commit refresh while dirty:** enter explicit conflict state, preserve the draft, cancel the old derivation, withdraw outdated Git presentation, and require the existing recovery flow before a new baseline is admitted.
8. **Persistence proof:** a successful save must survive a fresh authoritative reload. A rejected save must show server-confirmed conflict identity without losing the recoverable local draft.

## F. Canonical Markdown Semantic Boundary

1. **Required parser contract:** extend `LedgerMarkdownBlock` and `LedgerMarkdownInline` with exact absolute `from` plus `to` source offsets captured before trimming, escaped-newline normalization, and block transformation.
2. **Base Markdown:** reconcile canonical spans with CodeMirror's current incremental Markdown syntax tree for the same exact document bytes.
3. **Decision OS directives:** keep `::html`, `::git-diff`, and `::questions` semantics in the canonical parser. Publish their source-positioned records to CodeMirror only when parser document identity still equals `EditorState.doc`.
4. **Presentation:** derive CodeMirror marks, line attributes, and bounded widgets from semantic spans. Keep the literal Markdown editable and keep the canonical parser as the semantic authority.
5. **Rejected integration:** do not mount `renderLedgerCardMarkdown()` inside CodeMirror. Its detached DOM lacks transaction-mapped source positions and would compete with the editor's DOM ownership.
6. **Claim limit:** complete canonical rendered-Markdown parity remains unproven until every canonical block, inline construct, media surface, embed, review widget, questionnaire, and application directive has source-positioned served proof inside the editable surface.

## G. Accessibility and Interaction Contract

1. **Change identity:** added content uses insertion semantics plus a visible `+` label. Removed content uses deletion semantics plus a visible `−` label. Blue and red styling supplements text and semantics; color is never the sole distinction.
2. **DOM order:** every deletion widget appears at its mapped document anchor in the same CodeMirror content flow. Screen-reader traversal encounters the deletion label plus removed text at that source position.
3. **Widget behavior:** deletion widgets are non-editable `WidgetType` blocks. They expose a stable accessible group name, do not accept authored input, and do not create a second tab stop.
4. **Keyboard behavior:** existing CodeMirror cursor movement remains authoritative. A point deletion widget contributes no false document offset. Existing change navigation may target its anchor without moving selection into deleted text.
5. **Focus behavior:** save, Worker settlement, snapshot replacement, timeout, stale-result rejection, and conflict transition preserve the CodeMirror focus owner.
6. **Reference evidence:** CodeMirror's official decoration guidance requires editor-owned decorations for added DOM, maps decoration ranges through transactions, and requires layout-changing block widgets to come from direct decorations: [CodeMirror Decoration Example](https://codemirror.net/examples/decoration/). WAI-ARIA requires roles, properties, states, accessible names, and keyboard semantics for dynamic application content: [WAI-ARIA Overview](https://www.w3.org/WAI/standards-guidelines/aria/).

## H. Performance, Cancellation, Stale Results, and Disposal

1. **Computation boundary:** run complete `parseDiffFromFile(baseMarkdown, draftMarkdown)` derivation in the dedicated Worker after a bounded debounce. Input handling performs no synchronous full-file diff.
2. **Single-flight rule:** allow at most one active Worker generation per editor session. Starting a newer generation terminates the older Worker before replacement.
3. **Finite deadline:** every Worker generation has a session-owned timer. Deadline settlement terminates the Worker immediately, clears the timer plus message listeners, records diff-unavailable timeout state, and leaves editing operational.
4. **Stale-generation rejection:** a Worker message may mutate no state until session generation, authoritative identity, baseline bytes, and requested draft bytes match the active values. A mismatch is discarded without dispatch.
5. **Viewport rule:** use direct state decorations for deletion block widgets because they alter vertical layout. Restrict non-layout semantic work to CodeMirror visible ranges when the complete state is not required.
6. **Maximum admitted document:** prove the model at the existing `1,000,000`-byte authored-card ceiling. Diff computation must create no input-thread long task of `50 ms` attributable to diff derivation.
7. **Timeout evidence:** `Worker.terminate()` stops a Worker immediately, so timeout and supersession use termination rather than cooperative completion: [MDN Worker termination](https://developer.mozilla.org/en-US/docs/Web/API/Worker/terminate).
8. **Session teardown:** cancel debounce, invalidate generation, terminate the active Worker, clear every timer plus listener, abort persistence and refresh requests, dispose CodeMirror plugins plus widgets through `EditorView.destroy()`, and settle the session once.
