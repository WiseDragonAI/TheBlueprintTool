## A. Scope

1. Expose Cloudflare connection state, priority-state queue depth, local and peer event summaries, missing events, pending acknowledgements, state-snapshot manifests, bootstrap progress, replay tails, content queue depth, content availability, retries, invalidated checkpoints, conflicts, and projection fingerprints.
2. Build a deterministic multi-node harness with controllable delivery order, disconnection, Worker restart, Durable Object eviction, duplication, corruption, blank-node bootstrap, snapshot age, saturated content, content failure, and Git availability.
3. Attribute failures to the first broken boundary: issuer, event store, reducer, state snapshot, projection API, connector, Cloudflare relay, acknowledgement, reconciliation, content manifest, content queue, content install, or archive.

---

## B. Acceptance

1. The harness covers parallel mutation, live delivery, arbitrary arrival, late events, disconnect, reconnect, Cloudflare lifecycle, blank-node bootstrap, backpressure, and events emitted during catch-up.
2. A year-scale history restores from a verified state snapshot plus bounded tail and matches a clean genesis replay.
3. Late events inside covered history invalidate the correct checkpoints and converge on every node.
4. A stalled maximum-size content transfer cannot delay priority task events, acknowledgements, state snapshot bootstrap, or convergence.
5. Content hash reuse, corruption, interruption, retry, offline cache reads, and atomic replacement pass.
6. Static and integration checks prove the legacy task replica path is gone and all task readers use the projection API.
7. Projection rebuild, snapshot fallback, content isolation, Git independence, and one-time migration pass together.
