## A. Repository Intent

1. **Decision OS presents project-owned ledgers, cards, threads, skills, pipelines, and execution state through stable resource identities.** The server resolves those identities to filesystem resources; browser requests do not receive authority to select arbitrary filesystem paths.
2. **Markdown is durable content, not a static public asset.** Card Markdown is referenced by `card.comment.contentFile`, thread Markdown is referenced by `ledger.threadFiles[threadId]`, and authored skill Markdown is resolved from the scanned skill identity.
3. **Mutations stay with the owning model.** Cards use scoped ledger mutations, threads use note mutations, and skills use the skill-library save contract.

---

## B. Current Iteration Intent

1. **A browser visit to an authorized Markdown path must open the corresponding Decision OS authoring surface.** The motivating URL is an absolute same-origin path such as `/home/jbb/dev/EditorBP/decision-os/.decision-os/cards/tasks/<card>.md`.
2. **The change must reuse the pinned CodeMirror 6 adapter.** File authorization, owner lookup, optimistic concurrency, Git persistence, federation, and navigation remain outside `mountCodeMirrorFileEditor`.
3. **The direct URL is a compatibility input, not the durable browser identity.** After resolution, the address bar must contain a canonical project/resource route without an absolute filesystem path.

## D. Existing Ownership And Containment

1. **Projects are server-registered resources.** `DecisionOsProject` contains `id`, `root`, `decisionOsRoot`, and the project ledger registry in `backend/src/business/server/helper/project-catalog.ts:13-24`.
2. `projectFromRegisteredPath()` resolves registered roots below the catalog root, rejects lexical escapes, validates stable project identity, and marks unavailable projects explicitly in `project-catalog.ts:74-131`.
3. Normal discovery skips `.git`, `.decision-os`, `.worktrees`, and `node_modules` in `project-catalog.ts:33` and `:187-234`. A production server therefore does not silently authorize Markdown in an isolated development worktree.
4. **Card paths are already constrained.** `resolveCardContentFile()` accepts only `.md`, strips the `.decision-os/` prefix, resolves below the selected `decisionOsRoot`, and rejects escapes in `backend/src/business/ledger/helper/card-content-file.ts:23-25` and `:40-45`.
5. **Thread paths use the same boundary.** `resolveThreadContentFile()` accepts only `.md` below the selected `decisionOsRoot` in `backend/src/business/ledger/helper/thread-content-file.ts:26-29` and `:85-90`.
6. **Skill writes have the strongest existing authored-file check.** `verifiedEditableFile()` rejects protected sources, missing roots, file symlinks, root escapes, and `.system` content in `backend/src/business/codex/helper/codex-skill-library.ts:146-172`.
7. Skill create and save requests explicitly reject `skillFile`, `filePath`, and `path` fields in `codex-skill-library.ts:426-433` and `:566-580`.
8. **The direct-path resolver must preserve these invariants.** It may compare a requested path to server-resolved authorized files, but it must not convert the path into general file authority.

## F. Existing Editor And Save Behavior

1. **The reusable boundary is `mountCodeMirrorFileEditor()`.** It owns Markdown mode, line wrapping, undo, redo, search, dirty state, focus, teardown, and a read-only flag in `frontend/src/runtime/codex/component/codemirror-file-editor.ts:52-166`.
2. The adapter already documents future authorized thread-attachment reuse and explicitly rejects client-selected paths as an application design in `codemirror-file-editor.ts:1-9`.
3. **The current modal is skill-specific.** `renderSkillLibraryEditorModal()` owns skill metadata, tags, defaults, creation, save, history, and revision selection in `frontend/src/runtime/codex/effect/render-skill-library-editor-modal.ts:373-710`.
4. `openSkillLibraryEditor()` accepts `skillName` and optional `projectId`; it never accepts a path in `render-skill-library-editor-modal.ts:505-520`.
5. Skill saves submit a loaded SHA-256 `revision`; the backend returns `409` when current bytes differ in `codex-skill-library.ts:628-653`.
6. Each admitted skill-content save uses `commitSkillFileRevision()`. Its isolated index protects unrelated staged state, verifies one repository, advances `HEAD` with compare-and-swap, and exposes file-scoped history in `backend/src/business/codex/helper/skill-git-revisions.ts:44-225`.
7. **Card editing does not use CodeMirror.** `beginLedgerCardDescriptionEdit()` replaces rendered Markdown with a plain `<textarea>` and saves on blur through `patch-card` in `frontend/src/runtime/card/effect/begin-ledger-card-edit.ts:53-99`.
8. `patch-card` atomically replaces the card Markdown and records the changed content resource in `backend/src/business/ledger/helper/apply-ledger-mutation.ts:275-350` and `card-content-file.ts:58-77`.
9. **Card editing currently has no file-content expected revision and no Git-history API.** Ledger response revisions and Epoch-4 task clocks reconcile document state, but the card editor cannot detect an external byte change between load and save.
10. **Raw thread-file replacement is not an admitted mutation.** Thread Markdown contains role headings and `decision-os:note` metadata. The supported writes are `append-note`, `update-note`, `delete-note`, and `restore-note`; `writeThreadNotesFile()` regenerates canonical Markdown from the note model in `thread-content-file.ts:92-150` and `:172-187`.

## G. Findings

1. **Gap — direct Markdown identity resolution is absent.** The server has all required ownership data but performs no reverse lookup from a requested Markdown path to a registered card, thread, skill, or pipeline prompt.
2. **Gap — the responsive router has no route-driven editor state.** `/skills` opens the library, while card routes render card detail; neither reads an editor query on initial load, refresh, or `popstate`.
3. **Gap — card authoring still bypasses CodeMirror.** The plain textarea is inconsistent with the requested editor toolbox and full-screen authoring surface.
4. **Gap — card optimistic concurrency is incomplete.** The mutation is identity-scoped but not byte-revision-scoped.
5. **Gap — card Git revision history is absent.** The existing Git helper is technically file-oriented despite its skill-specific name, but no card controller exposes history or revision content.
6. **Omission — navigation-away protection covers modal close only.** `hasUnsavedChanges()` guards explicit skill modal close, while `navigate()`, `popstate`, reload, and tab close do not consult editor dirty state.
7. **Omission — a stable zone-independent card route is absent.** The existing card route requires `zoneId`, although a content file owns a card identity and the card can move between zones.
8. **Drift — the unmatched fallback reports success for an invalid UI route.** Returning HTTP `200` JSON hides the missing route and produces the operator-visible failure.
9. **Safety finding — raw thread editing cannot reuse card save semantics.** A whole-file write could create, delete, duplicate, or rewrite note identities without the causal task-state changes required by Epoch 4.
10. **Safety finding — a generic file API is unnecessary and unsafe.** Existing owner APIs can read and save every currently admitted editable content kind. A path-based `GET` or `PUT` would weaken the established identity boundary.

## H. Selected Route Contract

1. **Canonical card editor route:** `/p/:projectId/ledgers/:ledgerId/cards/:cardId?editor=markdown`.
2. This route is intentionally zone-independent. The server already serves every project-scoped `/ledgers` route through the SPA, and the client can load the ledger navigation projection plus exact card projection without depending on current canvas geometry.
3. **Canonical skill editor route:** `/skills?editor=skill&name=:skillName&projectId=:projectId`. Omit `projectId` for server and user skills. The server still derives source, path, editability, and read-only reason.
4. **Canonical pipeline-prompt editor route:** `/skills?editor=skill&name=:promptName`. Pipeline prompts remain part of the authoring catalog and reuse the existing identity API.
5. **Canonical thread destination:** `/p/:projectId/ledgers/:ledgerId/cards/:cardId?thread=open`. It opens the card's existing thread panel and note composer. It does not expose raw thread Markdown for replacement.
6. **Compatibility input:** a `GET` or `HEAD` whose decoded pathname is an absolute `.md` path, plus a project-scoped `/.decision-os/...md` path, enters one server-side `resolveMarkdownEditorTarget()` boundary before asset serving and before the generic fallback.
7. The resolver enumerates available registered projects, resolves each candidate through its current owner helper, and requires an **exact canonical-file match**:
   1. card: current `comment.contentFile`;
   2. thread: current `threadFiles[threadId]`;
   3. skill: current scanned skill identity;
   4. pipeline prompt: current registered prompt identity.
8. The resolver rejects non-Markdown files, nonexistent files, unavailable projects, lexical escapes, realpath escapes, symlinked authored files, unregistered files, and ambiguous identities.
9. **A successful compatibility resolution returns `302` with `Cache-Control: no-store` and the canonical identity route.** It never returns file bytes and never places the absolute path in client state.
10. **An unresolved direct Markdown path returns `404` JSON** with stable code `markdown_editor_target_not_found`. An ambiguous identity returns `409` with `markdown_editor_target_ambiguous`. A protected skill still redirects and opens read-only because editability is decided by the skill detail response.
11. **Card editor load:** the client loads `GET /p/:projectId/api/ledgers/:ledgerId/cards/:cardId`, then mounts `mountCodeMirrorFileEditor()` in the existing `80vw` by `95vh` modal geometry.
12. **Card editor save:** the client sends `patch-card` to `/p/:projectId/decision-os/:ledgerId` with `cardPatch.id`, `description`, and `expectedContentRevision`. The server checks the current SHA-256 before writing and returns `409` plus the current revision when stale.
13. **Card revision routes:** `GET /p/:projectId/api/ledgers/:ledgerId/cards/:cardId/revisions` and `GET /p/:projectId/api/ledgers/:ledgerId/cards/:cardId/revisions/:commit`. Both resolve the card file from current ownership, admit only commits present in that file history, and return no filesystem path.
14. Card revisions reuse the isolated-index Git implementation after renaming the helper and DTOs from skill-specific names to authored-file names. A Git failure preserves the already-authored bytes and content head, reports no new Git revision, and returns an explicit recovery result consistent with current skill save behavior.
15. **Skill editor load, save, and history remain on the current skill-library APIs.** The route only opens `openSkillLibraryEditor()` after application initialization.
16. **Thread history and persistence remain note-owned.** The direct thread destination uses the parsed thread projection and existing note controls. Raw CodeMirror thread replacement is outside this implementation because no safe whole-thread mutation exists.

## I. Browser Navigation Contract

1. Initial page load and refresh parse `editor`, `name`, `projectId`, and `thread` after project catalog initialization.
2. Opening an editor inside the app pushes one history entry containing the canonical editor query and an `editorLayer` marker.
3. Browser Back requests modal close. If the editor is dirty, the same discard confirmation used by explicit close runs before navigation commits.
4. Explicit close uses `history.back()` only when the current history entry owns `editorLayer`; a direct deep-link load removes the editor query with `replaceState` and leaves the canonical card or `/skills` surface visible.
5. `beforeunload` is installed only while the CodeMirror document is dirty and is removed after save, discard, or editor teardown.
6. Reloading a canonical editor URL re-resolves content from the owner API, reopens the modal, and does not reuse an in-memory draft.
7. The current Markdown link renderer may keep `target="_blank"`; the new tab receives the compatibility redirect and lands on the canonical editor route.

## L. Operator Decision Summary

1. **Selected implementation:** resolve direct Markdown paths once on the server, redirect to path-free owner routes, and reuse owner-specific APIs with the existing CodeMirror adapter.
2. **No generic file endpoint is added.** Browser paths never become read/write authority.
3. **Card Markdown becomes the second editable owner supported by the reusable editor.** It receives expected-content revision checks and file-scoped Git history.
4. **Thread Markdown remains note-owned.** A direct thread path opens the canonical thread UI; raw whole-thread editing is rejected until a causal whole-thread mutation contract exists.
