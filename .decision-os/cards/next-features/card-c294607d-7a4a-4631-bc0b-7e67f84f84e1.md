## Desmos-style formula graphs

Add a graph block renderer so cards and thread notes can display mathematical formulas as interactive 2D plots, similar to the Desmos graphing surface.

### Proposed syntax

````markdown
```graph
y = sin(x)
y = x^2 - 3
```
````

The parser should treat `graph` as a fenced markdown block and render it as a contained graph widget instead of a code block. The widget must stay inside the card/thread width, support horizontal and vertical pan/zoom inside its own surface, and never steal canvas pan/zoom unless the pointer starts inside the graph.

### Repository choice

Primary recommendation: [JSXGraph](https://github.com/jsxgraph/jsxgraph)

Use JSXGraph for the plotting surface because it is plain JavaScript, not React-bound, and fits decision-os's current vanilla TypeScript runtime. It can support simple function plots now and leaves room for later Desmos-like behavior such as points, sliders, intersections, geometry, and multiple series.

Companion recommendation: [MathLive](https://github.com/arnog/mathlive)

Use MathLive only when editable formula input is needed. For the first render-only milestone, fenced `graph` blocks can accept text formulas directly and skip the full math editor.

### Alternatives checked

| Repo | Use if | Tradeoff |
| --- | --- | --- |
| [mauriciopoppe/function-plot](https://github.com/mauriciopoppe/function-plot) | We want the fastest MVP for `y=f(x)` only. | Narrower surface; less future room for interactive geometry and sliders. |
| [josdejong/mathjs](https://github.com/josdejong/mathjs) | We need a mature parser/evaluator behind graph expressions. | Not a graph renderer. Use as an evaluator companion, not the visual layer. |
| [silentmatt/expr-eval](https://github.com/silentmatt/expr-eval) | We want a small expression evaluator for simple `x` formulas. | Less comprehensive than mathjs. |
| [stevenpetryk/mafs](https://github.com/stevenpetryk/mafs) | We move this surface into React. | Attractive graph components, but React dependency does not match the current decision-os frontend. |
| Desmos API | We accept an external vendor embed. | Best visual benchmark, but not an open-source GitHub dependency and not ideal for workspace-local behavior. |

### Implementation path

1. Extend the shared markdown parser with a `graph` fenced block kind.
2. Add `render-ledger-card-graph.ts` beside the existing markdown table/code/media renderers.
3. Render a fixed-aspect graph shell with `resize: horizontal`, `max-width: 100%`, and wheel/pointer containment rules matching card image and editor behavior.
4. Start with `y = expression` lines, multiple series, auto colors from `--card-zone-color`, and default viewport `{ x: [-10, 10], y: [-10, 10] }`.
5. Add an error state for invalid formulas that preserves the original formula text and does not break the rest of the markdown body.
6. Add tests for parser block recognition, DOM rendering, containment CSS, invalid formula fallback, and thread-note parity.

### Acceptance

- A card description containing a `graph` fenced block renders an interactive plot instead of raw code.
- Thread notes render the same graph block through the shared markdown renderer.
- Wide or zoomed graph content cannot expand the card, thread panel, or canvas layout.
- Canvas pan/zoom still works outside the graph, while graph pan/zoom is contained when the pointer starts inside the graph.
- Invalid formulas show a compact error inside the graph shell and keep the source formula visible for editing.
