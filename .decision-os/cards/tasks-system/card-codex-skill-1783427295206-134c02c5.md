## Opening Snapshot

**What is this for?**

- **Decision workspace:** `decision-os` turns local ledger files into a browser canvas for specs, data, performance evidence, and task planning.
- **Operator control:** the operator uses cards, zones, groups, relationships, threads, and voice notes to shape decisions.
- **Agent handoff:** agents read operator notes, change repo or ledger state, and answer in durable `# AGENT` sections.
- **Local-first runtime:** current use is a local workspace session, not a hosted or multi-tenant deployment.

Source refs: A.1, A.3, A.4, B.9, D.2.

## What Can The Operator Do?

**Canvas work**

- **Review ledgers:** open `specs`, `data`, `performances`, or `tasks-system` as route-addressed canvas tabs.
- **Shape objects:** create, move, select, resize, copy, paste, group, relate, and delete cards, zones, and groups.
- **Edit card content:** work with Markdown, fields, descriptions, media, HTML embeds, and report mockup cards.
- **Navigate spatially:** pan, zoom, use low-detail rendering, and drill into detailed card views when needed.

Source refs: A.2, A.3, C.1, C.2, C.3.

**Thread and note work**

- **Open threads:** use the right-side thread inspector to attach decisions, requests, progress, and recovery context.
- **Write notes:** keep operator input under `# OPERATOR` and expect agent replies under `# AGENT`.
- **Record voice:** use voice capture when text entry is slower, with upload, transcription, failure, and retry states.
- **Attach files:** paste or upload images and files into thread workflows when evidence is visual or document-based.

Source refs: A.2, A.3, C.3, C.5, C.8.

## How Is The Workspace Organized?

**Ledger map**

- **`specs`:** behavior contracts for boot, navigation, canvas, cards, threads, voice, groups, media, CLI, and architecture.
- **`data`:** base classes and relationships that support the product model.
- **`performances`:** evidence about frame production, drag, pan, card detail, overlays, and relationship routing.
- **`tasks-system`:** next-feature planning for watcher loops, summaries, queues, report UX, and goal-object UX.

Source refs: A.1, A.6, B.8, C.6.

**Object model**

- **Cards:** the primary units for specs, reports, task notes, fields, Markdown, and media.
- **Zones and groups:** spatial organization tools for clustering related work on the canvas.
- **Relationships:** visible links between cards or objects that explain dependency or association.
- **Threads:** durable conversation surfaces that carry operator-agent handoffs.

Source refs: A.2, B.4, C.2, C.6.

## Which Controls Matter?

**Keyboard contract**

- **`A`:** open or focus the thread panel.
- **`X`:** start or stop the active voice note.
- **`Esc`:** cancel voice capture, close thread tooling, or clear selection.
- **`Del`:** confirm deletion for the selected card, zone, or group.
- **`Ctrl+C` / `Ctrl+V` / `Ctrl+D`:** copy, paste, and resize selected objects to content or contained cards.

Source refs: C.7.

**Entry points**

- **Routes:** use `/`, `/ledgers`, and `/<ledgerId>` to enter the product.
- **Browser UI:** use the tab registry, toolbox, canvas controls, thread buttons, upload controls, and voice controls.
- **CLI:** use `ledger-cli` for maintenance and queue-facing workflows.
- **Server:** run local operator sessions through the detached `decision-os` launcher and verify the HTTP route.

Source refs: B.3, B.9, C.4.

## How Does Work Move Through The System?

**Human-agent loop**

- **Operator starts:** decisions, approvals, notes, and workspace intent originate with the operator.
- **Agent acts:** agents read threads, edit repo or ledger state, and answer in `# AGENT` sections.
- **Watcher concept:** unanswered notes are intended to be monitored by a watcher workflow.
- **Durable recovery:** threads also carry status, progress, lock, queue, and recovery information today.

Source refs: A.4, A.7, C.5.

**Media and report loop**

- **Images:** card image assets can appear as carousels, with persisted dimensions.
- **HTML reports:** cards can embed HTML assets under allowed card asset paths.
- **Report UX:** report boundaries remain unresolved across card view, ledger type, goal cockpit tab, or embedded reader.
- **Performance guardrail:** rich card surfaces must not break responsive pan, zoom, or drag behavior.

Source refs: A.2, A.7, B.4, C.9.

## What Decisions Remain Open?

**Operator-owned boundaries**

- **Report product shape:** decide whether reports live as cards, ledgers, cockpit tabs, or embedded readers.
- **Work queue model:** decide how threads, watcher loops, task queues, locks, and progress status should separate.
- **Goal-object UX:** decide how goal objects should appear and behave in the next-feature surface.
- **Summary maintenance:** decide how card and zone summaries stay current without overloading thread behavior.
