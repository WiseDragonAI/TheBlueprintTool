## B. Introduced Concepts

1. **Pipeline library:** Saved pipelines reference ordered reusable steps, and every step owns an ordered skill sequence with explicit settings or `Use skill default` inheritance.
2. **Run manifest:** Each launch snapshots resolved model and effort values, output cards, run artifacts, lifecycle timestamps, and terminal state so later default changes cannot rewrite execution history.
3. **Sequential runner:** Every skill runs in an isolated Codex process, downstream skills wait for terminal settlement, and failures or cancellation stop later execution.
4. **Generated execution surface:** Pending, running, completed, failed, and cancelled step cards expose live context, metrics, continuation, cancellation, retry, and restart controls without a page reload.
5. **Safe skill editing:** The backend owns skill path resolution, canonical-root containment, revision validation, Markdown validation, atomic writes, and protected-source enforcement.

## E. Lessons

1. **Runtime imports:** Moving browser-consumed values into `shared/` requires the HTTP server to resolve, contain, transpile, and serve the matching `/shared/*` module URL.
2. **Durable lifecycle:** Persisted run manifests and immutable option snapshots let cancellation, restart, resume, and UI reconstruction work without relying on process-local memory.
3. **Dirty worktrees:** Card-linked task and worker evidence is sufficient to commit a large implementation safely when every staged path and mixed hunk is reviewed against that scope.
4. **Documentation boundary:** Durable iteration evidence includes linked cards, threads, mockup sources, and scoped ledger structure; ignored runtime artifacts and local images remain outside the repository contract.
