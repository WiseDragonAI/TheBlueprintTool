## Goal-Linked Spec Analysis Prompt

```text
Research the context report, base goal, and existing specs to populate:

Goal/spec link: goal need, affected product area, affected workflows, affected
actors or roles, relevant context facts, current behavior, expected behavior,
acceptance signals.

Linked specs: existing specs that support the goal, constrain the goal, block the
goal, conflict with the goal, are adjacent but not goal-critical, or should be
treated as non-goals.

Missing specs: requirements implied by the goal or context but not covered by an
existing spec, missing acceptance signals, missing UX specs, missing technical
specs, missing data specs, missing operational specs.

Spec gaps and risks: contradictions, unknowns, unverified facts, source gaps,
unclear ownership, product-boundary decisions, technical constraints, UX
constraints, data constraints, dependency constraints.

Context boundaries: in scope, out of scope, unverified areas, source gaps,
cross-team dependencies.

Rules: keep it neutral and product-agnostic; use the context report as source
material; use existing spec IDs and titles when available; do not invent specs,
owners, metrics, or requirements; mark missing evidence as unknown or
unverified; do not recommend a path, implementation plan, or approval gate.
```
