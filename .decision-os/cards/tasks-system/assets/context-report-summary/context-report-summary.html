Decision OS Context

Context Summary

Current state, technical frame, UX constraints, and evidence limits.

01

Quick scan

First read

Decision OS is being dogfooded as a local decision workspace. The active surface is the canvas, cards, zones, groups, threads, media, voice notes, CLI tooling, and report/mockup cards.

Tech stack

Node and TypeScript backend through tsx, frameworkless TypeScript frontend, workspace-local .decision-os files as durable state.

Open constraints

Threads are overloaded and the report object boundary is still unresolved. Performance, accessibility, external adoption, and hosted deployment are not proven by this report.

02

Context details

Product shape

  • Surface: ledgers, cards, zones, groups, relationships, card Markdown, media carousels, HTML assets, threads, and voice notes.
  • Workflow: inspect and edit canvas objects, review specs and performance evidence, paste files/images, record voice notes, treat unanswered notes, and review mockups.
  • Active boundary work: watcher loops, summary maintenance, task queues, report UX, and goal-object UX live in tasks-system.

State model

  • Canonical store: the filesystem; the backend hydrates and writes ledger JSON, card Markdown, and thread Markdown.
  • Registry: .decision-os/state.json lists the active ledgers; each ledger JSON owns cards, relationships, viewport, and thread references.
  • Asset rule: live HTML must stay under active card asset paths; images and thread files are served from constrained workspace paths.

Workspace use

  • Main loop: open a ledger route, inspect the canvas, select cards/zones/groups, edit content or geometry, then review the result in card detail.
  • Agent handoff: use threads, pasted files/images, and voice notes to pass work to agents; agent replies return through durable # AGENT notes and card edits.
  • Keyboard contract: A, X, Esc, Del, Ctrl+C, Ctrl+V, and Ctrl+D define the current operator controls.

Proof limits

  • Grounded in: current repo files, active workspace ledgers, docs, source inspection, task cards, performance notes, CLI behavior, and local runtime behavior.
  • Not proven: hosted deployment, multi-tenant permissions, billing, customer analytics, external adoption, assistive technology behavior, and current browser performance.
  • External dependency: optional OpenAI transcription configuration is the only confirmed dependency outside the local repo.
