## A. A. Ownership audit

1. Thread launch persists a queue claim, then Node owns prompt delivery, stdout/stderr transport, JSONL ingestion, retry timing, settlement, queue removal, card cleanup, and notifications.

---

2. Thread recovery can adopt a surviving PID for status polling, but cancellation still requires the lost `ChildProcess` handle.

---

3. Pipeline launch has no durable process identity and startup converts an unowned running skill to failed.

---

4. Global capacity counts `runtime.codexSkillRuns`, so capacity truth is also tied to the server runtime.

---

## B. B. Structural conclusion

1. **Persisting PID metadata did not make execution server-independent.** Direct file descriptors, process-group control, durable lifecycle transitions, and a shared manifest are all required.
