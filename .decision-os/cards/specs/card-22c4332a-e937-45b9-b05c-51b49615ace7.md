## A. Root Cause

1. **Cause:** The continuation request omits the canonical project prefix `/p/ZGVjaXNpb24tb3M`; project routing rejects it before `continueCardSkillRunController` can enqueue the run.
2. **Why Run appears inert:** The frontend consumes the `400` response, returns `false`, and exposes the error only through telemetry.

---

## B. Corrective Action

1. **Request fix:** Route `requestCardSkillRunContinue` through `projectScopedRequestPath`, matching the existing run-status request.
2. **Regression:** Assert that continuation from a canonical `/p/:projectId/...` page posts to `/p/:projectId/api/codex/skills/runs/<run-id>/continue`.
3. **Failure visibility:** Render the backend error beside the Run control so a rejected launch cannot appear inert.
4. **Authorization boundary:** Product code remains unchanged because the operator asked why relaunch fails, not to implement the fix.
