## A. Verified Security Boundary

1. **Current constraint:** The Decision OS server is loopback-only and has no end-user authentication layer. The bounded proof therefore uses one operator federation in which a paired node is the authenticated principal.
2. **No public origin:** Browsers continue to access their local Decision OS server. Only the server's outbound relay connection is internet-facing.
3. **Owner authority:** The relay chooses the connected owner socket, but the owner independently validates federation membership, target owner identity, local project existence, method/path allowlist, and body size before loopback dispatch.

---

## B. Pairing and Credentials

1. **Pairing:** An authenticated relay administrator creates a random single-use token with a `10 min` expiry. Redeeming it creates one `nodeId` and returns a random `256-bit` node credential.
2. **Storage:** Persist the credential in ignored `.decision-os/.federation.json` with file mode `0600`; never place it in a ledger, card, thread, Git commit, URL, or log.
3. **Connection:** Authenticate the node during the TLS-protected WebSocket handshake. Bind the accepted socket to `federationId` and `nodeId`; ignore requester identity supplied inside later payloads.
4. **Revocation:** Relay revocation immediately closes the node socket and prevents reconnect. Node credential rotation invalidates the previous credential.

---

## C. Authorization Matrix

1. **Catalog read:** Any active node in the federation may read the authorized union of manifests.
2. **Project operations:** Any active node in the bounded two-node federation may access every project published by the other node, subject to the route allowlist.
3. **Administration:** No node may remotely restart a server, change server settings, create a project, alter project metadata, invoke debug routes, or address a project owned by a different socket.
4. **Payload enforcement:** Limit JSON/control bodies to `1 MiB`, file and voice uploads to `25 MiB`, individual chunks to `64 KiB`, and active streams to `32` per node.
5. **Rejection contract:** Use stable `401 federation_authentication`, `403 federation_forbidden`, `404 owner_or_project_unknown`, `409 duplicate_request`, `413 federation_body_limit`, and `503 owner_offline` results.

---

## D. Audit

1. **Record:** Persist timestamp, federation, requester node, owner node, global project key, request ID, method, normalized route class, byte counts, duration, status, and terminal reason.
2. **Exclude:** Never record credentials, request bodies, response bodies, uploaded content, card text, thread text, or Codex prompts.
3. **Product boundary:** Multi-user identity and per-user project ACLs require a separate authorization study before any federation wider than the paired single-operator environment.
