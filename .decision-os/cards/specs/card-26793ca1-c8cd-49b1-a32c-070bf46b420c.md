## A. Cloudflare Security Boundary

1. **Public surface:** Expose only the WebSocket upgrade, pairing administration, health, and revocation routes. Browsers continue to access their loopback Decision OS server.
2. **Pairing administration:** Protect the pairing and revocation routes with one random administrator credential stored as a Cloudflare Worker secret. Do not use a committed Wrangler variable for secrets.
3. **Node authentication:** Redeeming a single-use `10 min` pairing token creates a `nodeId` and random `256-bit` credential. Persist only its cryptographic hash and credential version in Durable Object SQLite storage.
4. **Handshake:** Authenticate in the Durable Object before accepting the socket, bind it to `federationId` and `nodeId`, and ignore requester identity carried in subsequent payloads.
5. **Owner authority:** The owner node independently validates federation membership, owner identity, local project existence, route allowlist, and body size before loopback dispatch.

---

## B. Authorization Matrix

1. **Catalog read:** Any active node in the paired federation may read the union of stored manifests.
2. **Project operations:** Each active paired node may access every project published by the other node, subject to the owner route allowlist.
3. **Administration:** A node cannot remotely restart a server, change settings, create a project, alter project metadata, invoke debug routes, or address a project owned by a different socket.
4. **Payload enforcement:** Limit JSON/control bodies to `1 MiB`, file and voice uploads to `25 MiB`, chunks to `64 KiB`, outstanding credit to `1 MiB` per direction, and active streams to `32` per node.
5. **Rejection contract:** Use stable `401 federation_authentication`, `403 federation_forbidden`, `404 owner_or_project_unknown`, `409 duplicate_request`, `413 federation_body_limit`, and `503 owner_offline` results.

---

## C. Storage and Audit

1. **Durable Object storage:** Persist federation membership, credential hashes, revocation, project manifests, and bounded terminal request metadata in SQLite. Do not persist project files, card text, thread text, uploads, voice, Codex prompts, or streamed bodies.
2. **Audit fields:** Record timestamp, federation, requester node, owner node, global project key, request ID, method, normalized route class, byte counts, duration, status, and terminal reason.
3. **Deployment secret:** Declare the administrator secret as required configuration and inject it with Wrangler secret management. Never place it in source, ledger state, URLs, logs, or `.dev.vars` committed to Git.
4. **Product boundary:** Multi-user identity and per-user project ACLs require a separate authorization study before federation expands beyond one paired operator.
