## A. Study Result

1. **Decision OS can present one shared phone–workstation project inventory without synchronizing Git or copying project state.** Each project remains stored and executed on its owner node.
2. **Either device can use the other device's projects as if they were local:** open ledgers, edit cards and threads, upload assets and voice, follow live changes, launch Codex, observe status, and cancel runs.
3. **Authority stays unambiguous:** every remote request is routed to the owner server; its existing project controller reads the files, applies mutations, runs Codex, and publishes events.

---

## B. Smallest Architecture

1. **One lightweight relay:** The phone and workstation each open one authenticated outbound `WSS` connection. The relay forwards bounded HTTP and event streams and holds only node identity, presence, authorization membership, and project manifests.
2. **Reuse the current product:** Decision OS already has stable project IDs, one frontend request-scoping layer, and one backend project-dispatch boundary. Remote projects can reuse `/p/:projectId/...` with an owner-qualified opaque ID; the canvas, cards, threads, uploads, voice, and Codex interfaces remain unchanged.
3. **Expected failure behavior:** Local projects remain fully usable during relay or peer loss. Remote projects stay visible as `Owner offline`, but their content and actions are unavailable because no stale replica is presented as authoritative.

---

## C. Proof Gate

1. **Bounded next step:** Build one relay connecting exactly one phone and one workstation, then prove discovery, ledger mutation, assets, voice, live events, Codex launch and cancellation in both directions.
2. **Unverified until the proof:** Mobile network recovery, ambiguous mutation reconciliation, authorization rejection, event latency, upload throughput, and the defined memory and bandwidth budgets.
3. **Decision required:** Authorize the two-node proof of concept. This study does not authorize product implementation.
