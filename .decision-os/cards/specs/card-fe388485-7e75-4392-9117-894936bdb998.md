## A. Study Result

1. **Decision OS federation can run on Cloudflare without a managed VPS.** One dedicated Worker plus one SQLite Durable Object can connect the phone and workstation while all project files and Codex execution remain on the owning device.
2. **The experience remains symmetric:** either device can discover and operate the other node's projects, and every mutation plus Codex run is routed to the project owner.
3. **DroidFleet confirms the managed Cloudflare operating model, but Bay is not the relay.** Bay proves Wrangler deployment, managed ingress, secrets, durable state, and deployment probes in this workspace; Decision OS still needs a new Durable Object to own both WebSocket connections.

---

## B. Smallest Managed Architecture

1. **Proof services:** Use one Worker entry point and one SQLite Durable Object. The proof needs no Cloudflare Queues, D1 database, R2 bucket, DigitalOcean droplet, GitLab integration, builder orchestration, or scheduled cleanup.
2. **Connection model:** Both Decision OS servers open authenticated outbound `WSS` connections to `workers.dev`. The Durable Object owns membership, manifests, presence, bounded stream routing, and terminal request metadata without persisting project content.
3. **Deployment boundary:** Create a separate Decision OS Worker package. Reuse Bay's Wrangler deployment, secret injection, custom-domain promotion, and post-deploy probe patterns without coupling the relay to Bay's DigitalOcean control plane.

---

## C. Proof Gate

1. **Selected next step:** Build the bounded two-node proof on Cloudflare Workers and Durable Objects.
2. **Required evidence:** Verify credit-based backpressure, reconnect during runtime replacement, Thailand latency, CPU per message, memory, `25 MiB` upload throughput, event latency, cancellation latency, and billed requests.
3. **Decision required:** Authorize the Cloudflare proof. This study does not authorize product implementation.

## D. DroidFleet Comparison

1. **Verified repository:** `/home/jbb/dev/DroidFleet/bay` contains Bay's Go deployment CLI and TypeScript Cloudflare control plane.
2. **Current Bay topology:** `bay/cf-worker/wrangler.toml` binds three priority queues, D1, R2, and a one-minute scheduled trigger. The Worker serves HTTP control routes, dispatches queued jobs, and calls DigitalOcean to manage droplets, builders, snapshots, volume handoff, DNS cutover, and rollback. Bay reduces VPS operations; it does not remove the VPS.
3. **Relay gap:** Repository search found no WebSocket API usage in Bay's Worker or Go control-plane code. The Wrangler migration deletes the former `ScaleRun` Durable Object, so the current Bay runtime supplies no reusable two-socket relay.
4. **Reusable boundary:** Reuse the deployment and security patterns in `bay/internal/services/control_plane_setup*.go`, `bay/cf-worker/src/auth.ts`, and `bay/cf-worker/src/registration/auth.ts`. Build socket ownership, frame routing, flow control, and hibernation as a separate minimal package.
