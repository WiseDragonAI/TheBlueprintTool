## A. Bounded Proof

1. **Topology:** Connect one phone Decision OS server and one workstation Decision OS server to one TLS relay. Use only the two-node, single-operator federation authorization model.
2. **Transport implementation:** Add `ws@8.21.0` with compression disabled, the versioned frame codec, relay routing, node authentication, manifest replacement, heartbeat, admission limits, backpressure, and audit metadata.
3. **Decision OS adapter:** Add owner-qualified project resolution, requester HTTP/SSE bridging, owner allowlist validation, and loopback dispatch through the existing `/p/:localProjectId/...` boundary.
4. **Frontend integration:** Merge catalogs and Control Room projections, preserve `/p/:projectId` navigation, and add owner plus offline indicators without redesigning existing project surfaces.

---

## B. Bidirectional Acceptance

1. **Discovery:** Both interfaces show the union of phone-owned and workstation-owned projects, including duplicate local IDs without collision.
2. **State authority:** From each interface, open a remote ledger, mutate one card, reload, and prove the changed file exists only under the owner project's `.decision-os` root.
3. **Codex authority:** From each interface, launch and cancel a remote Codex run, observe live status, and prove the process PID plus run files exist on the owner node.
4. **Assets and voice:** Upload one image and one voice note to a remote project and prove persistence plus transcription under the owner node.
5. **Live events:** Observe owner-side card, thread, ledger, and Codex changes on the requester without manual reload.

---

## C. Isolation and Recovery Acceptance

1. **Isolation:** Reject an invalid credential, revoked node, wrong owner key, unknown project, forbidden global route, `1 MiB`-plus control body, `25 MiB`-plus upload, and conflicting duplicate request ID.
2. **Failure:** Disconnect requester, owner, and relay separately during finite requests, SSE, upload, mutation, and Codex execution; verify the failure contract and no orphan relay stream.
3. **Recovery:** Prove local projects remain usable, remote projects become explicitly offline, both catalogs converge after reconnect, SSE resubscribes, and ambiguous mutations refresh before retry.
4. **Resources:** Capture every measurement and threshold defined in the resource card.

---

## D. Operator Gate

1. **Study result:** The architecture is feasible without Git synchronization, project replicas, inbound device ports, or duplicated project controllers.
2. **Next decision:** Authorize the bounded two-node proof. Product implementation remains blocked until that proof validates mobile network behavior, failure recovery, authorization, and resource budgets.
