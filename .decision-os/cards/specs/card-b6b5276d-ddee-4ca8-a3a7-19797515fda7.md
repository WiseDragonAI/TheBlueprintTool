## A. Cloudflare Proof Deployment

1. **Topology:** Connect one phone Decision OS server and one workstation Decision OS server to one Worker endpoint on `workers.dev` and one SQLite-backed Durable Object named for the federation.
2. **Deployment source:** Add a dedicated Decision OS Worker package with TypeScript, tests, Wrangler configuration, one Durable Object binding, one SQLite class migration, and required secret declarations. Do not place the relay inside DroidFleet Bay and do not provision DigitalOcean infrastructure.
3. **Transport:** Add the versioned frame codec, hibernatable socket routing, authentication, manifest replacement, protocol ping, admission limits, explicit credit flow control, and audit metadata.
4. **Decision OS adapter:** Add owner-qualified project resolution, requester HTTP/SSE bridging, owner allowlist validation, and loopback dispatch through `/p/:localProjectId/...`.
5. **Frontend:** Merge catalogs and Control Room projections, preserve `/p/:projectId` navigation, and add owner plus offline indicators without redesigning existing project surfaces.

---

## B. Bidirectional Acceptance

1. **Discovery:** Both interfaces show the union of phone-owned and workstation-owned projects, including duplicate local IDs without collision.
2. **State authority:** From each interface, open a remote ledger, mutate one card, reload, and prove the changed file exists only under the owner project's `.decision-os` root.
3. **Codex authority:** From each interface, launch and cancel a remote Codex run, observe live status, and prove the process PID plus run files exist on the owner node.
4. **Assets and voice:** Upload one image and one voice note to a remote project and prove persistence plus transcription under the owner node.
5. **Live events:** Observe owner-side card, thread, ledger, and Codex changes on the requester without manual reload.

---

## C. Cloudflare Acceptance

1. **Hibernation:** Keep both node sockets connected through an idle period and prove the Durable Object incurs no idle duration.
2. **Flow control:** Pause the receiver and prove sender credit stops data before relay memory grows beyond the defined bound.
3. **Deployment recovery:** Deploy a new Worker version while a federation is connected, then prove explicit offline state, reconnect, manifest convergence, and SSE recovery.
4. **Free-tier evidence:** Capture a full proof run's Worker requests, Durable Object billed requests, CPU, duration, memory, storage, and errors.
5. **Latency:** Verify event and cancellation propagation below `2 s` with the federation object created using the `apac-se` placement hint.

---

## D. DroidFleet Reuse Boundary

1. **Use the proven operational pattern:** Follow Bay's Wrangler deployment, secret injection, route installation, health probe, authenticated read probe, authenticated mutation probe, and durable append/read probe structure.
2. **Exclude Bay's runtime topology:** Bay's queues, D1 orchestration database, R2 log bucket, scheduled reaper, GitLab integration, DigitalOcean client, builder lifecycle, and blue-green engine solve asynchronous VPS orchestration rather than live symmetric stream routing.
3. **Implement the missing primitive:** Add a new hibernatable Durable Object that accepts both outbound node sockets and relays bounded request, response, event, upload, voice, Codex status, and cancellation frames.
4. **Security carryover:** Retain timing-safe secret comparison, HMAC timestamp validation, replay rejection, Wrangler-managed secrets, bounded idempotency records, and explicit deployment probes.

---

## E. Operator Gate

1. **Study result:** Cloudflare Workers plus Durable Objects remains the selected proof platform. DroidFleet demonstrates a tested Cloudflare deployment and control-plane pattern while proving that Bay itself cannot provide the required WebSocket relay.
2. **Next decision:** Authorize this bounded Cloudflare two-node proof. Product implementation remains blocked until the proof validates network recovery, backpressure, runtime replacement, authorization, latency, and resource usage.
