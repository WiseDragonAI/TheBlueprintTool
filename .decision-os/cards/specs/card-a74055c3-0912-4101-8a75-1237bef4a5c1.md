## A. Frontend Result

1. **Preserve the validated route model:** Keep `/p/:projectId/...`. A remote catalog record uses the opaque route ID `${ownerNodeId}:${localProjectId}`, which the existing `encodeURIComponent` path construction can carry as one segment.
2. **Preserve request scoping:** The existing global `fetch` wrapper and ledger `EventSource` already prepend the active project route. They do not need separate remote endpoint logic.
3. **Server decision:** Extend project resolution so local IDs dispatch locally and owner-qualified IDs use the federation connector.

---

## B. Required Runtime Changes

1. **Catalog:** Make local `GET /decision-os/projects` return the merged local and authorized remote catalog with owner and presence fields.
2. **Navigation:** Use `routeProjectId` in project, ledger, zone, and card URLs. Keep `localProjectId` only for owner dispatch.
3. **Control Room:** Fetch each online owner's node-wide read model through the relay, qualify its project IDs, and merge it with the local projection. Bridge each owner's control-room event stream through the local server.
4. **Project surface:** Reuse current ledger, card, thread, asset, upload, voice, and Codex components. Every request continues through the same project-scope helper.
5. **Live changes:** The local server converts the remote owner's relayed SSE bytes back into the browser-facing SSE response; existing refresh and Codex-resume handlers remain unchanged.

---

## C. Presence Behavior

1. **Online:** Show the owner node label beside remote projects and allow the same actions as local projects.
2. **Offline:** Keep cached project and ledger-summary entries visible with an explicit `Owner offline` state. Disable entry into uncached project content, mutation, upload, voice, and Codex actions.
3. **Local continuity:** Relay loss never changes local project routing, local event subscriptions, local mutations, or local Codex execution.
4. **No false cache:** Do not display cached ledgers, cards, threads, or Codex status as current; the relay does not replicate project state.

---

## D. Change Boundary

1. **Frontend code:** Extend catalog types, project navigation identity, presence rendering, and Control Room projection merge only.
2. **Unchanged UI:** Preserve canvas, cards, threads, uploads, voice capture, Codex widgets, keyboard behavior, and mobile interaction structure.
