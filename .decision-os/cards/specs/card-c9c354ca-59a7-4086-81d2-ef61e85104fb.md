## A. Mobile Control Room Cutover

1. **Goal:** Render the complete mobile Control Room from the compact server projection.
2. **Route:** Preserve `/`, `/p/:projectId/control-room`, project and ledger filters, task anchors, and tab query state.
3. **Data boundary:** Replace project-ledger fan-out, client Markdown classification, complete thread arrays, full pipeline detail, and skill-run history requests with one `GET /api/control-room` request.

---

## B. State And Refresh Contract

1. **Client state:** Store the projection envelope and selected filters; remove hydrated `documents`, raw master Markdown, and duplicate derived task collections.
2. **Revision events:** Subscribe to `/api/control-room-events`, debounce by aggregate revision, and refetch only after revision advances.
3. **Unchanged state:** Preserve the rendered list and scroll anchor when a conditional request reports no new revision.
4. **Stale state:** Display a non-blocking stale indicator with the served revision while the server rebuilds.
5. **Failure:** Keep the last rendered revision on refresh failure and expose a retry without clearing task lists.

---

## C. Behavior Parity

1. **Tabs:** Preserve Queue and Active, rename Delayed to Backlog, and keep completed tasks outside the current visible tabs while retaining their server classification.
2. **Filtering:** Preserve all-project, one-project, and per-ledger filters plus accurate tab counts after every filter change.
3. **Queue order:** Preserve ranked ordering, long-press drag, optimistic DOM order, queue-rank persistence, success after reload, and server reconciliation after rejection.
4. **Active rows:** Preserve queued position, active stopwatch, run status, and direct navigation.
5. **Backlog rows:** Preserve expandable subtask progress, open-master action, restore-to-queue action, and empty-state copy using `Backlog` vocabulary.
6. **Task navigation:** Preserve stable anchors, scroll restoration, project-scoped card links, ledger and zone resolution, and subtask navigation.
7. **Task intake:** Preserve `+ New task`, project selection, ledger selection, zone creation, master card creation, initial thread opening, and activation after Codex starts.
8. **Task detail:** Preserve visible content, subtask list, move-to-backlog, restore, complete, delete, back navigation, thread tooling, and Codex launch.
9. **Diagnostics:** Render server-provided malformed-task diagnostics without parsing Markdown in the browser.

---

## D. Network And Instrumentation

1. **Initial load:** Make one Control Room data request and no ledger and run-history requests.
2. **Refresh:** Refetch the compact projection once per new aggregate revision.
3. **Mutation reconciliation:** Consume compact changed-task projections after queue, backlog, completion, deletion, and intake mutations.
4. **Metrics:** Capture request count, response bytes, server timing, JSON parse time, render time, first rendered task, and revision-refresh duration.

---
