## A. Root cause

1. **First incorrect client transition:** Both canvas and mobile Run controllers treated any persisted `codexThreadRunId` as a resume target. A `pending` status returned before launch, so operator input became a focus operation instead of an authoritative start.
2. **First incorrect server transition:** `startThreadCodexProcessController` rejected card-owned resumable metadata without verifying a live child process.
3. **Referenced-card evidence:** `card-b85c6294-593d-4870-8c6e-ec559386df3c` retained terminal `codexThreadRunId` `codex-skill-1784101794025-b91c2f04` with no `codexActiveRunId`.
4. **Required boundary:** Only a runtime run with status `running`, a positive child PID, `exitCode === null`, and `killed !== true` may reject Run.
