## A. Contradicted-Success RCA

1. **Reproduction:** On `http://127.0.0.1:50150/skills` in a `412 × 915` Android Chromium viewport, opening `retrospect-and-close-task`, selecting `Architecture`, then pressing `Save tags` produced three `PUT` requests and three `403` responses.
2. **First incorrect transition:** The tag tap changed only local checkbox state. A redundant Save action later submitted `{"tags":["Architecture"]}` to every owning project.
3. **Backend evidence:** The running process predates the metadata-save backend change. Its protected skill route returns `Server skills are synchronized through ledger-cli.` and its detail responses contain neither `tags` nor `availableTags`.
4. **Prior claim correction:** Simulated rejection evidence did not prove a successful save on the served backend. The tag and served-route subtasks were reopened.

---

## B. Corrected Implementation

1. **Single selection:** Mobile and desktop expose the ten fixed categories as `aria-pressed` buttons. Exactly one tag can be selected.
2. **Immediate save:** Selecting a different tag applies `[tag]` optimistically and immediately sends the metadata request. The `Save tags` action no longer exists.
3. **Reconciliation:** A successful response keeps the canonical server tag; a rejected response reloads and restores server-confirmed state.
4. **Server boundary:** The backend accepts one supported tag as project metadata for synchronized server skills without modifying their server-owned `SKILL.md`.

1. **Automated checks:** Combined frontend/backend typecheck passed. Backend route regressions passed `3/3`; mobile tests passed `14/14`; focused desktop tag tests passed `2/2` after the optimistic-state correction.
