## A. Deliverable

1. **Protocol:** Define versioned schemas for pairing, registration, heartbeat, inventory, leases, command acknowledgement, status, cancellation, and reconnect replay.
2. **Persistence:** Define coordinator records for nodes, projects, leases, commands, audits, and idempotency.
3. **Threat model:** Cover stolen tokens, revoked nodes, replay, compromised projects, stale leases, outage, and secret leakage.
4. **Boundary:** Keep arbitrary shell execution outside the protocol.

---

## B. Acceptance Criteria

1. **Messages:** Every message has a schema version, message ID, node ID, timestamp, and acknowledgement rule.
2. **Recovery:** Reconnect resumes status delivery without re-executing a terminal command ID.
3. **Authorization:** Every command names one project, one node, one typed operation, and one required permission.
4. **Mapping:** The contract identifies each endpoint and persistence record required by later subtasks.
