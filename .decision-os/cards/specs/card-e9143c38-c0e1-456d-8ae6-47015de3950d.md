## A. Scope And Canvas Boundary

1. **Status:** This is the fifth implementation subtask of `Build Stable Server State Projections`, retained from the repository-wide audit requested by the operator.
2. **Canvas invariant:** Desktop ledger canvases continue receiving all card bodies required for rendering. The optimization removes unrelated thread bodies and oversized mutation responses, not canvas card content.
3. **Goal:** Replace universal hydrated-ledger transport and broad internal hydration with read models scoped to each consumer.
4. **Authoritative state:** Keep ledger JSON, card Markdown, and thread Markdown as source truth.
5. **Verified amplification:** `tasks-system.json` is `35,731 bytes`; its hydrated response measured `6,398,140 bytes`, with parsed threads occupying approximately `94.8%`.
6. **Rule:** A consumer receives the smallest coherent entity projection that satisfies its current surface; unrelated bodies and histories are excluded.

---

## B. Server Read Contracts

1. **Ledger canvas:** `GET /api/ledgers/:ledgerId/canvas` returns viewport, geometry, zones, groups, relationships, required card bodies, image sizes, and server-derived workflow flags; it excludes every thread body.
2. **Ledgers canvas:** `GET /api/ledgers-canvas` returns project ledger nodes, geometry, relationships, labels, colors, and counts without card and thread hydration from member ledgers.
3. **Navigation:** `GET /api/ledgers/:ledgerId/navigation` returns zones, groups, counts, and card summaries without Markdown bodies and thread histories.
4. **Card detail:** `GET /api/ledgers/:ledgerId/cards/:cardId` returns one card body, metadata, image sizes, workflow state, task detail, linked subtask summaries, owning zone, and revision.
5. **Thread detail:** `GET /api/ledgers/:ledgerId/threads/:threadId` returns one parsed thread, deleted-note ids, content-file identity, card identity, and revision.
6. **Search:** `GET /api/ledgers/:ledgerId/search` requires `zoneId` and `q`, searches server-owned card text, and returns matching card summaries plus highlighted field identity without returning all bodies.
7. **Mutation:** `POST /api/ledgers/:ledgerId/mutations` returns `ok`, ledger revision, changed entity ids, removed entity ids, and changed projections; it never returns the complete ledger.
8. **Project scope:** Every contract uses canonical `/p/:projectId/...` scoping and rejects resource identities outside the owning project.

## C. Mutation Coverage

1. **Cards:** Cover create, title, body, status, image sizes, model preference, effort preference, image deletion, card deletion, and master-task completion.
2. **Regions:** Cover zone and group creation, deletion, label, color, geometry, and contained-card effects.
3. **Canvas:** Cover card geometry, zone geometry, group geometry, viewport, relationships, relationship deletion, selection paste, and resize-to-content reconciliation.
4. **Threads:** Cover append, update, delete, deleted-note ids, voice metadata, transcription reconciliation, image upload, file upload, and optimistic note state.
5. **Task workflow:** Cover queue-rank body edits, backlog status, completion projection, task deletion, and changed Control Room slice.
6. **Mutation reads:** Dispatch by action before loading content. Geometry and viewport read no Markdown; card-body actions read one card file; note actions read one thread file.
7. **Responses:** Return only the projections needed to reconcile the initiating surface and advance its revision.

## D. Client Surface Cutover

1. **Desktop canvas:** Move active ledger bootstrap, ledger switching, ledgers canvas, workflow indicators, geometry persistence, viewport persistence, card editing, media sizing, clipboard, zone, group, relationship, and deletion flows to scoped contracts.
2. **Desktop thread:** Replace `loadActiveThreadSlice()` full-ledger fetch with the thread-detail route while preserving route epoch, content-file ownership checks, local optimistic notes, deleted-note reconciliation, and render behavior.
3. **Desktop Codex and voice:** Refresh only the changed card and thread after process, cancel, continue, session deletion, voice upload, retry, transcription, file upload, and image upload.
4. **Mobile navigation:** Load ledger and zone lists from navigation summaries, one card route from card detail, and one thread panel from thread detail.
5. **Mobile search:** Replace browser scans of all card Markdown with the scoped search endpoint.
6. **Mobile mutations:** Replace full-ledger mutation reconciliation after card, zone, thread, task, voice, upload, and Codex actions with changed projections.
7. **Presentation:** Keep Markdown-to-DOM rendering on the client only for the card and thread bodies currently visible.

---

## E. Server, Watcher, And CLI Cutover

1. **Server mutations:** Remove unconditional `hydrateLedgerThreadNotes()` from `applyLedgerMutation()` and load the target thread only for note actions.
2. **Codex workflows:** Scope thread-process start, messages-after-last-event, run-event persistence, pipeline context, and run ownership to their target card and thread files.
3. **Voice workflows:** Scope voice upload and transcription orchestration to the target thread rather than hydrating every thread in the ledger.
4. **Watcher ownership:** Replace per-event scans of `state.json` plus every ledger with the projection store's canonical content-file ownership index.
5. **CLI commands:** Move thread hydration behind commands that consume thread data and card hydration behind commands that consume card bodies; `overview`, `card-context`, `zone-cards`, status mutation, geometry mutation, and relationship mutation perform no unrelated hydration.
6. **Legitimate hydration:** Keep explicit export and full diagnostic commands capable of reading complete content when their output contract requires it.

---

## F. Rollout And Legacy Removal

1. **Additive server phase:** Add scoped endpoints, revisions, ownership validation, and focused tests while existing clients remain available.
2. **Client phase:** Migrate desktop, mobile navigation, thread, search, mutation, Codex, and voice consumers to scoped contracts.
3. **Internal phase:** Migrate server controllers, watcher resolution, and CLI command dispatch to scoped reads.
4. **Removal phase:** Delete the universal hydrated `GET /decision-os/:ledgerId` response after repository search confirms zero consumers; keep source-file helpers only for explicit scoped reads.
5. **Mutation phase:** Remove complete-ledger mutation bodies and the client code that parses them after every mutation consumer accepts changed projections.
6. **Compatibility gate:** Update integration fixtures, route tests, project scoping, revision reconciliation, and error contracts in the same removal change.
