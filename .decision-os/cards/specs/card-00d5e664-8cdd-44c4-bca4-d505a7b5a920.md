## A. Scope

1. **Objective:** Create and update OpenAI-format skills through `ledger-cli`, keep their file-level Skills ledger projection synchronized with `.skills`, commit each transaction, and resolve the packages from every managed project.

---

## B. Verified Current State

1. **Discovery roots:** `backend/src/business/codex/helper/scan-codex-skills.ts` scans `<workspace>/.skills`, `$CODEX_HOME/skills`, `$CODEX_HOME/skills/.system`, and `$CODEX_HOME/plugins/cache`.
2. **Existing ledger:** This repository already stores a Skills ledger at `.decision-os/skills.json` with skill cards under `.decision-os/cards/skills/`.
3. **OpenAI layout:** Existing packages use `.skills/<name>/SKILL.md`, `.skills/<name>/agents/openai.yaml`, and optional `references/`, `scripts/`, and `assets/`.
4. **Card boundary:** Card content files must remain under `.decision-os`; they cannot directly use `.skills` files as `comment.contentFile` values.
5. **CLI gap:** `ledger-cli` exposes no server-skill create, update, synchronization, and commit commands.
6. **Shared resolution point:** Catalog reads, direct runs, pipeline runs, and pipeline validation resolve skills through `scanCodexSkills`.

## C. Architecture

1. **Registry ledger:** Use `<server-launch-root>/.decision-os/skills.json` as both the server Skills ledger and the hard server-side JSON registry.
2. **Package storage:** Copy the complete OpenAI-format package to `<server-launch-root>/.skills/<skill-name>`.
3. **Skill zone:** Append one zone labeled with the validated skill name to `skills.json`.
4. **Primary card:** Create one card inside the zone whose external Markdown body is an exact mirror of `.skills/<skill-name>/SKILL.md`.
5. **Reference cards:** Create one card inside the same zone for every regular file under `.skills/<skill-name>/references/`; each card body exactly mirrors its reference file.
6. **File mapping:** Persist `skillName`, `skillRole`, and repository-relative `skillFile` on every skill card in `skills.json`; use `skillRole: "main"` for `SKILL.md` and `skillRole: "reference"` for reference files.
7. **Relationships:** Link the primary card to every reference card with the reference's package-relative path as the relationship label.
8. **Non-card resources:** Copy `agents/openai.yaml`, `scripts/`, and `assets/` into `.skills` without creating cards for them.
9. **Synchronization invariant:** The primary and reference card bodies are byte-equivalent to their mapped `.skills` files after every successful create and update transaction.
10. **Shared discovery:** Scan the server `.skills` root for every project context created by the multi-project server.
11. **Name collision:** The synchronized server skill wins when another discovered skill has the same name.

## D. CLI Contract

1. **Create command:** `ledger-cli skills create --source <skill-directory> [--json]` uses `process.cwd()` as the server launch root, provisions the Skills ledger on first use, and rejects an existing skill name.
2. **Update command:** `ledger-cli skills update --source <skill-directory> [--json]` uses `process.cwd()` as the server launch root, updates an existing synchronized skill, and rejects a missing skill name.
3. **Validation:** Require valid `SKILL.md` frontmatter and `agents/openai.yaml`; validate every reference and resource; reject symlinks, path escapes, and unreadable entries.
4. **Create projection:** Generate deterministic zone, primary-card, reference-card, relationship, content-file, and thread-file identities with non-overlapping geometry.
5. **Update projection:** Preserve the zone and primary-card ids; preserve reference-card ids by `skillFile`; add new reference cards; remove stale reference cards, relationships, content files, and thread mappings.
6. **Exact mirrors:** Write exact `SKILL.md` and `references/**` contents to the mapped `.decision-os/cards/skills/` files and materialize the complete source package under `.skills/<skill-name>`.
7. **Atomic files:** Stage the package, card Markdown files, thread files, `skills.json`, `state.json`, and `ledgers-canvas.json`; restore every surface when any write fails.
8. **Git precheck:** Require a Git repository with `HEAD`; reject the transaction when any owned target path has uncommitted changes.
9. **Create commit:** Stage only transaction-owned paths and create `skills: create <skill-name>`.
10. **Update commit:** Stage only transaction-owned additions, modifications, and deletions and create `skills: update <skill-name>`.
11. **Commit failure:** Restore the pre-transaction worktree and Git index state when commit creation fails.
12. **Output:** Return the operation, skill name, zone id, primary card id, reference card ids, package path, ledger path, and commit SHA.

## F. Verification Contract

1. **Create projection:** A package with three reference files creates one zone, one primary card, three reference cards, three labeled relationships, matching card Markdown, and one `.skills` package.
2. **Update projection:** Adding, changing, and removing references updates cards, relationships, mirror files, and `.skills` files while preserving stable ids for unchanged mappings.
3. **Exact synchronization:** Every main and reference card body matches its mapped `.skills` file byte for byte after create and update.
4. **Commit:** Each command creates one focused commit containing the synchronized package, cards, threads, `.decision-os/skills.json`, and first-run registry files with no unrelated paths.
5. **Shared availability:** Both fixture projects resolve the created and updated skill for direct and pipeline execution.
6. **Isolation:** Synchronization writes nothing to Codex home or either managed project.
7. **Failure safety:** Invalid, duplicate-create, missing-update, first-run write-failed, and commit-failed transactions leave the worktree and index at their pre-command state.
8. **Repository gate:** Run focused backend and CLI tests, backend TypeScript checks, and the repository test command from an isolated feature worktree.
