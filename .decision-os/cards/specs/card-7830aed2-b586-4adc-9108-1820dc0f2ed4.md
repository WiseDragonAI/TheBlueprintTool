## A. Objective

1. **Define** the repository rule that a master-task card is an operator summary.
2. **Keep** implementation details, RCA evidence, test output, code paths, commit identifiers, and low-level visual values in linked result subcards.
3. **Limit** the master card to the outcome, decision state, material risk, linked task status, and next operator action.

---

## B. Acceptance

1. **Rule location:** the canonical card-writing instructions contain the concise master-task contract.
2. **Concrete boundary:** the rule names the content allowed on master cards and the content required in result subcards.
3. **Examples:** one concise master-card example and one implementation-results subcard example demonstrate the boundary.
4. **Validation:** existing master-task lifecycle requirements and canonical subtask links remain intact.
