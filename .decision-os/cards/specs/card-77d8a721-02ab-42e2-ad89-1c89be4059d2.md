## A. Selected Transport

1. **Connection model:** Each Decision OS server opens one outbound `WSS` connection on port `443` to the relay. The phone and workstation require no inbound public port.
2. **Protocol basis:** Use [RFC 6455 WebSocket transport](https://www.rfc-editor.org/info/rfc6455) because it provides one full-duplex connection over TCP and supports text control messages plus binary data messages.
3. **Runtime library:** Pin [`ws@8.21.0`](https://www.npmjs.com/package/ws), MIT, through npm for the Node relay and node connector. It has zero required dependencies and passes the Autobahn WebSocket test suite. Disable `permessage-deflate` for the proof to avoid its documented memory and CPU overhead.
4. **Industry evidence:** [Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/) documents the same outbound-only bidirectional tunnel shape; [GitHub self-hosted runners](https://docs.github.com/en/actions/reference/runners/self-hosted-runners) use outbound HTTPS to receive owner-executed work; [Tailscale](https://tailscale.com/docs/concepts/control-data-planes) separates central identity, discovery, and policy from device-local data authority.

## B. Version 1 Frames

1. **Session:** `hello`, `hello.accepted`, `manifest.replace`, `presence.heartbeat`, and `error` are JSON control frames.
2. **Request:** `request.open` carries `requestId`, authenticated requester identity, target global project key, method, path, query, and allowlisted headers. `request.data` carries ordered binary chunks; `request.end` closes the body; `request.cancel` aborts the owner request.
3. **Response:** `response.open` carries status and allowlisted headers. `response.data` carries ordered binary chunks. `response.end` carries the terminal result.
4. **Live events:** SSE is the same response state machine with an open-ended body. Browser disconnect produces `request.cancel`; reconnect creates a new request and obtains current authoritative state through the existing refresh path.

## C. Ordering and Backpressure

1. **Identity:** Generate a UUID `requestId` at the requester. The relay rejects a duplicate active ID, and the owner rejects a duplicate terminal mutation ID retained for `10 min`.
2. **Ordering:** Sequence data chunks per request and reject gaps, repeats, data after end, and terminal frames before open.
3. **Fairness:** Limit chunks to `64 KiB` and interleave streams so an upload does not monopolize the connection.
4. **Flow control:** Pause the local source while WebSocket `bufferedAmount` exceeds `1 MiB`; cancel the offending stream if queued data reaches `4 MiB`.
5. **Admission:** Allow at most `32` simultaneous remote streams per node; reject excess work with `503 federation_capacity`.

---

## D. Recovery

1. **Reconnect:** Retry with jittered exponential delay from `1 s` to `30 s`; publish a full manifest after authentication.
2. **Safe replay:** Automatically recreate only `GET`, `HEAD`, and SSE subscriptions. Never automatically replay a mutation, upload, cancellation, or Codex launch after an ambiguous disconnect.
3. **Ambiguous mutation:** Return `502 federation_outcome_unknown`, refresh the authoritative ledger or run status after reconnection, and present the result before the operator can retry.
4. **Timeouts:** Use `10 s` connect timeout and `30 s` inactivity timeout for finite streams. Heartbeats, chunks, and response frames reset inactivity; SSE remains open while heartbeats continue.
