## A. Implementation

1. Add one backend schedule service that scans enabled schedules, claims due occurrences atomically, and calls the existing saved-pipeline start path.
2. Start the service with the Decision OS server and reconcile due schedules once after project discovery.
3. Advance `nextRunAt` from the scheduled timestamp, not from wall-clock completion time.
4. Persist the created `pipelineRunId` and launch error on the occurrence without bypassing the existing process-capacity queue.

---

## B. Acceptance evidence

1. Tests with a controlled clock prove exactly one run is created for concurrent scans of the same occurrence.
2. Restart tests prove one latest missed occurrence is recovered and older missed occurrences are marked skipped.
3. Queue tests prove scheduled and manually launched pipelines share the current FIFO capacity limit.
4. Failure tests prove a rejected launch remains visible and the next occurrence is still calculated.
