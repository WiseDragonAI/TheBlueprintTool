## A. Failure Contract

1. **Requester disconnect:** Cancel its open remote streams at the owner. A completed owner mutation remains authoritative and is discovered by refresh after reconnect.
2. **Owner disconnect:** Fail new work with `503 owner_offline`; terminate finite streams with the same status; close bridged SSE so the browser's existing reconnect path can retry.
3. **Relay restart:** Local projects continue normally. Both nodes reconnect and replace their manifests; remote projects remain visible but offline until presence returns.
4. **Duplicate delivery:** Reject an active duplicate request ID. Return the retained terminal result for an identical finite request; reject a conflicting reuse with `409 duplicate_request`.
5. **Late response:** Discard frames for a cancelled or terminal request ID and record the protocol violation.
6. **Rejected mutation:** Forward the owner's HTTP status and structured body unchanged.
7. **Codex termination:** The owner persists run state and publishes its normal settlement event. Requester loss does not kill the owner process; explicit cancellation does.

---

## B. Proof Resource Budget

1. **Topology:** One relay, two connected nodes, at most `32` remote streams per node.
2. **Bodies:** `1 MiB` maximum JSON/control body, `25 MiB` maximum upload, and `64 KiB` data chunks.
3. **Memory:** Pause writes above `1 MiB` WebSocket buffered data and hard-cancel at `4 MiB`. The relay stores at most `256 KiB` of manifest data per node and no project content.
4. **Bandwidth:** Use binary data frames, so the relay receives and forwards each payload byte once without base64 expansion. Disable compression for predictable CPU and memory.
5. **Presence traffic:** Two `15 s` heartbeats plus manifest replacement on catalog change; no ledger or card polling is added while SSE is healthy.

---

## C. Measurements Required in the Proof

1. **Relay:** Record idle RSS, RSS with `64` admitted streams, peak buffered bytes, ingress and egress bytes, reconnect CPU, and manifest-store size.
2. **Nodes:** Record connector idle RSS, per-stream RSS, event latency, finite-request latency, upload throughput, and Codex launch-to-status latency.
3. **Thresholds:** The proof passes when no buffer exceeds the defined hard limit, local project latency is unchanged within measurement noise, a `25 MiB` upload completes without unbounded RSS growth, and event plus cancellation propagation remain below `2 s` on the test network.
4. **Status:** These are acceptance budgets, not measured production results; quantitative measurements require the operator-authorized two-node proof.
