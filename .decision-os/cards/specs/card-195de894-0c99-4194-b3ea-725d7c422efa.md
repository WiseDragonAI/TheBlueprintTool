## A. Implementation

1. Extend the project-owned pipeline store with validated schedule and occurrence collections.
2. Add project-scoped endpoints to list, create, update, enable, disable, and delete schedules.
3. Reject a schedule whose pipeline, ledger, source card, cron expression, or IANA time zone is invalid.
4. Preserve atomic store writes and backward compatibility for existing `.decision-os/codex-pipelines.json` files.

---

## B. Acceptance evidence

1. Store tests prove legacy files load unchanged and schedule mutations survive a fresh read.
2. Route tests prove project isolation, validation failures, state transitions, and deletion behavior.
3. API responses expose canonical `nextRunAt` values computed from the persisted contract.
