## C. Product Contract

1. **Projects index:** Add the route `/projects` with one project card per catalog entry, showing its display name, description, relative path, color, and active-project state.
2. **Project detail:** Selecting a project card opens `/projects/:projectId`; the detail surface provides an explicit `Open project` action and a `Settings` action.
3. **Settings dialog:** Use the existing native `<dialog>` pattern for an accessible modal form with `Name`, `Description`, and `Color` fields, validation feedback, cancel, and save controls.
4. **Successful save:** Persist the three editable fields, update the in-memory catalog, and immediately refresh every visible project name, description, and color projection.
5. **Project identity:** Keep project `id`, filesystem root, `.decision-os` root, and relative path read-only; editable names are display metadata and never rename directories.
6. **Drawer destinations:** Render `Control room`, `Projects`, `Ledgers`, `Pipelines`, and `Skill library` only, in that order, with dedicated inline SVG icons and visible text labels.

## D. Acceptance Criteria

1. **Drawer removal:** Opening the burger drawer shows no project list, project row, or color input.
2. **Projects navigation:** The `Projects` destination is between `Control room` and `Ledgers`, routes to `/projects`, and receives the active navigation state on project routes.
3. **Project browsing:** The Projects page lists every catalog project and exposes an unambiguous active-project marker.
4. **Project actions:** A project detail can switch the active project and can open its settings dialog.
5. **Persistence:** A saved name, description, and color survive a fresh catalog request and browser reload without changing project identity or filesystem paths.
6. **Validation:** An empty name, a name longer than `120` characters, a description longer than `1000` characters, and a non-six-digit hexadecimal color are rejected without partially changing settings.
7. **Icons:** Each of the five application destinations has a distinct inline SVG icon; the repeated empty-circle pseudo-icon is removed.
8. **Regression coverage:** Focused backend catalog tests and mobile route/rendering tests cover the metadata API, route entry, drawer removal, settings save, active-project switching, and icon contract.
