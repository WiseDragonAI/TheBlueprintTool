## A. Objective

1. **Define project settings.** Add a durable configuration contract for detected projects and their assigned colors.

---

## B. Contract

1. **Project record.** Define the exact persisted fields needed to identify a project CWD, show its name, and store its color.
2. **Lifecycle.** Define behavior for newly detected, renamed, moved, and no-longer-detected projects from verified runtime constraints.
3. **Settings ownership.** Place project configuration at the Termux-home master-server scope.

---

## C. Exit Criteria

1. **Shared schema.** The server and burger-menu UI use one validated project settings contract.

---

## D. Implemented Contract

1. **Catalog record.** Each project exposes `id`, `name`, `relativePath`, `root`, `decisionOsRoot`, `color`, and `ledgers` through `/decision-os/projects`.
2. **Color persistence.** `PATCH /decision-os/projects/:projectId` validates a six-digit hex color and stores it under `colors[projectId]` in the master `.decision-os/projects.json`.
3. **Lifecycle.** Discovery remains authoritative. Newly detected projects receive deterministic palette colors; absent projects disappear from the catalog while their saved color entry remains available if the same relative-path identity returns.
