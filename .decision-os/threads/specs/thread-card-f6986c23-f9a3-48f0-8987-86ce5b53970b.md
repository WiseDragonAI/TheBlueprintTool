# AGENT

## A. Finding

1. **Root cause:** The completed recording existed only as an in-memory `Blob` between `MediaRecorder` stop and `POST /api/voice-upload`.
2. **First incorrect transition:** When that request failed before server acceptance, the optimistic note had no `voiceFileRef`; the renderer only exposed `Retry` for `transcription failed` notes with a server-owned file.
3. **Observed evidence:** The screenshot shows `Voice upload failed before transcription.` with status `upload failed` and no retry control.

---

## B. Implemented

1. **Persist before upload:** Every non-empty recording is committed to native browser `IndexedDB` database `decision-os-voice` before `fetch` starts.
2. **Stable identity:** The stored entry retains the original `noteId`, `threadId`, ledger ID, card ID, MIME type, audio `Blob`, and `queueCodex` value.
3. **Pre-acceptance retry:** Failed uploads now render `Retry` and resubmit the original stored audio into the same optimistic note.
4. **Reload recovery:** A fresh page load restores the failed note and retry control from `IndexedDB`.
5. **Cleanup:** The local entry is deleted only after server acceptance returns a non-empty `voiceFileRef`; deleting the note also removes its retained recording.
6. **Commit:** Merged as `0d950e0` (`merge: durable voice upload retry`).
