## A. Finding

1. **Your desktop observation confirms the mobile root cause.** Every card render enters `openCardDetail()`, which automatically opens the thread on desktop and automatically closes it on mobile. The renderer therefore overwrites the operator’s explicit thread state.
2. **A concrete background trigger is verified.** `federation-replica-change` calls `loadRoute({ retainView: true })`; the completed load rerenders the card and runs that automatic open/close policy. This explains a desktop thread reopening after Close and a mobile thread plus expanded text input disappearing during background activity.
3. **The Control Room rollback has a second unsafe boundary.** Deferred process completion dispatches a global accepted-run event from mutable context, and the application unconditionally replaces the current route with Control Room `exec`. The route loader and responsive thread refresher also lack complete post-await ownership checks.
