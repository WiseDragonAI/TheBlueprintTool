## A. Root cause

1. **The Pink Codex run was live; the mobile thread held stale card state.** The launch persisted `codex-skill-1784211925748-5e8f0f24`, the durable queue and status API reported it running, and JSONL continued growing. The post-launch refresh updated `currentCard` but did not replace `canvasState.activeLedger`; the shared Codex Log renderer reads the latter and therefore rendered the empty state.

---

## B. Architecture finding

1. **The current restart work persists PID identity but does not detach execution from the server.** Thread and pipeline launches still pipe all standard streams through Node and rely on in-memory child callbacks. Adopted thread runs lose cancellation, pipeline runs are not adopted, and lifecycle/capacity truth is split across cards, durable stores, and runtime memory.

---

## C. Decision

1. **Use one durable run manifest and one host-owned detached launcher for every Codex run kind.** Bind prompt, JSONL, and log directly to files; reconcile status from manifest plus validated OS identity and terminal JSONL; signal the persisted process group for cancellation; keep the HTTP server as an API/projection consumer.

---

## D. Next implementation

1. Apply the shared-ledger hydration fix and exact new-intake regression first.

2. Migrate thread, continuation, and pipeline execution to the unified manifest/launcher/reconciler contract.

3. Prove JSONL growth, liveness, recovery, cancellation, capacity, and pipeline advancement across a server stop/restart before removing the compatibility paths.
