This is a bug, with one intentional rule underneath it.

1. **What the client is supposed to do:** the run widget polls the backend run-status endpoint and displays that authoritative status. The canvas reloads ledger state when it receives a project-scoped server-sent ledger event. The client intentionally does not declare a process finished merely because the JSONL log contains `turn.completed`.
2. **What happened on this run:** JSONL line `226` is `turn.completed`, but the Codex wrapper process tree is still alive as PIDs `7283 → 7313 → 7433`. The backend therefore still returns `status: running` and `active: true`; the queue item remains `running`, and the card still owns `codexActiveRunId`.
3. **Why settlement never occurred:** Decision OS updates terminal runtime state and removes the queue item only when the child emits `close`. That callback has not fired, despite the terminal Codex event.
4. **Why the canvas was not automatically refreshed:** the server publishes a terminal ledger lifecycle event for pipeline runs, but the ordinary thread-run `onCodexRunSettled` path publishes no ledger event when there is no queued voice note. Even a normally closed thread run therefore lacks the explicit canvas refresh event.

So the client is correctly rendering the backend state, but the overall behavior is defective in two places: there is no bounded reconciliation for a terminal JSONL event plus a hung wrapper, and ordinary thread settlement does not publish a terminal ledger refresh event.

The corrective contract is: after a bounded grace period following terminal JSONL, terminate the hung wrapper, persist terminal status, remove the queue item, clear active ownership, and publish a terminal ledger event for every thread run.

I did not terminate the process or change implementation because this request asked for diagnosis and explanation. The diagnosis subtasks are complete, the master-task gate is ready, and the master remains active pending explicit operator authorization.
