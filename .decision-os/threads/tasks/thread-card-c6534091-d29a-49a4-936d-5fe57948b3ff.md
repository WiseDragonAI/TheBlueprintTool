## A. What Actually Happened

1. **Decision OS does not currently have a real default-ledger setting.** The project registry preserves the order of `state.json.ledgers`, and the automatic project-synchronization master-task path simply takes `project.ledgers[0]`.
2. The old project-creation code created `tasks` only while creating a brand-new `.decision-os/state.json`. When the selected directory already had `state.json` with an empty ledger list, that branch was skipped and the project remained unable to host tasks.
3. Commit `74aef42a` moved ledger creation after state initialization and added the condition “create `tasks` when the registry is empty.” That fixes exactly the empty-ledger intake defect.
4. **It does not solve the larger task-ledger contract.** Existing projects with any ledger are deliberately left unchanged. No `tasks` ledger is added when another ledger exists, no semantic task-ledger selection is performed, and no existing task is migrated.

3. A normal Codex run uses the ledger of the card that launched it through `DECISION_OS_LEDGER_FILE`; it does not redirect a `master-task` label to `tasks`.
4. Verified current state: **48 master-task cards are in `specs`; 0 are in `tasks`.**
