## A. Flood Cause

1. The Cloudflare flood was produced by state anti-entropy, not the gated frontend polls.
2. Each received entity batch advertised an intermediate project root. The relay compared that incomplete root and initiated another missing-bucket repair while the current repair was still settling.
3. Relay acknowledgement also scanned project storage to recalculate the full root after every persisted batch, converting the message loop into high Durable Object row reads.

---

## B. Correction Boundary

1. Relay publication now permits one in-flight batch group per project and coalesces later entities behind it.
2. Repair batches acknowledge without intermediate summaries. The complete repair sequence ends with one terminal summary.
3. Relay acknowledgement no longer performs a per-batch project-root scan.
4. Relay disconnect retires stale transport delivery identifiers while preserving durable retry authority.

---

## C. Proof Boundary

1. The 16 federation replicator tests and 10 connector integration tests pass, including serialized publication, terminal-only repair summaries, remote-project execution publication, and disconnect cleanup.
2. All 670 backend tests, 9 Worker relay tests, the Termux relay test, backend typecheck, and relay typecheck pass.
3. The combined relay command retains a baseline `workerd` crash after its Worker tests pass; the same failure reproduces on unchanged `dev`, while both relay test files pass separately.
4. The task remains active because the correction is not deployed and production behavior is not yet proven.
