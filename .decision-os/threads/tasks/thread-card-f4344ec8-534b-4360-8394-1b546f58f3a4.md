## A. Why Desktop and Mobile Diverged

1. **The observed desktop and mobile flows are in the same responsive runtime but use different handlers.** Desktop `Shift+X` enters `handleResponsiveThreadShortcut()`; the mobile `RUN` button enters `stopQuickVoiceComment()`.
2. Desktop was repaired repeatedly in `ccf6bffb`, `3baeb597`, and `18df448e` by adding the `onPersisted` handoff only to the keyboard branch.
3. Mobile buttons were added through a separate quick-capture wrapper. Commit `f2abacf0` changed that wrapper to preserve explicit `SEND`, `RUN`, and `PIPELINE` selection, but also restored `await stopVoiceRecording()`. That await includes upload settlement.
4. The tests asserted source patterns and launch-mode selection. They did not force a delayed upload through every entry point. The duplication therefore allowed the timing regression to pass.

---

## B. Remaining Duplicate Paths

1. **Responsive desktop shortcut:** `frontend/src/app/responsive/thread.js:207` directly calls `stopVoiceRecording()` with its own handoff logic.
2. **Responsive buttons:** `frontend/src/app/responsive/thread.js:275` use the new `submitVoiceRecording()` coordinator.
3. **Canvas keyboard:** `frontend/src/runtime/input/controller/handle-keyboard.ts:74` directly awaits `stopVoiceRecording()`.
4. **Canvas record button:** `frontend/src/runtime/input/controller/handle-action-click.ts:117` directly awaits `stopVoiceRecording()`.
5. **Canvas action dock:** `frontend/src/runtime/input/controller/handle-action-click.ts:296` directly awaits `stopVoiceRecording()`.
6. Launch-mode decoding and the `VoiceLaunchMode` union are also repeated across responsive input, canvas input, upload compatibility, and backend normalization.
7. **Finding:** the July 20 fix corrects the reported mobile path, but the frontend command boundary is still not fully factorized.

---

## C. What Is Already Canonical

1. After a handler reaches `requestTranscription()`, the lifecycle is shared: capture, IndexedDB persistence, optimistic note identity, background upload, retry retention, server acceptance, transcription, and Codex launch.
2. The backend has one authoritative launch decision: `launchMode !== 'send'` creates `transcribing-before-launch`, then the same orchestration launches the run after transcription.
3. The divergence is confined to frontend action coordination before `requestTranscription()`.

---

## D. Required Factorization

1. Make one `executeVoiceAction()` controller own mode resolution, stop capture, local durability, background submission, failure reconciliation, and the durable handoff event.
2. Route every responsive and canvas keyboard/button entry point through that controller.
3. Keep navigation as a surface callback invoked by the shared durable event; the submission lifecycle must not be reimplemented by a surface.
4. Export one `VoiceLaunchMode` type and one modifier-to-mode resolver.
5. Remove the frontend `queueCodex` compatibility fallback after migrating its tests and callers to required `launchMode`.
6. Add one contract suite that runs delayed upload and persistence failure against every entry point, plus served checks for responsive desktop, responsive mobile, and canvas.

---

## E. Conclusion

1. **The operator is correct:** the paths are still duplicated, and that duplication directly caused the regression.
2. The mobile behavior is currently fixed and verified, but structural prevention requires the factorization above.
3. This continuation performed analysis only; no code was changed.
