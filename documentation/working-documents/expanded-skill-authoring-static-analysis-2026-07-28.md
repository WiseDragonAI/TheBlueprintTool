## A. Repository Intent

1. **Decision OS owns multi-project authoring, execution, and federation from one failsafe server.** A content-authoring failure must remain inside its request, a node-delivery failure must remain inside its delivery attempt, and unrelated projects, health routes, diagnostics, task state, and federation traffic must stay available.
2. **Durable owners remain authoritative.** Skill identity comes from validated `SKILL.md` frontmatter, pipeline prompts belong to `.decision-os/codex-pipelines.json`, Tasks card Markdown belongs to the task-state mutation path, Git owns authored revision history, MultiTerm owns registered server processes, and Wrangler owns relay deployment state.
3. **The browser does not own filesystem authority.** Existing skill creation and save routes accept kind plus identity and explicitly reject `path`, `filePath`, and `skillFile`. Direct-file editing must preserve this boundary after the server resolves the operator-supplied canonical Markdown URL.
4. **The current implementation is an uncommitted development iteration.** Worktree `.worktrees/dev` is on `dev` at `34c7e4ae`, two commits ahead of `origin/dev`, with `40` modified tracked files, multiple untracked implementation files, `2,314` tracked insertions, `280` tracked deletions, and no staged changes. This state is not an admitted delivery input.

## B. Current Iteration Intent

1. **Authoring:** create, edit, save, and inspect `federated-skill`, `workspace-skill`, and `pipeline-prompt` content from the Skills interface.
2. **Editor:** reuse the pinned CodeMirror 6 Markdown adapter in an `80vw` by `95vh` modal with search, history, undo, redo, wrapping, dirty state, keyboard access, conflict handling, and disposal.
3. **Revisions:** create one focused Git revision for every successful content save and navigate complete history through Pierre `1.2.12`, using red removals and blue additions plus non-color semantics.
4. **Isolation:** exclude pipeline prompts from natural agent discovery, workspace discovery, workstation discovery, cloud-agent discovery, and federation; inject exact prompt content only through an explicitly selected pipeline step.
5. **Direct Markdown URLs:** resolve a canonical Markdown filesystem URL belonging to a registered project, open the reusable editor instead of the generic JSON fallback, and persist through the file's authoritative owner.
6. **Delivery:** expose one CLI that consumes an admitted `dev` commit, updates `main`, updates and restarts every registered Decision OS node, deploys the production relay, verifies the resulting versions and convergence, and performs bounded compensation on failure.

## C. Findings

1. **`F01 — Critical omission — no delivery CLI exists.`** `bin/` contains server, node-message, migration, verification, workload, and ledger commands. It contains no command that admits a `dev` revision, promotes `main`, updates nodes, restarts nodes, deploys the relay, verifies convergence, or compensates a partial delivery. `federation-relay/package.json` exposes only the separate `wrangler deploy` script. The canary runbook explicitly stops at a later promotion decision.
2. **`F02 — Critical omission — current node operations cannot execute a release.`** `bin/decision-os-node.mjs` supports only `nodes` and Codex-backed `ask`. `createHttpServer()` exposes `/api/server/restart`, which acknowledges before a delayed exit and restarts only the receiving process. It has no target commit, delivery identity, authenticated admission record, Git update, supervisor receipt, post-restart version proof, idempotency key, retry journal, or rollback boundary. The federation connector can transport a bounded authenticated request to an online peer, but no node-local delivery controller consumes such a request.
3. **`F03 — Critical omission — delivery admission and compensation have no durable owner.`** No schema records the admitted `dev` SHA, `main` predecessor, generated `main` release commit, prior relay deployment, target node set, node predecessor versions, phase receipts, deadlines, failure, resumed attempt, compensation, or final proof. A process interruption after updating `main`, one node, or the relay therefore has no source-defined recovery point.
4. **`F04 — High omission — direct Markdown URLs still return JSON.`** In `create-http-server.ts`, application routes are limited to the known Control Room, project, ledger, pipeline, skill, and settings paths. Static serving is limited to `/assets`, `/src`, `/shared`, images, thread files, and card-owned static assets. An absolute Markdown URL such as `/home/jbb/dev/EditorBP/decision-os/.decision-os/cards/tasks/<card>.md` reaches the final `{ ok: true, method, url }` JSON response. No frontend bootstrap state, authorized file identity, generic Markdown read route, generic Markdown save route, or direct-file screen exists.
5. **`F05 — Critical ownership constraint — a Task card file cannot be saved as a raw file.`** `applyLedgerMutation()` turns `patch-card` content into `changedContentFiles`; `project-task-state.ts` publishes those resources through authoritative task state; `task-mutation-command.ts` materializes the card entity change. Writing `.decision-os/cards/tasks/<card>.md` directly would bypass the ledger projection, task-state command, content head, and federation publication. The direct-file editor must resolve this path as a `task-card-description` owner and save through the scoped Tasks `patch-card` command before creating the focused Git revision.
6. **`F06 — Critical defect — pipeline-prompt admission does not pin committed content.`** `availablePipelineContent()` validates catalog presence and kind, while `readPipelinePrompt()` reads current working-tree bytes. `createCodexPipelineRunManifest()` records `contentKind` but no content revision, Git commit, or immutable prompt snapshot. `codex-pipeline-runner.ts` re-reads the prompt at execution time. If the prompt disappears between admission and execution, `buildPipelineSkillPrompt()` receives no prompt and emits `$<skillName>`, converting a pipeline-only identity into a natural skill invocation. Dirty and uncommitted prompt bytes are also admissible. This violates exact explicit injection and discovery isolation.
7. **`F07 — High regression — the CodeMirror owner destroys editor state during ordinary rerenders.`** `renderSkillLibraryEditorModal()` calls `disposeSurfaces()` at the start of every render. Saving state, changing defaults, changing tags, switching status, and several focus updates destroy and remount `EditorView`, losing CodeMirror undo history, search state, selection, and adapter dirty state. The task inventory requires editor state to survive modal rerenders.
8. **`F08 — Medium accessibility defect — read-only mode disables navigation tools.`** `mountCodeMirrorFileEditor()` disables every toolbar button when `readOnly` is true. This correctly disables `Undo` and `Redo`, but also disables `Find` and `Wrap lines`, even though both are non-mutating and required for usable inspection of protected content.
9. **`F09 — High recovery defect — the frontend discards the backend's Git-failure state.`** `saveCodexSkillLibrary()` correctly returns `503` with `recovery.authoredBytesPreserved: true` and `gitRevisionCreated: false`. `requestCodexSkillLibrarySave()` drops `recovery`. `saveSkillLibraryDraft()` treats every non-conflict failure identically, reloads the server bytes, resets `persistedMarkdown`, and reports that it reloaded a confirmed revision. In this case the bytes are new but uncommitted, so the UI erases the distinction between canonical content and a Git revision pending recovery.
10. **`F10 — High revision-integrity defect — a successful save can report an old commit.`** `commitSkillFileRevision()` returns the newest existing file revision when its generated tree equals `HEAD`. The save route then returns success, and the modal says `Saved as a new Git revision.` A repeated identical save and a defaults-only change submitted through the content-save payload can therefore claim a new revision without advancing `HEAD`. For federated and workspace skills, default model and effort metadata are written to `codex-pipelines.json` but are not included in the skill Git transaction, leaving that metadata outside the reported revision.
11. **`F11 — High specification drift — history is capped at 500 commits.`** `readSkillGitHistory()` clamps `--max-count` to `500`; `readCodexSkillLibraryHistory()` and `readSkillGitRevision()` request that maximum. The master and `T05` require complete affecting history. A file with more than `500` revisions makes older commits unreachable and causes `readSkillGitRevision()` to reject them as unknown.
12. **`F12 — High failsafe defect — synchronous Git can stop unrelated requests.`** `skill-git-revisions.ts` runs every Git operation through `spawnSync` with a `20,000ms` timeout. `federated-library-cache.ts:isCommittedPackage()` also runs multiple synchronous Git commands per candidate package. A slow repository can block the Node event loop, including unrelated project routes, health routes, diagnostics, and federation work. The process-level timeout does not contain event-loop unavailability.
13. **`F13 — High editability defect — user skills are advertised as editable without a revision repository.`** `sourceEditability()` marks user skills editable, `editableRoot()` accepts the user skill root, and content kind maps them to `external-skill`. `commitSkillFileRevision()` then requires the file to belong to a Git repository. A normal user skill root without Git accepts the content write and fails during commit, producing a permanently recoverable state for content that the three-kind authoring contract did not authorize.
14. **`F14 — Medium collision defect — global content creation does not inspect every project root.`** Global federated-skill and pipeline-prompt creation uses the master runtime plus its local catalog. `createCodexSkillLibrary()` rejects duplicates only in `librarySkills(input, true)` for that context. A same-name workspace skill owned by another registered project is not guaranteed to participate in the check. The merged name-first catalog can then hide one identity.
15. **`F15 — Medium editor-contract drift — the reusable adapter is not the stable owning surface yet.`** The adapter is path-free and correctly documents future thread-attachment reuse, but it exposes change callbacks only. Save state, save actions, close confirmation, focus return, and rerender persistence remain embedded in the skill modal. Direct-file reuse would duplicate these state transitions unless the editor session owner is separated from skill-specific metadata.
16. **`F16 — High verification omission — first-boundary failures and new end-to-end requirements are not covered.`** Existing new tests cover content kinds, selected routes, one Git `add` failure, editor controls, and a canary browser path. Source inspection found no complete regression for Git `read-tree`, `commit-tree`, `update-ref`, index reconciliation rollback, preserved-byte recovery UX, exact committed prompt admission, prompt disappearance after admission, history beyond `500`, direct Markdown routing, Task card owner dispatch, delivery lease, interrupted delivery resume, node restart proof, relay rollback, and compensation after partial node update. Static test presence does not establish that any current test passes.
17. **`F17 — High plan drift — authoritative planning artifacts omit both expanded requirements.`** The master card still ends at a later operator promotion decision. The `T01`–`T14` task list has no direct Markdown URL task and no one-command delivery task. `codex-content-authoring.md` explicitly states that this iteration adds no generic file API, and the canary runbook contains only manual dev deployment plus a prohibition against production promotion. The current implementation therefore cannot be assessed complete against the operator's expanded specification.
18. **`F18 — Confirmed boundaries to retain.`** The development implementation already pins local CodeMirror assets, uses the requested `80vw` by `95vh` modal, renders Pierre diffs with red removal and blue addition variables plus textual semantics, rejects browser-supplied skill paths, separates pipeline prompts from ordinary skill discovery, excludes workspace and prompt content from federated skill exports, invalidates the export cache after federated authoring, preserves pre-existing staged authored paths with an isolated Git index, and keeps production promotion outside the current canary runbook.

   4. Require a clean, pushed `origin/dev` commit whose SHA and verification evidence match the admission record. Require an exact `origin/main` predecessor and require every node in `/api/federation/nodes` to be online before mutation.
   5. Build the reviewed merge in an isolated release worktree, push that commit to `origin/main`, and record both predecessor and result before any node changes.

## E. Operator Decision Summary

1. **Decision: the current `dev` implementation is not complete and is not ready for delivery admission.**
2. **Highest-risk blockers:** the missing delivery authority and journal, direct Markdown URLs returning JSON, Task card ownership bypass risk, mutable pipeline-prompt admission with `$skill` fallback, and false revision recovery state.
3. **Implementation order:** update the master and task graph; repair immutable content and Git semantics; stabilize the reusable editor session; implement direct Markdown owner dispatch; implement the delivery journal and node authority; complete automated and served canary proof; admit one pushed `dev` commit; run the single delivery CLI.
4. **Verification boundary:** this analysis inspected source, Git state, task cards, and deployment procedures. It ran no test, typecheck, server restart, browser interaction, deployment, task lifecycle mutation, Git commit, or push.
