## A. Corrected Product Invariant

1. **A logical project is intentionally multi-writer.** The same durable project can be hosted on Workstation and Mobile. Both nodes must accept local task mutations, continue while disconnected, and converge after reconnection.
2. Code synchronization and task synchronization are independent. Git carries code commits. The task replication system carries live ledger state and Markdown resources without waiting for a code synchronization run.
3. A remote-only route can proxy a mutation to a selected hosting node, but that routing behavior does not make the selected node the canonical writer for the logical project.
4. **The previous single-owner recommendation was incorrect and has been removed from this document.**

---

## B. Repository and Iteration Intent

1. Decision OS stores one structured ledger document plus exact card, thread, voice, and asset resources for each project.
2. The event-first iteration attempted to make independently writable nodes converge through immutable field events, projections, snapshots, event buckets, acknowledgements, relay persistence, and content manifests.
3. The required result is **immediate local durability on every node, deterministic multi-writer convergence, bounded same-field conflict retention, offline continuation, and work proportional to current divergence**.

## C. Fundamental Misconception

1. **Multi-writer convergence was equated with permanent operation-history reconstruction.** The system made the event log serve simultaneously as local durability, application authority, replication payload, repair inventory, audit history, snapshot input, and Git archive input.
2. Multi-writer convergence requires causal metadata and a deterministic merge algebra. It does not require every node and the relay to retain every superseded mutation forever.
3. The current design is an operation-based replicated system. Correct recovery therefore depends on retaining, transferring, deduplicating, acknowledging, replaying, snapshotting, and reconciling the complete operation set.
4. **The simpler model is a state-based delta CRDT.** Each replica retains only the causally maximal current values, current conflicts, current tombstones, and a compact causal clock. Replicas join current state directly. Superseded history disappears from the correctness path.
5. The distinction is decisive: an operation log makes cost grow with everything that ever happened; a joined current state makes cost grow with what currently exists and what currently diverges.
6. **The current scalar revision is not sufficient causal metadata.** A disconnected node can reach revision `12` through unrelated edits while another node changes the same field at revision `8`. The reducer can suppress the revision-`8` write as older even though the two writes are causally concurrent. A total number cannot establish happened-before across independent writers.

## D. Verified Current Architecture

1. `createProjectTaskState()` turns typed mutations into field events, assigns each hosting node a `writerId`, obtains a revision from its node-local projection, writes every event into a durable outbox, and appends the event batch.
2. `createTaskEventStore()` retains all loaded events and event IDs in memory, reduces them into a projection, writes `projection.json`, rewrites compatibility `tasks.json`, maintains peer event-ID acknowledgements, and creates complete snapshots.
3. The reducer groups fields by project revision. Independently disconnected nodes can issue the same revision. Different writes to the same field at that revision become conflict candidates.
4. The reducer also skips a field event below the stored scalar field revision. A higher scalar generated by unrelated offline activity can therefore erase a genuine concurrency conflict.
5. The relay stores the complete shared event set, hourly bucket indexes, and verified snapshots. A reconnect compares bucket manifests, requests historical gaps, transfers snapshots, then replays an uncovered event tail.
6. Content replication is nominally resource-based, but a content signal loses the exact resource identity. The receiver consequently rebuilds complete manifests and can also initiate complete task-checkpoint repair.
7. A fixed `30`-second timer activates task maintenance, relay reconciliation, and complete remote content synchronization.

## F. Correct Multi-Writer State Model

1. **Represent the task ledger as a current-state observed-remove map.** Stable keys are `{ entityType, entityId, fieldPath }`. Cards, annotations, relationships, and ledger fields remain independently mergeable.
2. **Represent each field as a dotted multi-value register.** A local mutation creates one dot `{ replicaId, counter }` and includes the compact version vector observed by that mutation.
3. Use deliberate domain merge units rather than arbitrary JSON flattening: card title, status, labels, geometry, execution intent, and content reference; annotation geometry, label, and style; complete relationship value; ledger viewport; per-thread reference. Geometry changes remain atomic as one unit.
4. A causally newer value replaces values it observed. Concurrent values at different dots remain as the current conflict set. Identical concurrent values collapse.
5. A later edit made after observing a conflict causally dominates every conflicting candidate and resolves the conflict.
6. **Represent deletion as a tombstone value in the same register algebra.** Concurrent update-versus-delete remains an explicit bounded conflict. A causally later decision resolves it.
7. Project causal metadata is proportional to the number of registered replicas. Field metadata is proportional to current fields and unresolved current conflicts. It is not proportional to mutation history.
8. The merge operation is a deterministic join: associative, commutative, and idempotent. Delivery order, duplicate delivery, reconnect order, and transport batching cannot change the result.

## G. Local Persistence

1. **Keep one atomic current-state document per project.** It contains the materialized ledger, compact replica clock, field dots, tombstones, unresolved candidates, coalesced pending delta, and current Merkle metadata. API readers receive the materialized ledger without synchronization metadata.
2. A local writer serializes only mutations originating in that process, advances its replica counter, updates the affected current registers, atomically renames the current-state document, and returns after local durability.
3. The compatibility `.decision-os/tasks.json` remains a materialized export for existing tools during cutover. It is not independently diffed back into events.
4. The embedded durable outbox contains a **join of unsent state deltas keyed by current register**, not a list of every operation. A newer local state for the same key subsumes the older unsent delta.
5. Startup reads one current-state document. No event segments, snapshot directory, projection replay, applied-event set, or historical field-revision map is required.

---

## H. Relay and Anti-Entropy

1. **Make the relay a durable current-state replica.** It joins incoming deltas into one current register table per logical project and acknowledges after that joined state is durable.
2. Normal live delivery carries bounded state deltas containing changed registers, the sender clock, and the resulting project-state hash.
3. The relay maintains a short transport sequence window for efficient reconnect delivery. That sequence is a delivery cursor, not application authority.
4. Every replica and the relay maintain a Merkle index over canonical current register entries. A cursor older than the retained window triggers Merkle comparison and transfer of mismatched current buckets only.
5. A blank node downloads one verified current-state image, then joins deltas received during transfer. It never reconstructs from genesis.
6. Duplicate deltas perform zero durable writes after the join proves they add no state. Equivalent Merkle roots perform zero bucket transfer.
7. Replica membership has an epoch. Removing a replica explicitly fences its old epoch. This allows stable tombstone compaction without letting a retired stale replica resurrect deleted state.

## I. Markdown and Binary Resources

1. **Content is multi-writer too.** Remove owner-scoped content authority from the model.
2. Each exact resource key has a dotted current-head register whose values are content hashes. Bytes remain content-addressed objects and are transferred only when the winning or conflicting hash is absent locally.
3. Card-body Markdown uses a multi-value head. Concurrent edits retain both current hashes and surface an explicit document conflict. A resolved edit based on the selected content causally dominates both heads.
4. Thread notes use their stable note IDs as independent replicated entities. Concurrent additions therefore merge without treating the complete thread Markdown file as one competing blob. The Markdown file remains the materialized representation.
5. Voice files, images, and managed assets are immutable hash objects. Their mutable references use the same dotted-register semantics as other fields.
6. An exact file mutation hashes that file once, updates its resource head, and publishes that key. Full resource discovery is limited to initial migration and explicit integrity repair.

## J. What Is Removed

1. Remove immutable task event segments and complete relay event retention.
2. Remove event replay, `appliedEventIds`, historical `fieldRevisions`, event bucket manifests, missing-event requests, and per-peer event-ID acknowledgement arrays.
3. Remove state snapshot generation, snapshot compatibility selection, snapshot chunk transfer, snapshot retention, and snapshot Git archive refs.
4. Remove HTTP task-checkpoint repair and content-triggered task repair.
5. Remove periodic complete content-manifest rebuilding and fixed project-wide anti-entropy scans.
6. Remove the second complete `projection.json` authority. Current CRDT state materializes the ledger directly.
7. Keep typed mutation commands, stable project identity, authenticated relay connections, content-addressed bytes, offline local writes, exact-resource priority, and scoped UI invalidation.

## K. Migration Path

1. Build one verified union projection from the currently retained event set and preserve every unresolved reducer conflict.
2. Convert each materialized field and conflict candidate into the baseline dotted-register state. Convert current deletions into baseline tombstones.
3. Convert card and thread resource hashes into current resource-head registers. Split parseable thread notes into stable note entities.
4. Install the identical baseline current state and replica membership epoch in the relay, Workstation, and Mobile before accepting CRDT-native mutations.
5. Route all local commands through current-register updates and route replication through joinable deltas.
6. Enable Merkle current-state repair and prove independent offline writes converge.
7. Preserve one timestamped rollback backup, then remove the `220 MiB` snapshot corpus, event segments, projection caches, historical acknowledgements, and obsolete relay event rows.

## L. Required Acceptance Evidence

1. Workstation changes a card title while Mobile changes its status offline; reconnection produces both changes on both nodes.
2. Both nodes change the same field offline; both nodes retain the same bounded conflict candidates after arbitrary delivery order.
3. One node performs many unrelated writes before the other node changes the same field from a lower counter; the lower-counter write remains a concurrent candidate and is not suppressed.
4. A later resolution observed on either node removes the conflict on every replica.
5. Concurrent deletion and modification remain visible as one explicit conflict and cannot resurrect silently.
6. Workstation and Mobile independently create cards from the same baseline; both cards appear after convergence.
7. Concurrent thread-note additions merge by note ID. Concurrent card-body edits retain both content hashes until resolution.
8. A duplicate delta causes zero current-state writes, zero materialized-ledger writes, and zero UI invalidations.
9. A disconnected node rejoins through the short delta window when possible and through mismatched current Merkle buckets when the window has expired.
10. Startup work is constant with respect to historical mutation count. It reads no event segment and no snapshot corpus.
11. One changed Markdown resource opens and hashes that resource only.
12. A retired replica cannot publish from its fenced membership epoch and cannot resurrect compacted tombstones.
13. The final runtime has no task event log, snapshot corpus, event-bucket anti-entropy, complete applied-event ID set, or task-event archive workflow.

---

## M. Operator Decision Summary

1. **Do not replace multi-writer replication with single ownership.** Writable offline replicas are a product invariant.
2. **Do replace permanent event-history authority with a current-state delta CRDT.** This preserves causal independent-field merging, bounded explicit conflicts, tombstones, offline writes, and arbitrary-order convergence.
3. The high-yield correction is to make reconciliation compare and join **current causal state**, using Merkle differences only after a transport-cursor gap. Historical mutation count then disappears from startup, steady-state repair, and relay storage cost.
