## A. Repository Intent

1. **Decision OS is a project-catalog server with local-first task execution and federated visibility.** The launcher in `bin/decision-os-server.mjs:11-38` binds the frontend and backend from one checkout, while `backend/src/business/server/helper/create-http-server.ts:1392-1406` connects the catalog to one configured relay and reacts to remote catalog changes.
2. **Skills are filesystem packages selected by stable names.** `backend/src/business/codex/helper/scan-codex-skills.ts:10-20` defines the current identity as `name`, `source`, `revision`, and server-resolved `skillFile`; `candidateSkillRoots()` at `:40-52` searches server, workspace, user, system, and plugin roots in precedence order.
3. **The server already owns safe reads and updates for existing skills.** `backend/src/business/codex/helper/codex-skill-library.ts:101-163` confines editable files to verified workspace and user roots, rejects symlink escapes, validates immutable frontmatter names, compares revisions, and replaces `SKILL.md` atomically.
4. **Federation already transports complete skill packages.** `backend/src/business/federation/helper/federated-library-cache.ts:103-174` exports manifests and snapshots; `:179-238` validates package paths, hashes, modes, frontmatter, and size before atomic installation under the receiving server's `.skills`.

## B. Current Iteration Intent

1. **Create skills from the Skills interface.** A new authoring action must collect a valid skill name, description, Markdown instructions, execution defaults, category, and one explicit synchronization choice.
2. **Edit files through one reusable editor surface.** Clicking an editable skill must open its `SKILL.md` in a modal sized to `80vw` by `95vh`. The component boundary must accept file identity, language, revision, content, read-only state, load, save, and conflict callbacks so a later thread-file click can reuse it without implementing thread-file editing now.
3. **Keep local and synchronized ownership explicit.** A local skill belongs to the selected project workspace. A synchronized skill belongs to the server catalog and is the only authored skill class admitted to federation export.
4. **Protect production through a real canary.** Development must run from a long-lived `dev` branch checkout, on a separate MultiTerm registration, against a separate Cloudflare Worker environment and Durable Object namespace.
5. **Document every contract change.** The implementation must update the Skills API, federation-library protocol, environment configuration, deployment procedure, rollback procedure, and operator verification gates before canary admission.

## C. Findings

1. **Gap — no skill creation contract exists.** `backend/src/business/server/helper/create-http-server.ts:3598-3668` exposes catalog reads plus `GET` and `PUT` detail routes. There is no `POST` skill route, creation controller, collision policy, package-directory transaction, or creation test. The current responsive Skills surface in `frontend/src/app/responsive/codex.js:72-223` lists and reads skills but exposes no authoring action.
2. **Drift — an editor implementation exists outside the active Skills surface.** `frontend/src/runtime/codex/effect/render-skill-library-editor-modal.ts:91-221` builds a skill editor, yet the served responsive workflow in `frontend/src/app/responsive/codex.js:179-205` renders global skill details as read-only Markdown and exposes only tags and favorites. The dialog remains declared at `frontend/index.html:195`, but the responsive Skills route never opens it.
3. **Omission — the existing editor is a plain textarea, not the requested robust file editor.** `render-skill-library-editor-modal.ts:173-184` creates `textarea.skill-markdown-editor`; `frontend/assets/canvas/dialogs.css:543-546` caps the skill modal at `920px`, while the shared editor boundary at `:517-525` caps height at `760px`. Neither satisfies `80vw` by `95vh`, and no search, replace, undo, redo, line-number, syntax, keyboard-command, or formatting toolbox is present.
4. **Decision evidence — CodeMirror 6 fits the repository and target better than Monaco.** CodeMirror provides modular search, lint, folding, completion, history, and keymap extensions through its official [extension contract](https://codemirror.com/docs/extensions/), and its current package line remains active in the official [changelog](https://codemirror.com/docs/changelog/). The registry currently reports `codemirror@6.0.2`, `@codemirror/view@6.43.6`, `@codemirror/lang-markdown@6.5.1`, `@codemirror/commands@6.10.4`, and `@codemirror/search@6.7.1`, all under `MIT`. Monaco is also `MIT` and feature-rich, but its own [repository contract](https://github.com/microsoft/monaco-editor) requires worker lifecycle integration and explicitly states that mobile browsers are unsupported. Decision OS serves a framework-free responsive interface, so **CodeMirror 6 is the selected editor**.
5. **Gap — local versus synchronized is not a domain field.** `CodexSkillSource` in `scan-codex-skills.ts:10` describes discovery location, not replication intent. The public records in `codex-skill-library.ts:38-55` expose `source` and `editable` but no ownership scope. A checkbox cannot safely infer synchronization from `source`, because the master workspace root can be both the current workspace and the server catalog.
6. **Drift — federation exports every discovered source.** `exportableSkills()` in `backend/src/business/federation/helper/federated-library-cache.ts:103-114` calls `scanCodexSkills()` for every workspace root without filtering `user`, `system`, `plugin`, or project-local skills. This violates the requested distinction and can package machine-local or plugin-owned prompts into the shared library.
7. **Defect — successful Markdown edits can publish a stale skill manifest.** The export index is cached at `create-http-server.ts:1208-1213`. The skill update route at `:3636-3655` calls `federation.publishManifest()` after a Markdown save but does not call `invalidateFederatedSkillExportIndex()`. Automatic peer synchronization at `:1299-1321` reads the cached manifest unless the operator invokes the forced synchronization endpoint, which adds `refresh=1` at `:1305`. Current code therefore does not prove automatic propagation of an edited package.
8. **Omission — synchronized skill deletion and conflict ownership are undefined.** Import at `federated-library-cache.ts:229-238` only installs newer packages and has no tombstone. Duplicate names are reduced by scan precedence at `scan-codex-skills.ts:178-187`, while federation winner selection uses filesystem `updatedAt` plus hash at `federated-library-cache.ts:98-114`. This is insufficient for authored rename, deletion, concurrent update, and clock-skew behavior.
9. **Gap — the API is split across incompatible editing surfaces.** Project detail uses `/p/:projectId/api/codex/skill-library/:name`; global detail uses `/api/codex/server-skills/:name`. `create-http-server.ts:3607-3625` restricts the global `PUT` route to favorite and tag metadata, so the current global Skills page cannot edit synchronized Markdown even when the owning server package is locally authoritative.
10. **Omission — the reusable file boundary is absent.** The backend accepts only a skill name and deliberately rejects client paths at `codex-skill-library.ts:314-316`, which is correct for security, but the frontend editor is coupled to `SKILL.md`, model defaults, tags, and favorites. No generic file descriptor, capability token, language mapping, dirty-state close guard, disposal hook, or future thread-attachment adapter exists.
11. **Gap — no canary branch or server exists.** `git branch -a` contains no `dev` branch. MultiTerm currently registers only the production catalog at `/home/jbb` on `50150`; `50151` is not listening. `AGENTS.md:128-166` assigns server ownership to MultiTerm, but the repository has no dev registration procedure, canary health gate, isolated catalog path, or promotion and rollback contract.
12. **Gap — the launcher has no named environment boundary.** `bin/decision-os-server.mjs:15-23` strips most `DECISION_OS_*` variables and always resolves `DECISION_OS_REPOSITORY_SETTINGS_FILE` from its own checkout. This supports isolation when a separate checkout owns its own ignored settings, but no code records or reports a `dev` environment identity, preventing diagnostics from distinguishing production and canary processes.
13. **Gap — the relay has only production configuration.** `federation-relay/wrangler.toml:1-19` defines one Worker and one `FEDERATIONS` binding with no `[env.dev]`. Cloudflare documents that named [Wrangler environments](https://developers.cloudflare.com/workers/wrangler/environments/) create separately named Workers, and that Durable Object bindings are non-inheritable and environment-specific in the [Durable Object environment contract](https://developers.cloudflare.com/durable-objects/reference/environments/).
14. **Documentation drift — current docs do not describe skill authoring.** `federation-relay/README.md:1-51` documents one relay, `documentation/procedure/deployment/epoch-4-node-cutover.md:119-143` documents production relay and node admission, and the architecture documents contain no skill creation, skill edit, synchronization-scope, package tombstone, canary server, or dev relay API contract.
15. **Verification omission — existing tests cover only the old boundary.** `backend/test/codex/codex-skill-library-routes.test.ts:35-249` proves existing workspace and user edits, conflicts, validation, and read-only sources. `backend/test/server/federated-library-cache.test.ts:25-74` proves package import and update. Neither suite tests creation, explicit synchronization scope, export exclusion, cache invalidation after save, deletion convergence, editor commands, `80vw` by `95vh`, mobile input, optimistic save, rejected-save reconciliation, canary isolation, or dev-relay separation.

## D. Remediation Paths

1. **Establish one explicit ownership model before UI work.** Add `scope: "local" | "synchronized"` to the public skill record and authoring payload. Resolve `local` to the selected project's `.skills/<name>` and `synchronized` to the server catalog's `.skills/<name>`. Keep `source` as discovery provenance. Export only server-catalog packages marked `synchronized`; never export user, system, plugin, or project-local roots.
2. **Add one transactional skill API.** Introduce `POST /p/:projectId/api/codex/skills` with `{name, description, markdown, scope, defaultCodexModel, defaultCodexEffort, tags}`. Validate the slug and frontmatter, reject every cross-scope name collision, stage the complete package beside the destination, atomically rename it, persist defaults, invalidate the export index, and publish the federation manifest only after the complete transaction succeeds.
3. **Unify reads and updates behind capability-bearing DTOs.** Return `{name, scope, source, editable, revision, language: "markdown", content, capabilities}` from the detail API. Keep physical paths server-only. Route synchronized edits to the authoritative server package and local edits to the selected project package. Require `expectedRevision` for every content write and return the current revision on `409`.
4. **Build one generic file-editor component with a skill adapter.** Create a reusable `FileEditorModal` that owns `title`, `language`, `content`, `revision`, `readOnly`, `load`, `save`, `close`, and `dispose`. Mount CodeMirror 6 inside it. Keep skill defaults, category, synchronization status, and favorite controls in the skill adapter outside the editor core. Add the requested code comment at that adapter boundary: a future thread attachment click will supply a different capability-backed loader and saver to the same modal; this iteration does not add thread-file editing.
5. **Pin and vendor CodeMirror deterministically.** Add exact `frontend/package.json` dependencies and lockfile entries for `codemirror@6.0.2`, `@codemirror/view@6.43.6`, `@codemirror/lang-markdown@6.5.1`, `@codemirror/commands@6.10.4`, and `@codemirror/search@6.7.1`. Produce one checked-in browser ESM asset under `frontend/assets/vendor/` using the same local dynamic-import delivery pattern as `/assets/vendor/pierre-diffs-1.2.12.js` in `render-ledger-card-git-diff.ts:30-34`.
6. **Implement the required modal and toolbox.** Set the desktop dialog to `width: 80vw`, `height: 95vh`, and bounded viewport maxima. Preserve the existing near-full-screen mobile rule at `dialogs.css:1306-1313`. Provide toolbar buttons wired to CodeMirror commands for undo, redo, search, replace, previous match, next match, heading, bold, inline code, fenced code, and line wrap. Preserve keyboard access, focus return, `Escape`, dirty-close confirmation, editor destruction, and screen-reader labels.
7. **Repair federation publication at the source.** Invalidate the cached export index after every successful synchronized create, edit, delete, and imported replacement before `federation.publishManifest()`. Build the local index once per synchronization pass. Add a package lifecycle field and durable tombstone so deletion converges. Replace filesystem-time winner selection with a causal revision owned by the synchronized package manifest.
8. **Create the isolated canary from current `main`.** Create long-lived branch `dev` and sibling checkout `/home/jbb/dev/EditorBP/decision-os-dev`. Use the checkout itself as the canary catalog so its `.decision-os`, ignored `.settings.json`, frontend, backend, logs, and runtime artifacts stay separate from `/home/jbb`. Register it in MultiTerm as `decision-os-workstation-dev` on verified-free port `50151`, with the dev checkout launcher and `http://127.0.0.1:50151/`.
9. **Create the separate dev relay.** Add `[env.dev]`, `[[env.dev.durable_objects.bindings]]`, and environment migration entries to `federation-relay/wrangler.toml`. Deploy with `wrangler deploy --env dev`, inject a separate `ADMIN_SECRET`, provision a distinct dev federation and node credential, and write only those values into the dev checkout's ignored `.decision-os/.settings.json`. Never reuse the production relay URL, federation identity, credential, Durable Object namespace, or MultiTerm process.
10. **Make environment identity observable.** Add a non-secret `decisionOsEnvironment` setting with exact value `production` or `dev`; surface it in `/api/health`, diagnostics, and the application shell. Reject startup when a `dev` server points at the production relay host and reject production startup when it points at the dev relay host.
11. **Write the canonical documentation set.** Add a product and API document for skill authoring DTOs and errors; an architecture document for local and synchronized ownership, federation lifecycle, and conflict rules; a dev environment runbook for branch, checkout, MultiTerm, settings, ports, and logs; a dev relay deployment and credential-rotation runbook; and a promotion runbook that requires reviewed merge from `dev` to `main` without copying canary runtime state.
12. **Gate completion on behavior.** Add backend tests for creation transactions, path confinement, scope, collisions, stale revision, cache invalidation, export exclusion, package update, tombstone convergence, and rollback. Add frontend tests for CodeMirror lifecycle and toolbox commands. Run the complete gesture on the served `50151` route and prove the UI changes before save resolves, a successful save survives reload, a rejected save restores server-confirmed content, a synchronized edit reaches a second dev node, and production `50150` plus the production relay remain unchanged.

## E. Operator Decision Summary

1. **Proceed through the existing filesystem package boundary, not a new prompt database.** Project `.skills` owns local prompts; server `.skills` owns synchronized prompts; `scope` makes that decision explicit in the API and UI.
2. **Use CodeMirror 6.** It meets the requested robust editor and toolbox boundary, supports the responsive target, and avoids Monaco's unsupported mobile surface and worker integration cost.
3. **Repair synchronization before claiming authoring complete.** Current exports are over-broad and the cached manifest remains stale after ordinary Markdown edits.
4. **Admit the feature only through the isolated canary.** The credible path is `dev` at `/home/jbb/dev/EditorBP/decision-os-dev`, MultiTerm port `50151`, and Cloudflare environment `dev` with separate Durable Object storage and credentials.
5. **Do not promote until the canary proves create, edit, reload, rejected-save reconciliation, cross-node skill convergence, environment identity, and zero production-state mutation.**
