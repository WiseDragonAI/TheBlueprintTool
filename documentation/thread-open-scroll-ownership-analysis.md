## A. Repository Intent

1. **Decision OS intent:** The application renders a ledger canvas with card, zone, group, and conversation threads in one right-side inspector. Thread content, Codex run output, voice state, selection, and browser-local viewport state remain distinct ownership domains.
2. **Canonical opening contract:** Specification `a4d9e2b6`, `Opening a thread pins to the latest message`, requires every panel-open transition and every thread-context switch to scroll the conversation viewport to the newest rendered note after content and footer mounting. Ordinary note rerenders must not force-scroll without an entry-transition request.
3. **Component boundary:** The existing thread panel structure, styles, notes renderer, Codex log renderer, jump control, and scroll surfaces are validated components. The correction belongs in runtime state and controllers, not in a replacement component.

---

## B. Current Iteration Intent

1. **Operator requirement:** Opening any card thread must land at the bottom. The current card-dependent top opening has survived several claimed fixes, so the next implementation must correct runtime ownership before changing scroll timing.
2. **Required distinction:** A panel open, a thread-context switch, and a tab activation are entry transitions. An incoming note, voice transcription update, Codex event, and ordinary repaint are continuation transitions. Entry transitions pin the newly active surface and enable follow-bottom. Continuation transitions preserve a paused reader and pin a following reader.
3. **Contradicted-success boundary:** The July delivery claimed served verification, but it verified that a persisted paused offset survives reload. It did not verify the current requirement that reopening a surface with an explicit persisted `false` follow record resets that surface to bottom.

## C. Findings

1. **Drift — the implementation contradicts the canonical specification.** `frontend/src/runtime/thread/effect/open-thread-panel.ts:14` and `frontend/src/runtime/thread/effect/select-thread.ts:31` consult `isThreadFollowingBottom(...)` before requesting a pin. An explicit persisted `false` sets `state.threadPinOnRender = false`, so `frontend/src/runtime/thread/effect/render-thread-panel.ts:328` restores the saved offset instead of pinning. Specification `a4d9e2b6` requires every open and thread-context switch to pin.
2. **Root cause — follow state owns two incompatible decisions.** `threadFollowBottomByThreadId` and `threadLogFollowBottomByThreadId` correctly express continuation behavior after a trusted upward scroll. The same records also veto entry-transition pinning. A continuation preference therefore controls an open command that has a stronger canonical contract.
3. **Deterministic explanation for “some cards.”** `frontend/src/runtime/thread/effect/render-thread-jump-button.ts:63` writes `false` after a trusted upward scroll more than `72px` from bottom. `frontend/src/runtime/thread/helper/thread-follow-bottom.ts:21` persists that value. `frontend/src/runtime/thread/effect/persist-thread-scroll.ts:24` hydrates it on boot and refresh. Only threads with a stored `false` follow record reopen at their saved offset; unseen threads default to bottom.
4. **Ownership gap — the pending pin is an untyped global boolean.** `state.threadPinOnRender` is written by `selectThread()` and `openThreadPanel()`, consumed and cleared by `renderThreadPanel()`, but it is absent from the initialized runtime object in `frontend/src/runtime/state.ts`. The store is typed as `any`, so TypeScript cannot detect the missing field, a stale request, a wrong thread, or a wrong surface.
5. **Ownership gap — the pin request has no identity.** A single boolean cannot prove which `threadId` and `ThreadPanelTab` requested the pin. Any intervening thread selection, tab change, render, deep-link hydration, or asynchronous refresh can consume the flag without matching the initiating transition.
6. **Responsive reopening has a second deterministic failure path.** `frontend/src/app/responsive/thread.js:127` calls `selectThread(threadId)` directly, sets `threadPanelOpen`, and renders. `closeMobileThread()` leaves `state.threadId` intact. Reopening the same card makes `selectThread()` return at `frontend/src/runtime/thread/effect/select-thread.ts:20`, so the responsive entry path creates no new pin decision. Commit `9564267c` removed the responsive path's previous unconditional `threadPinOnRender = true` assignment.
7. **Controller duplication — one Notes click can traverse the selection and open path multiple times.** `handleActionClick()` calls `selectThread()`, then `selectTarget()`, which calls `selectThread()` again. Master-task selection calls `openThreadPanel()` inside `selectTarget()`, and the Notes action calls `openThreadPanel()` again afterward. The responsive app assembles another open sequence in `openMobileThread()`. The browser command has no single controller that owns target selection, thread selection, panel visibility, follow reset, pin request, and render order.
8. **Function-role drift puts policy inside effects and IO inside a helper.** The `GeneratedFunction` contract in `documentation/data.json:1188` assigns domain branching to controllers, pure computation to helpers, and DOM plus IO boundaries to effects. `open-thread-panel.ts` is an effect that chooses pin policy, `render-thread-panel.ts` is an effect that branches between pin and restore, and `thread-follow-bottom.ts` is a helper that writes local storage.
9. **Render ownership is split across two scroll writers.** `renderThreadCodexLog()` restores or pins `.thread-log-scroll` at `frontend/src/runtime/thread/effect/render-thread-codex-log.ts:386`. `renderThreadPanel()` then independently calls `pinThreadSurfaceToBottom()` or `restoreThreadScrollPosition()` at `frontend/src/runtime/thread/effect/render-thread-panel.ts:325`. The panel renderer also invokes the log renderer while the conversation tab is active. One render turn can therefore write the log viewport twice.
10. **Comment conflict exposes the design drift.** `pin-thread-feed-to-last-message.ts` says opening a card thread should land on the latest exchange. `persist-thread-scroll.ts` says switching threads and tabs must not move the reading position. Both comments describe valid continuation concerns, but neither defines transition precedence. `select-thread.ts` documents voice ownership while containing scroll policy. `open-thread-panel.ts` documents focus behavior only. `render-thread-panel.ts` claims separate scroll ownership while deciding open, follow, pin, restore, conversation render, log render, voice render, and run binding in one function. `openMobileThread()` duplicates the lifecycle without a local ownership comment.
11. **Data-model omission — canonical `ThreadPanelState` does not model viewport ownership.** `documentation/data.json` defines `ThreadPanelState` with `isOpen`, `threadId`, `targetId`, and `targetKind`. It omits the active surface, pending entry transition, scroll offsets, and follow state. Runtime maps were added outside the documented state contract, and the one-shot pin flag was added without initialization.
12. **Layout-timing omission can break a valid pin after media expansion.** `pinThreadSurfaceToBottom()` pins immediately and once in the next animation frame. Thread markdown images use lazy loading and asynchronous decoding in `render-ledger-card-media.ts:280` and `append-inline-nodes.ts:88`. Thread-surface image growth does not request another pin, so a following viewport can stop being bottom-aligned after delayed media layout.
13. **Regression coverage enforces the bug.** `frontend/test/runtime/thread-selection-runtime.integration.test.ts:98` is named `select-thread restores saved thread scroll instead of pinning when returning to a thread` and asserts `threadPinOnRender === false` for an explicit persisted `false`. The focused suite passes `23/23`, demonstrating internal consistency with the wrong entry contract rather than conformance to specification `a4d9e2b6`.
14. **Coverage omission — no controller-level test exercises the reported boundary.** Existing tests cover the pin helper, follow persistence, upward-scroll pause, offset restoration, and missing-key defaults. They do not execute an `open-card-thread` command with a saved `false` record, close and reopen the same thread, switch to another paused thread, activate a paused Codex Log tab, then assert bottom position and enabled follow state. `mobile-thread.test.mjs` verifies only that open does not focus the draft. The responsive browser suite verifies panel geometry, and the thread browser test manually assigns `scrollTop = scrollHeight` before asserting bottom.
15. **Commit lineage explains the regression.** Commit `06dfd034` introduced unconditional pin requests for panel open and thread switch. Commit `afd1461c` replaced them with `!hasSavedThreadScrollPosition(...)`, making saved offsets veto entry pins. Commit `9564267c` changed the veto to explicit persisted follow state, removed the responsive unconditional pin, and added tests for pause persistence. Commits `3868f38c` and `0b6d4d69` protected paused offsets during rerenders and hydration. Commit `91c09fd1` added only the missing-key Codex Log assertion. The later commits hardened pause persistence without restoring the canonical entry-transition precedence.

## D. Remediation Paths

1. **Create one typed viewport transition contract.** Add `ThreadViewportPinRequest` with exact `threadId`, `surface`, `openGeneration`, and `reason` fields. Initialize `state.threadViewportPinRequest` in `frontend/src/runtime/state.ts`. Add `requestThreadViewportPin(...)` and `consumeThreadViewportPin(...)` helpers so a render can consume only a request matching the active thread, surface, and open generation.
2. **Give one controller ownership of thread entry.** Add a thread-entry controller that owns target selection, thread selection, panel visibility, active-surface selection, open generation, follow enablement, pin request, and the final render. Route Notes actions, master-task automatic opening, the `A` and `X` shortcuts, the Thread tool, card deep links, and `openMobileThread()` through this controller. Keep `selectThread()` responsible for saving the previous draft and scroll state plus changing thread identity.
3. **Make entry precedence explicit.** Panel open, thread switch, and tab activation must set follow-bottom to `true` for the activated surface and request a scoped pin regardless of a persisted `false` record. This restores specification `a4d9e2b6` and the operator’s current requirement.
4. **Preserve pause only during continuation.** Ordinary rerenders, optimistic note patches, transcription reconciliation, active-thread refresh, and Codex polling must read the surface follow record. A following surface pins after content replacement. A paused surface restores its saved offset. These continuation paths must not create an entry pin request.
5. **Assign one scroll writer per surface per render.** Move Codex Log restoration and pin application behind the shared viewport effect. `renderThreadCodexLog()` should render log DOM and report content completion without applying a second viewport decision. `renderThreadPanel()` should delegate the final matched pin or restore effect after the active surface content is mounted.
6. **Update comments at the ownership boundaries.** Document entry-transition precedence in the controller and scoped request helper. Document continuation-only persistence in `persist-thread-scroll.ts`. Document DOM-only responsibility in both renderers. Remove comments that claim separate ownership where the function still controls unrelated surfaces.
7. **Replace the contradictory regression.** Remove the assertion that a persisted pause vetoes thread selection. Add controller-level cases for explicit `false` records on panel reopen, thread switch, and tab activation. Retain focused cases proving that the same paused offset survives an ordinary rerender without an entry transition.
8. **Observe followed-content growth.** Attach one `ResizeObserver` to the active surface content while follow-bottom is enabled. Repin after lazy media and embedded-content growth. Disconnect the observer on close, thread change, and tab change.
9. **Perform contradicted-success browser verification before the next success claim.** On the served project route, record route, HTTP result, browser, viewport, persisted records, exact wheel input, close command, reopen command, tab activation, DOM `scrollTop`, DOM `scrollHeight`, and follow records. Verify desktop input and a mobile viewport. Verify both pin-on-entry and pause-on-continuation. Include delayed thread-image growth without assigning `scrollTop` inside the test.
10. **Keep the implementation boundary unchanged.** Do not replace the thread component, scroll surfaces, jump button, voice composer, Codex log component, DOM structure, CSS, or interaction library. Correct the runtime transition and controller ownership that decides when the validated components pin.

---

## E. Operator Decision Summary

1. **Confirmed cause:** The bug is not a failed `scrollTop` call. Persisted pause state is deliberately allowed to veto open and thread-switch pin requests, and the regression suite asserts that behavior.
2. **Selected correction:** Separate entry intent from continuation follow state with a typed, thread-scoped, surface-scoped, one-shot pin request owned by one entry controller.
3. **Preserved behavior:** Manual upward scrolling continues to pause live updates during the current mounted reading session. The jump control resumes follow. Ordinary rerenders preserve a paused reader.
4. **Changed behavior:** Reopening the panel, changing thread context, and activating a thread tab always reset the activated surface to bottom and enable follow, even when browser persistence contains an older `false` record.
5. **Completion gate:** No implementation should be declared fixed until the explicit persisted-`false` reopen case passes controller tests and served desktop plus mobile-viewport interaction verification.
